# results/rehearsal_viz_drill1f3f — AI hub 1층·3층 합동 훈련 시각화

`tools/rehearsal_viz.py` 로 뽑은 **좌: 카메라 그리드 / 우: 공유 2D 맵** mp4.
패키지 `aihub-drill-1f3f` (2026-09-11 촬영 · 27대 · 시나리오 14개).

```bash
python tools/rehearsal_viz.py --package aihub-drill-1f3f --scenario scenario_01 \
       --out results/rehearsal_viz_drill1f3f
```

| 위치 | 내용 |
|---|---|
| 좌 | 카메라 그리드 — ID 박스(ID별 색) · 발끝점 · **대응점 헐**(청록) · 헐 안이면 ● 녹색 / 밖이면 ✕ 빨강(= 라이브에서 버려지는 관측) |
| 우 | 2D 도면 — 구역·병목·출구·경로 + 전 카메라 투영점(카메라별 색, 2초 궤적) + **출구별 OUT 카운트** |
| 좌하 | t · 카메라별 in/out/dropped · 살아있는 ID 수 |

판정은 엔진의 `DirectionalLine`/`ZoneGate` 를 **그대로 재사용**한다 — 라이브(:8900)와 같은 규칙.

## 헐이 좁은 카메라 — 관측이 통째로 버려진다

대응점(cctv_pts) 컨벡스 헐 밖 관측은 맵 투영에서 제외된다(외삽 오차 차단).
헐이 사람 동선을 못 덮으면 그 카메라는 지표에 기여하지 못한다.

| 카메라 | 헐 면적비 |
|---|---|
| cam36 · cam14 | 5.0% · 4.7% |
| cam31 · cam33 · cam37 | 5.6% · 7.3% · 8.7% |

실측(s12)에서 cam31·cam35·cam38·cam39 가 `dropped 100%` — 검출은 되는데
전부 헐 밖이라 맵에 한 점도 안 올라갔다. 해당 카메라는 **대응점을 더 넓게
다시 찍어야** 한다(② 매핑).

**cam17 은 아직 미매핑** — 시나리오 01~06 에서 그만큼 빠진다.
