# 발표용 시각화 영상 — 4대 지표 실증

각 영상이 **지표 하나를 주인공**으로 한다. 14개 리허설 각본 중 그 지표의 변별력이
가장 뚜렷하게 나온 세션을 골랐다.

**영상 4건 × 2판 = 8개.** 같은 세션·같은 수치를 2D 맵 표출만 달리해 뽑는다.

| 판 | 파일 | 2D 맵 |
|---|---|---|
| **점판**(기본) | `<지표>_<번호>.mp4` | 한 가지 색 점 + 사람마다 자기 자취 |
| **히트맵판** | `<지표>_<번호>_heat.mp4` | 밀도 히트맵(반경 2.5m) + 흰 점. 자취는 뺀다 |

두 판 모두 **이상적 궤적**(끊기지 않는 10명)으로 그린다 — 아래 절.

히트맵은 운영 화면(`webui/static/main/heatmap.js`)과 **같은 팔레트·같은 반경**이다.
발표에서 보여주는 그림과 운영 화면의 그림이 다르면 그때부터 설명이 꼬인다.

| 폴더 | 영상 | 세션 | 주지표 | 핵심 수치 |
|---|---|---|---|---|
| `01_IDR/` | `IDR_01.mp4` · `IDR_01_heat.mp4` | 01 IDR 권장경로 · 우측 우회 2명 | **IDR** | 개시 **9초** · IDR 2.26 m/s |
| `02_EPFI/` | `EPFI_04.mp4` · `EPFI_04_heat.mp4` | 04 EPFI 2명 완전 우회 진입 | **EPFI** | **55.6** (정상군 70.0 대비 −14.4) |
| `03_CBS/` | `CBS_08.mp4` · `CBS_08_heat.mp4` | 08 CBS 문 앞 밀집 2회 (밀도) | **CBS** | **4.18** · 최대밀도 3.35 (임계 2.0 초과) |
| `04_SEI/` | `SEI_14.mp4` · `SEI_14_heat.mp4` | 14 1층 반반 나눠 나가기 | **SEI** | **91.1** (한쪽 출구만 쓰면 53.3) |

출구 카운팅은 4건 전부 GT 정확 — 10 · 10 · 10 · 16(6+10).

## 왜 이 4건인가

**CBS** — 같은 CBS 각본 3개가 각본 의도대로 갈린다. 08 만 CBS 가 잡힌다.

| 각본 | 각본상 의도 | CBS | 최대밀도 |
|---|---|---:|---:|
| 07 2열 진입 | 밀도 **아님** | 0.00 | 1.67 |
| 09 5명+5명 합류 | 밀도 **아님** | 0.00 | 1.67 |
| **08 문 앞 밀집** | **밀도임** | **4.18** | **3.35** |

**EPFI** — 04(완전 우회)가 55.6 으로 14개 중 최저권. 정상 보행 각본 70.0 과 14점 차.

**SEI** — 대부분 세션은 한쪽 출구만 써서 53.3 에 머문다. 14(반반)만 91.1 로 뛴다.

**IDR** — 01 은 각본 자체가 IDR 용이고 개시가 9초에 깨끗하게 잡힌다.

## 영상 구성

```
① 인트로 (4초)  재실자별 피난경로를 맵에 펼쳐 보여주고 사라진다
                 "각자 이 길로 가야 한다"를 깔아야 뒤의 이탈·개시가 읽힌다
② 본편          좌 = 2D 도면 · 우 = 카메라 그리드(원본 fps)
                 하단 = 경보 후 경과(영상 시작 = 0:00) + 4대 지표 + 카운팅
```

- **점은 한 가지 색** — 카메라별 색은 사람이 카메라를 넘을 때마다 바뀌어 산만하다
- **뒤에 이동 흔적**을 남긴다(10초, 오래될수록 흐리게)
- 맵에는 **CBS 병목과 출입구만 도형으로** — IDR 구역·피난경로·글자는 전부 뺐다
- **주지표만 크게** 강조하고 나머지 3개는 작게

## 주의 — `01_IDR` 의 임계값

배포 기본값 `dt_hold` 3.0 에서는 이 각본이 **미개시**라 IDR 영상인데 IDR 이 안 뜬다.
검증보고서(MACS-EVAC-VR-2026-005)가 권고한 **`dt_hold` 1.0** 으로 재계산해 찍었고,
그 사실을 화면 좌하단에 표기했다.

## 이상적 궤적 — 끊기지 않는 10명

**이 영상들은 "모델이 이상적으로 동작하면 이렇게 보인다"를 보여주는 자리다.**
각본에는 10명이 처음부터 끝까지 있었는데, 카메라 경계마다 트랙 id 가 끊겨
그대로 그리면 점이 툭 사라졌다 딴 데서 튀어나온다. 보는 사람은 "사람이
사라졌다"로 읽는다.

그래서 파편을 **이어 붙여** 각본 인원만큼의 연속 궤적을 만든다. 영상 편집
레이어다 — `tools/demo_tracks.py`.

| 세션 | 원 파편 | → 합성 | 0:00 시작지점 뭉침 | 출발 차례 | 전원 출구 도달 |
|---|---:|---:|---:|---|---|
| 01_IDR | 74개 | **10명** | 1.6m 이내 | 2.1s ~ 12.8s | ✅ |
| 02_EPFI | 82개 | **10명** | 1.6m 이내 | 3.9s ~ 14.6s | ✅ |
| 03_CBS | 99개 | **10명** | 1.6m 이내 | 2.6s ~ 31.0s | ✅ |
| 04_SEI | 100개 | **10명** | 1.6m 이내 | 4.3s ~ 47.9s | ✅ |

**0:00 에 10명이 시작지점 한 자리에 뭉쳐 있다가** 차례로 출발해 좌·우로 갈라진다.
건물 여기저기 점이 박혀 있다 합류하는 그림은 나오지 않는다 — 실제로 그런 일은
없었고, 이 영상은 이상적으로 동작할 때의 그림을 보여주는 자리다.

만드는 순서

1. **파편 수집** — gid 별 (t, x, y). 0.4초 미만 조각은 잡음이라 버린다
2. **잇기** — 끝난 자리에서 시간·거리가 말이 되는(≤ 2.2 m/s) 다음 조각을 붙인다.
   후보가 여럿이면 **필요 속도가 가장 느린** 쪽 — 사람은 순간이동하지 않는다
3. **10개 고르기** — 오래 살아남고 출구에서 끝나는 사슬이 우선
4. **메우기** — 빈 구간은 **벽을 피해** 잇는다(직선이 벽을 뚫으면 격자 A*).
   경로 산출과 **같은 벽**을 쓴다 — 저기선 못 지나가는데 여기선 지나가면 안 된다
5. **끝내기** — 마지막 점이 출구에서 멀면 최적 경로를 따라 걸어 나가 사라진다.
   계단실 안쪽처럼 경로 산출이 실패하는 자리는 출구선까지 곧장 걸어 나간다
6. **시작지점에 모으기** — 10명 전부 경보 순간에는 **출발 자리에 뭉쳐** 있다가
   자기 차례에 거기서 걸어 나간다. 사슬 첫 점들이 가장 빽빽한 곳을 시작지점으로
   잡고, 첫 관측이 건물 한복판인 사람은 그 자리에 세워 두지 않고 시작지점에서
   걸어와 자기 동선에 올라탄다(닿을 수 없는 앞머리는 잘라낸다)
7. **다듬기** — 0.1초 격자 리샘플 + 0.9초 이동평균. 관측 5fps 의 덜컥거림을 없앤다

표출은 사람마다 **자기 자취를 끝까지** 남긴다(최근 6초는 진하게). id 가 유지된다는
게 눈에 보여야 한다.

남아 있는 정지 구간은 **전부 출구 앞**이다(4건 전체에서 출구선 0.1~2.8m). 계단
문 앞에 줄 서는 것이고, `03_CBS` 는 그게 각본의 요지다(문 앞 밀집 2회). 건물
한복판에 박혀 있는 점은 없다.

### 무엇을 건드리고 무엇을 안 건드리나

| 대상 | 영향 |
|---|---|
| 좌측 도면의 점·자취·재실 인원 | **이 궤적으로 그린다** |
| 4대 지표(IDR·EPFI·CBS·SEI)·출구 카운팅 | **원 관측 그대로.** 합성 궤적은 지표 계산 어디에도 안 들어간다 |
| 우측 카메라 그리드 | 원본 영상 그대로 |

```bash
python tools/demo_tracks_build.py --session <sess-id> --floor <층> \
       [--people 10] --png /tmp/대조.png      # 합성 + 원본/합성 대조 그림
python tools/demo_viz.py ... --tracks ideal   # 합성 궤적으로 렌더(기본 산출물)
python tools/demo_viz.py ... --tracks raw     # 원 관측 그대로(끊기는 판)
```

## 동선을 사람이 직접 그린다 — 편집기 :8930

자동으로 각본을 연출하는 방식(아래 절)은 **싱크가 끝내 안 맞았다.** 이어 붙이고
자르고 미는 손질이 쌓일 때마다 어딘가 튀었고, 한 군데를 잡으면 다른 데가 틀어졌다.

그래서 방향을 바꿨다. **④ 리플레이와 같은 타임라인 위에서 사람이 직접 찍는다.**
리플레이는 녹화본을 그대로 흘려보내는 화면이라 우측 그리드 영상과 처음부터
싱크가 맞는다. 그 위에서 "이 순간 이 사람은 여기" 를 찍으면 싱크는 **저절로**
맞는다 — 맞추려고 애쓸 일이 없다.

```bash
python tools/path_editor.py          # http://<서버>:8930
python tools/demo_viz.py ... --tracks drawn
```

### 화면

| 자리 | 내용 |
|---|---|
| 좌 | 도면. **회색 점 = 녹화본 그대로**(④ 리플레이와 같은 내용, 참고용) · 색점 = 내가 그린 사람 |
| 우 | 카메라 영상 한 대(고를 수 있음). 같은 시각으로 따라간다 |
| 아래 | 타임라인 — 재생/정지·배속(0.25~2배)·한 프레임씩 |
| 왼쪽 | P01~P10 목록, 세션 선택, 출구 **통과 실제 시각** 표시 |

### 배경 — 녹화된 전부를 한 장에

프레임마다 맞춰 찍는 건 노가다다. 그래서 **녹화된 모든 순간을 한 장에** 깐다.

| 색 기준 | 무엇 | 쓸 때 |
|---|---|---|
| **ID별 색** (기본) | 트랙(=검출 id)마다 다른 색 + **id 표기**. 굵은 점 = 그 트랙이 처음 잡힌 자리 | "이 사람이 여기서 저기로 갔다"를 읽을 때 |
| 시각별 색 | 파랑=처음 → 청록 → 초록 → 노랑 → 빨강=끝 | 전체 흐름의 방향을 볼 때 |

라벨은 **확대할수록 많이** 보인다(4초↑ → 2초↑ → 0.8초↑). 다 보이게 하면 글자밭이
되고, 확대해 들여다볼 때는 짧은 조각도 이름이 필요하다. 겹치면 건너뛴다.

휠 확대 · 오른쪽 끌어 이동 · `F` 화면 맞춤.

### 찍는 법 — 세 가지

| 방식 | 동작 |
|---|---|
| **트랙 가져오기** (가장 빠름) | 배경의 트랙을 클릭해 고르고 `G`. 그 트랙이 **실제로 움직인 시각 그대로** 키프레임이 된다 — 시간을 지어내지 않으니 **싱크가 저절로 맞는다**. 여러 트랙을 이어 가져오면 한 사람의 동선이 완성된다 |
| **차례 찍기** | 출발 자리부터 차례로 클릭. 한 번에 **1초씩**(0.5~2초 고를 수 있다) 붙는다 |
| **쭉 긋기** | 끌어서 한 번에. 간격대로 점이 자동으로 박힌다 |

그리고 **대충 찍어도 되게** 하는 버튼 둘.

| 버튼 | 하는 일 |
|---|---|
| **[시각까지 맞추기]** | 자리만 대충 찍어 두면, 각 점마다 "실측 사람들이 거기에 있던 시각"을 찾아 **시각을 정하고** 자리도 무리 중심으로 당긴다. 시각은 앞 점보다 뒤에서만 찾는다(뒤로 갈 수는 없다) |
| **[자리만]** | 시각은 내가 정한 대로 두고 **자리만** 실측으로 당긴다 |

붐빈 정도가 최댓값의 절반만 넘으면 그중 **가장 이른** 때를 고른다. 무작정
최댓값을 고르면 문 앞처럼 나중에 붐비는 자리에서 늦은 시각으로 끌려간다
(실측: 19.9초에 지나간 자리를 37.4초로 잡았다).

권하는 순서 — **대충 찍기 → [시각까지 맞추기] → [출구 시각에 맞추기]**.

다 찍고 **[출구 시각에 맞추기]** 를 누르면 마지막 점이 그 사람의 **실제 통과
시각**에 오도록 전체가 늘어난다(퇴장 시각도 같이 박힌다). P01~P10 목록에
배정된 통과 시각이 미리 떠 있다 — 01 IDR 이면 18·19·20·24·25·27·28·30·32·33s.

실측: 긴 트랙 3개를 이어 가져오니 45점짜리 동선이 한 번에 만들어졌고,
맞추기 한 번으로 37.6초 → 17.8초(통과 18.0s)로 정렬됐다.

| 키 | 동작 |
|---|---|
| `G` | 고른 트랙 가져오기 (`Alt`+클릭으로 어느 모드에서든 고를 수 있다) |
| `1`~`0` | 사람 고르기 (P01~P10) |
| `Ctrl`+`Z` | 마지막 점 취소 |
| `F` | 화면 맞춤 |
| `Space` / `←` `→` | 재생·정지 / 0.2초 이동 (`Shift` 함께 = 1초) |
| `X` | 이 순간을 퇴장으로 |

### 벽을 뚫었는지는 저장할 때 알려 준다

브라우저에서 벽을 판정하려면 격자를 통째로 내려보내야 하고, 다 그린 뒤에 알게
되면 다시 그려야 한다. **저장 순간 서버가 한 번 본다** — 뚫은 사람과 구간 수를
띄운다(`⚠ 벽·장애물 통과: P01(37)`). 깨끗하면 `벽 통과 없음 ✅`.

### 사이는 어떻게 메우나

**Catmull-Rom** 곡선이다. 직선으로 이으면 꺾이는 자리마다 각이 져서 사람이 아니라
로봇처럼 보인다. 찍은 점을 **그대로 지나가는** 곡선이라 찍은 자리를 배신하지
않는다(검증: 오차 0.00px). 0.1초 간격으로 펴서 영상에 넣는다.

저장 위치 `results/demo/_annotate/paths_<세션>.json`.

## 각본 연출 — 각본이 읽히게

이상적 궤적(앞 절)만으로는 **각본이 읽히지 않았다.** 실측 트랙이 카메라 사각과
오검출로 그렇게 찍힌 것이지 훈련이 그랬던 게 아니다:

- 우회 5명이어야 할 장면에 2명만 돌았다
- 줄지어 가야 할 4명이 3명으로 보였다
- 뭉쳐 가야 할 무리에서 둘이 뒤처졌다 나중에 합류했다
- 우회조가 출구 문 앞까지 갔다 **되돌아 나왔다**
- 점 179개가 **의자·적치물 위를 지나갔다**
- 우측 그리드에서 사람이 이미 문을 지났는데 좌측 점은 저 멀리 있었다
- 출구 **문틀(벽)** 을 겨누고 걸어갔다 — 수선의 발을 쓴 탓이다. 문 한가운데로 고쳤다

**길은 실측 동선 그대로 쓴다**(`tools/demo_choreo.py`). 도면 위에 최적 경로를 새로
그어 봤더니 사람이 실제로 다닌 자리와 달라져 우측 그리드 영상과 따로 놀았다 —
그건 시각화가 아니라 그림이다. 여기서 하는 일은 셋뿐이다.

1. **무리 나누기** — 실측 궤적을 곧장 간 쪽 / 크게 돌아간 쪽으로 가른다
   (시작지점→출구 직선에서 수직으로 얼마나 벗어났나)
2. **인원 맞추기** — 각 무리의 **실측 대표 동선**에 각본 인원을 태운다. 실제로 그
   길로 간 사람이 2명뿐이어도 각본이 5명이면 5명을 그 동선에 올린다. 출발 간격과
   좌우 폭만 준다 — 줄서기는 좁게(0.3m), 밀집은 넓게(1.5m)
3. **비켜 가기** — 장애물 안에 찍힌 점만 **진행방향과 수직으로 밀어** 뺀다.
   길을 새로 긋지 않는다 → 동선 모양과 시간축이 실측 그대로라 그리드와 안 어긋난다

### 싱크 — 실제 속도 곡선을 그대로 들고 간다

트랙렛 길이로 시간을 매기면 어긋난다. 그렇다고 **시간을 균등하게 다시 매기면**
더 나빠진다 — 실제 속도 곡선이 뭉개져 (ⓐ) 어디선가 갑자기 빨라지고 (ⓑ) 문 앞에서
멈칫하는 **병목이 사라지고** (ⓒ) 끝만 맞고 중간이 어긋난다.

그래서 대표가 실제로 걸은 **(시각, 위치) 짝을 그대로 쓰고**, 문을 지나는 시각만
배정받은 통과 시각에 맞춰 **통째로 민다**. 속도는 실측 그대로라 중간도 저절로
맞는다.

| 규칙 | 왜 |
|---|---|
| 시간은 실측 그대로, 평행이동만 | 속도 곡선·병목 대기를 보존한다 |
| **반드시 문에서 끝난다** | 지나친 뒤를 남기면 나간 점이 벽을 통과해 다시 나타난다 |
| 자르는 건 **맨 마지막** | 벽을 피해 옆으로 미는 손질이 점을 출구선에 스치게 만든다. 그 전에 자르면 잘못된 데서 끊긴다(실측: 01 IDR 3명) |
| 경로가 통과 시각보다 길면 **길이를 줄인다** | t0 를 0 으로 자르면 끝 시각이 밀린다(실측: 02 EPFI 우회 3명 4초 늦음) |
| 출발은 그 무리에서 **가장 이른 사람** 기준 | 중앙값이면 그리드에서 다들 움직이는데 점은 서 있다(03 CBS 는 첫 사람이 **0.8초**인데 중앙값이 28초였다) |

| 영상 | 실제 통과 시각 | 점이 지나는 시각 | 차이 |
|---|---|---|---|
| 01_IDR | 18·19·20·24·25·27·28·30·32·33 | 동일 | **0.0s** |
| 02_EPFI | 21·22·23·25·28·28 / 50·51·52·55 | 동일 | **0.0s** |
| 03_CBS | 44·45·45·45·46·46·48·48·49·49 | 동일 | **0.0s** |

`02_EPFI` 의 통과 시각이 **21~28초(6건) / 50~55초(4건)** 로 갈라진다 — 각본의
직선 6명 / 우회 4명과 그대로 맞는다.

### 04_SEI 는 각본 연출을 하지 않는다

1층은 계단에서 내려오는 동선이라 손댈수록 그리드와 어긋났다. **운영 웹 UI
(④ 리플레이)가 그리는 그대로** 원 관측을 보간해 찍는다.

```bash

```

### 속도가 갑자기 빨라지지 않게

이어 붙이고 자르고 미는 손질이 쌓이면 어느 구간에서 점이 튄다. 원인은 셋이었고
전부 **시간을 억지로 맞추려다** 생겼다.

| 원인 | 실측 | 고친 방법 |
|---|---|---|
| 카메라 사각을 **돌아서** 메우는데 원래 공백 시간에 욱여넣음 | 7~28 m/s | 걷는 데 걸리는 만큼 시간을 주고 **뒤를 통째로 민다**(끝은 어차피 통과 시각에 다시 못 박는다) |
| 문 앞 혼잡 구간의 실측 잡음을 0.4m 까지 끌고 감 | 순간 58 m/s | **문 앞 1.2m 에서 끊는다** — 화면에서 1.2m 는 문을 지난 것으로 읽힌다 |
| 한 점만 확 튀는 잡음 | — | 0.5초 **중앙값**으로 누른다(이동평균은 튄 점을 이웃으로 퍼뜨릴 뿐이다) |

결과 — 1초 평균 최고 속도: 01_IDR **4.0** · 02_EPFI **3.8** · 03_CBS **3.5** m/s.
(고치기 전 7.4 / 5.1 / 6.2, 중간 시도에서는 28.4까지 갔다.)

### 선이 벽을 뚫지 않게

점만 벽 밖으로 밀어내면 **두 점을 잇는 선분**이 얇은 벽을 건너뛴다(점 간격
0.35m, 벽 격자 0.08m). 보이는 건 선이니 선을 봐야 한다.

- 시간 격자에 올리기 **전**에는 막힌 구간에 돌아가는 길을 끼워 넣는다
- 올린 **뒤**에는 개수가 곧 시간이라 끼워 넣을 수 없다. 그 점만 **옆으로 살짝**
  민다(30cm~1.6m). 앞 점에 붙여 버리면 거기서 멈추고 그 뒤로도 계속 막혀
  **한 사람이 통째로 얼어붙는다**(실측: 02 EPFI 우회 3명이 출구에 못 닿고 끝났다)
- 서 있는 점은 진행방향이 없어 '옆'이 정의되지 않는다 — 사방으로 찾는다
  (실측: 시작 슬롯이 장애물 안에 놓여 한 사람이 통째로 벽에 박혔다)

(점 하나라 **클릭하면 바로 저장**된다 — [저장] 버튼과 무관).

| **시작지점** | 자동(실측 첫 점들이 가장 빽빽한 곳)으로도 잡지만, 찍어 주면 그게 우선이다 |

### 손본 두 가지

**출구에서 거꾸로 나오는 조각** — 계단 쪽 카메라가 내려간 사람을 다시 잡은 것이
우회조 사슬에 붙어, "출구에서 누가 역으로 나와 합류하는" 그림이 됐다(실측:
02 EPFI 의 `cam13:9`·`cam13:11` 이 출구 2m 에서 13m 로 멀어졌다). 문 앞에서
시작해 멀어지는 조각은 잇기 전에 뺀다.

**헛걸음** — 실측 우회 대표가 문 앞까지 갔다가 되돌아 나와 다시 들어온다
(출구거리 14→1→14→1). 각본은 "줄서서 빙 돌아 **들어간다**"다. 나가는 길과
되돌아 나온 길이 **둘 다 문에서 9m쯤 떨어져 있던 지점**을 찾아 둘을 잇고 사이를
뺀다. 잇는 구간만 새로 긋되 **출구 둘레를 막아 놓고** 계산해 로비를 가로지르지
않게 했다. 우회 고리 전체는 실측 동선 그대로다.

## 붙박이 오검출 제외

이 영상들은 **이상적인 케이스를 보여주는 자리**다. 도면 한 자리에 40초씩 박혀
있는 점이 있으면 보는 사람은 그게 지표 이야기인 줄 안다. 실제로는 사람이 아니다.

`03_CBS` 에서 상단에 계속 떠 있던 **물체 3개**를 뺐다(트랙은 5개 — 트래커가 id 를
새로 따서 같은 물체가 두 번 잡혔다).

| 트랙 | 위치 | 지속 | 정체 (원본 영상 확인) |
|---|---|---:|---|
| `cam3:71` · `cam3:57` | 도면 (986,239) | 43s · 7s | cam3 좌측 프레임 가장자리에 잘린 **의자** |
| `cam3:72` | 도면 (997,119) | 43s | 같은 가장자리의 **의자**(위쪽) |
| `cam1:81` · `cam1:30` | 도면 (856,261) | 37s · 13s | cam1 **벽 부착물**(소화전/센서류) |

**화면에서만 지우지 않는다** — 제외한 트랙은 엔진에 아예 넣지 않는다
(`run_replay(..., {"exclude_tracks": [...]})`). 그림에는 없는데 지표는 유령을
세고 있는 상태가 더 나쁘다.

그리고 실제로 **지표가 틀려 있었다.** 붙박이 3개를 빼자 `03_CBS` 의 IDR 이 살아났다
— 한 자리에 40초씩 박힌 점이 구역 안에 있으니 "이 구역은 아직 피난을 시작하지
않았다"로 계속 판정되고 있었던 것이다.

| | EPFI | CBS | SEI | IDR | 카운팅 | 최대 재실 |
|---|---:|---:|---:|---:|---:|---:|
| 제외 전 | 76.5 | 4.18 | 53.3 | **미개시 0/1** | 10 | 17 |
| 제외 후 | 78.0 | 4.18 | 53.3 | **0.46 m/s · 1/1** | 10 | 14 |

CBS·SEI·카운팅은 그대로다(병목·출구는 유령이 있던 자리와 무관하다).

### 확정은 사람이 한다

자동 규칙(25초 이상 · 반경 1m 미만)은 **진짜 사람도 문다.** 실측으로 확인했다:

| 세션 | 후보 | 원본 확인 | 처리 |
|---|---|---|---|
| 02_EPFI | `cam8:80` (26s, 0.90m) | 계단에 **서 있던 사람** | **제외 안 함** |
| 04_SEI | `cam39:70`·`cam39:49` (39s·31s) | 소파에 **앉아 있던 사람** | **제외 안 함** |

그래서 제외 목록은 **CBS 한 건에만** 있다. 절차는 제안 → 크롭 대조 → 확정이다.

```bash

       --sheet /tmp/sheet.png --save     # 후보 제안 + 크롭 대조표

```

사람을 지운 영상은 오검출을 남긴 영상보다 나쁘다. 이 단계를 건너뛰지 않는다.

## 장애물 표시 — 전용 편집기 (:8920)

도면에는 없지만 실제로는 못 지나가는 것(의자·적치물·통행금지 구역)을 찍어 둔다.
**운영 웹 UI(:8900)·CAD 편집기(:8910)와 완전히 분리**돼 있다 — 저 둘의 설정·도면을
전혀 건드리지 않고, 여기서 찍은 것은 발표 시각화에만 쓰인다.

```bash
python tools/annot_paths.py          # 밑그림(도면 + 실제 동선) 생성 — 한 번만
python tools/obstacle_editor.py      # http://<서버>:8920
```

**현재 찍힌 것** — 3층(floor4·floor6 공유) **10개**(통행금지 4 · 의자 4 · 박스 2),
1층(floor5) **3개**(의자 1 · 박스 2). 영상 4건 모두 이 상태로 찍었다.

| 항목 | 내용 |
|---|---|
| 종류 | CAD 편집기와 같은 3종 — 의자·집기 / 박스·적치물 / 통행금지 (같은 색·해치) |

점판과 히트맵판의 수치는 **완전히 같다**(같은 세션·같은 재계산, 맵 표출만 다르다).
`03_CBS` 의 EPFI·IDR 은 붙박이 오검출을 뺀 값이다(아래 절).

출발한 몇 명이 '산출 불가'로 빠진다).

장애물을 고치면 `demo_viz` 가 사이드카에 박아 둔 지문(`_obstacles_sig`)이 안 맞아
**개인 경로를 자동으로 다시 산출**한다 — 따로 지울 필요 없다.

## 재생성

```bash
python tools/demo_viz.py --session <sess-id> --metric IDR|EPFI|CBS|SEI \
       --out results/demo/<폴더> --map dots|heat [--th '{"dt_hold":1.0}']
```

`--map heat` 는 파일명에 `_heat` 가 붙어 점판을 덮어쓰지 않는다.

`<영상>.json` 에 그 영상의 근거 수치(4대 지표·구역별·출구별·경로 산출 통계)를 같이 남긴다.
