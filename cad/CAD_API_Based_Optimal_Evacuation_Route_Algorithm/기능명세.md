# evac 모듈 기능명세서

CAD 도면 기반 **최적 피난경로 산출** 모듈. 삼성 `TravelDistance_Analyzer`(C# AutoCAD
매크로)의 로직을 AutoCAD 없이 **리눅스/파이썬**으로 재구현하고, 다른 파이프라인에서
가져다 쓸 수 있도록 모듈화한 것. (분석 배경·검증결과는 [README.md](README.md) 참조.)

- 버전: `evac 0.1.0`
- 의존: `numpy`, `scipy`(csgraph.dijkstra `min_only`, ndimage.label), `ezdxf`, `matplotlib`
- 환경: conda `boosttrack`(Python 3.12). DWG→DXF 변환은 상위 `tools/cad_convert.py` 사용.

---

## 1. 목적 / 범위

| 구분 | 내용 |
|------|------|
| 입력 | CAD 평면도(DXF) — 장애물 형상 + Exit(피난계단) + (선택)출발점 |
| 처리 | 공간 격자화 → 멀티소스 다익스트라 최단거리 → 최근접 Exit까지 경로 + 평활화 |
| 출력 | 경로별 (피난거리 m, Pass/Fail, 경로 폴리라인) + 렌더 PNG(미터격자·스케일바) |
| 목표지표 | EPFI(예상 피난시간)·피난거리의 기준/정답 산출 → [4대지표 요구사항](../../docs/requirements/삼성화재-피난훈련-정량평가-4대지표-요구사항.md) |

## 2. 모듈 구조

```
evac/
├── __init__.py   패키지 진입 · 공개 심볼
├── core.py       ★순수 알고리즘(numpy/scipy). CAD·플롯 의존 없음 → 어디서나 재사용
├── cad.py        DXF 입출력(장애물/Exit/Occupant 수집, Exit 역주입, ref 로드)
├── render.py     평면도/경로/연결성 렌더(Agg, 헤드리스 OK)
├── pick.py       Exit 대화식 지정기(GUI, 디스플레이 필요)
└── cli.py        커맨드라인(route / pick / connect)
evac_route.py     CLI 얇은 진입점(하위호환)
```

**계층 원칙**: `core`는 도면 포맷·좌표계를 모른다(도면단위 mm 선분/점만 받음).
CAD 종속은 `cad`, 시각화는 `render`에 격리 → core를 트래킹·시뮬 등 타 입력에 재사용 가능.

## 3. 공개 API (core — 재사용 핵심)

### `core.analyze(obstacles, exits, bounds, *, starts=None, mode="occupant", worst_n=5, cell=50.0, clearance=304.8, threshold_mm=30000.0, max_cells=30_000_000) -> Analysis`
피난경로 산출 메인 진입점.

| 인자 | 타입 | 설명 |
|------|------|------|
| `obstacles` | ndarray (N,4) | 장애물 선분 `[x1,y1,x2,y2]` (도면단위 mm) |
| `exits` | list[(x,y)] | 도착점(도면단위). 여러 개면 각자 source, **최근접 자동 선택** |
| `bounds` | (minx,miny,maxx,maxy) | 탐색범위(도면단위) |
| `starts` | list[(x,y)] | occupant 모드 출발점. worstn이면 무시 |
| `mode` | "occupant"/"worstn" | 지정 출발점 / 자동 worst 추출 |
| `cell` | float | 격자 셀 크기(mm, 기본 50) |
| `clearance` | float | 벽 이격(mm, 기본 304.8=1ft) |
| `threshold_mm` | float | Pass/Fail 기준 피난거리(mm) |

**반환** `Analysis` 객체 속성:
- `paths` : `[{"path_m":[(x,y)…], "dist_mm":float, "is_pass":bool, "start_m":(x,y)}]`
- `grid`(bool[cols,rows] 벽=True), `dist`(거리장), `cols`,`rows`,`cell`,`clearance`,
  `n_free`,`n_wall`,`skipped`(도달불가 출발점 수), `bounds`

### 그 외 core 함수 (하위 재사용)
- `build_obstacle_grid(obstacles,minx,miny,cols,rows,cell,clearance,exit_cells) -> bool[,]`
- `run_dijkstra(grid, exit_cells, cell) -> (dist, pred, inv_c, inv_r, idx)` — 멀티소스
- `trace_path(pred, inv_c, inv_r, grid, start_node) -> [(c,r)]` — 역추적+String-Pulling
- `nearest_reachable(grid, dist, oc, or_, clearance, cell)` — 출발점 스냅
- `connectivity(obstacles, bounds, cell, clearance) -> dict` — 보행공간 연결성 진단
- 좌표: `world_to_grid`, `grid_to_world`

### cad
- `load_dxf(path) -> DxfData(obstacles, exits, occupants, bounds, doc, path)`
  - `DxfData.m_to_world(xm,ym)`, `.world_to_m(x,y)` — SW코너=0 미터 ↔ 도면 mm
- `write_exits_dxf(src, out, exits_world, bar_len=1000)` — Exit를 `Evac_Exit` 선으로 역주입
- `load_reference_paths(doc)`, `save_exits_json`, `load_exits_json`

### render
- `render_routes(out, obstacles, bounds, analysis, *, exits, ref, threshold_mm, dpi, title_extra)`
- `render_connectivity(out, obstacles, bounds, conn, dpi)`

### pick
- `pick_points(dxf, n=None, kind="Exit") -> [(xm,ym)]` — 맵 클릭(디스플레이 필요; 없으면 RuntimeError)

## 3.5 웹 도면 편집기 (`evac/web.py` + `evac/static/editor.html`)

CAD 없이 **브라우저에서 터치업(문 열기·치수선 삭제)·Exit 지정·검증·적용**까지 하는
독립 웹서비스. 운영 웹(:8900) 맵설정의 "CAD 도면에서 만들기" 버튼이 새 창으로 여는 대상.

```bash
cd cad/CAD_API_Based_Optimal_Evacuation_Route_Algorithm
conda run -n boosttrack uvicorn evac.web:app --host 0.0.0.0 --port 8910
# → http://<host>:8910/
```

| 단계 | 조작 | 구현 |
|------|------|------|
| ① 업로드 | DWG/DXF 드래그앤드롭 | DWG는 ODA 헤드리스 자동변환. `Evac_Exit` 레이어 있으면 Exit 자동인식 |
| ② 정리 | [🧹 삭제] 박스 드래그(엔티티 단위, undo) · [🚪 개구부] 선 드래그(셀 carve, 문폭 **900mm 고정** — `editor.html` 하드코딩, UI 조절 불가) | 비파괴 — 원본 무손상, 편집내역만 JSON. **뚫은 구간은 마진 0**(위 §8 과제) |
| — 보기 | 연결성 오버레이 토글 | 초록=연결·주황=고립, 편집 시 자동 갱신(100mm 프리뷰 셀, ~2s) |
| ③ Exit | 선 드래그 N개 | 중점=도착점(매크로 규약 동일) |
| ④ 검증 | 기준거리·worst N 입력 → 경로 표시 · **거리 열지도**(전체 거리장 색표현: 초록=가까움→빨강=멂, 회색=도달불가) | worst-N은 50mm 풀해상도(~5s), 열지도는 100mm(~3s). `GET /api/distfield.png` |
| ⑤ 적용 | site 이름 → [저장&적용] | `data/sites/<site>/`에 `map.png`(터치업 도면)+`floor.json`(편집내역·m_per_px 자동)+`evac_distfield.npz`(거리장) |

- **운영 웹 연동(2026-07-17)**: 운영 웹(:8900) 맵설정 툴바의 **[CAD 도면에서 만들기]**
  버튼이 이 편집기를 새 창(`?live=1`)으로 연다. 적용 완료 시 편집기가
  `postMessage('evac-floor-applied')`를 보내고 메인 맵설정이 맵·축척을 **자동 갱신**.
  (수정 파일: `webui/static/main/index.html` 버튼 1개 + `view_map.js` 핸들러/리스너 —
  기존 로직 무변경 추가분.) 편집기는 pm2 `evac-editor`로 상시 구동.
- **운영 서버(:8900) 즉시 반영은 opt-in 체크박스** (직접 접속 시 기본 꺼짐,
  **버튼 경유(`?live=1`) 시 기본 켜짐** — 맵설정에서 열었다는 명시적 의도). :8900의
  `POST /api/site/map`은 site 구분 없이 default 맵을 교체하므로 실수 방지용
  안전장치 — 실측 사고(2026-07-16, 즉시 복구됨)로 확인된 리스크.
- API: `POST /api/load` · `GET /api/geometry`(바이너리 세그먼트) · `POST /api/edits`

## 4. CLI

```bash
PY=~/miniconda3/envs/boosttrack/bin/python
# 경로 산출 + 렌더 (Exit: DXF레이어 > --exits > --exits-json)
$PY evac_route.py route --dxf Egress_Review-Test.dxf --out out.png --show-ref
$PY evac_route.py route --dxf plan.dxf --exits "10,5;60,65" --mode worstn --worst-n 8
$PY evac_route.py route --dxf plan.dxf --starts "12,40;55,20" --threshold-m 30

# Exit 대화식 지정(GUI) → JSON + DXF 역주입
$PY evac_route.py pick --dxf plan.dxf --n 2 --out-json exits.json --write-exits-dxf plan_tagged.dxf

# 보행공간 연결성 진단(도면 품질 점검)
$PY evac_route.py connect --dxf 17F.dxf --out conn.png
```
공통 옵션: `--cell`(mm) `--clearance`(mm) `--dpi`. `python -m evac.cli ...` 로도 동일 호출.

## 5. 입력 규약 (도면 주석) — 매크로와 동일

| 요소 | 레이어 | 형식 | 의미 |
|------|--------|------|------|
| Exit | `Evac_Exit` | Line | **선의 중점**이 도착점. N개면 최근접 자동 |
| 출발점 | `Evac_Occupant` | Polyline/Line 꼭짓점 | occupant 모드 검토점 |
| 장애물 | 위 특수레이어(+결과레이어) **제외 전부** | 모든 형상 | 피해서 가야 할 대상 |

Exit/출발점이 도면에 없으면: **pick(GUI 클릭)** 또는 **CLI 미터좌표 주입**(`--exits`/`--starts`,
SW코너=0 기준 미터 — 척도이미지와 동일)으로 공급. pick 결과는 `write_exits_dxf`로 도면에
`Evac_Exit` 선으로 되돌려 넣어(=매크로 규약 도면 생성) 재사용·검증 가능.

**좌표계/단위**: 도면 내부단위 mm, `$INSUNITS` 자동감지. 미터기준 SW코너=extents min.

## 6. 원본 매크로 대비 (구현범위 / 의도적 차이)

| 항목 | C# 매크로 | evac 포팅 |
|------|-----------|-----------|
| 격자·이격·다익스트라·평활화 | ✓ | ✓ 동일(50mm/304.8mm/8방향/String-Pulling) |
| 최근접 Exit(멀티 Exit) | ✓ | ✓ 멀티소스 다익스트라 |
| 탐색범위 | 사용자 두 코너 클릭 | 도면 extents 자동(또는 bounds 인자) |
| WorstN | 2단계 멀티해상도(속도) | 단일 고해상도 전탐색(scipy로 빠름·더 정확) |
| 거리값 | 폴리라인 실제길이(필드) | 다익스트라 격자거리(=매크로 Pass/Fail 판정기준) |
| 출력 | AutoCAD Polyline/텍스트/Wipeout | PNG 렌더 + 경로좌표 데이터(dict) |
| 미구현 | — | AutoCAD 엔티티 쓰기(불필요), 순위 라벨(dead code였음) |

검증: `Egress_Review-Test.dxf`의 매크로 원본 출력과 대조 → 겹치는 10개 출발점 **Pass/Fail
100% 일치**, 거리오차 +0.4~0.9m(격자거리 vs 폴리라인길이 차이). 상세 README §7.

## 7. 확장 / 통합 포인트

- **트래킹 연동(핵심)**: 한 번 만든 장애물 격자·거리장(`analyze`의 `grid`/`dist`)을 캐시하고,
  매 프레임 트래킹이 주는 재실자 평면좌표를 `starts`로 넣어 **실시간 피난거리/경로** 산출.
  거리장은 Exit 고정 시 1회 계산이면 되므로 프레임당 비용은 역추적뿐.
- **다중 층/구역**: bounds·cell을 인자로 받으므로 층별 독립 실행.
- **입력 무관성**: core는 선분/점만 받음 → DXF 외(예: 세그멘테이션 마스크→선분)로도 확장 가능.

## 8. 제약 / 주의

- **도면 품질 의존**: 벽이 닫힌 폴리곤이고 **문 개구부가 벡터에 있어야** 내부↔복도가 연결됨.
  PDF 트레이스본(예: 현 `17F.dxf`)은 문 정보가 없어 보행망이 조각남 → `connect`로 먼저 진단.
- **격자 상한**: `max_cells`(기본 3천만). 대형 범위는 `--cell`↑ 또는 bounds 축소.
- **pick GUI**: 디스플레이 필요. 헤드리스 서버는 `--exits`/`--exits-json` 사용.
- **정합**: 실제 배치·좌표는 실측 도면·카메라 파라미터로 재보정 전제(현 데모 좌표는 근사).
- ⚠ **개구부 뚫기는 경로 마진을 무시한다** — 벽은 `CLEARANCE`(304.8mm)만큼 부풀려
  통행불가로 잡히지만, `carve_free`/`apply_shapes(op="open")` 은 그 마진까지 지운다.
  자연 개구부는 경로가 벽에서 300mm+ 떨어져 지나가는데 뚫은 개구부는 5mm까지 붙는다
  (실측). 같은 도면에서 개구부를 만든 방식에 따라 피난거리가 달라진다.
  → **미착수 개발과제**: [개발과제_개구부-뚫기-마진-미적용.md](개발과제_개구부-뚫기-마진-미적용.md)
