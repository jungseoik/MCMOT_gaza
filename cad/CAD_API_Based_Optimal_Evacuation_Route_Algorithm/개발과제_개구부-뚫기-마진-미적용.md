# [개발과제] 개구부 뚫기가 경로 마진(clearance)을 무시한다

> 상태: **미착수 — 설계 확정 후 구현** (2026-08-23 기록)
> 제기: 현장 피드백 — "개구부 뚫기 기능시 마진값을 고려해야 한다"
> 관련: `evac/core.py` (`CLEARANCE` · `carve_free` · `apply_shapes`) ·
> `evac/static/editor.html` (개구부 뚫기 도구) · [기능명세.md §8](기능명세.md)

---

## 1. 배경 — 경로 마진은 실제로 있다

피드백에서 말한 "r값"은 실재한다. `core.py`의 `CLEARANCE = 304.8mm (=1ft)` 로,
격자를 만들 때 **모든 벽 선분을 이 값만큼 부풀려 벽으로 칠한다**.

```python
# core.py:build_obstacle_grid()
grid[c1:c2+1, r1:r2+1] |= (d < clearance)   # 셀중심~벽 거리 < 304.8mm → 통행불가
```

덕분에 경로가 벽·모서리에 딱 붙어 지나가지 않는다. **실측**(합성 도면, 벽 사이 틈만
두고 통과시킨 뒤 경로를 10mm 간격으로 샘플링해 벽까지 최단거리 측정):

| 벽 사이 틈 | 경로가 벽에 붙는 최소거리 | 판정 |
|---|---|---|
| 700 mm | 325.0 mm | ✔ 마진 확보 |
| 900 mm | 425.0 mm | ✔ |
| 1200 mm | 575.0 mm | ✔ |
| 2000 mm | 975.0 mm | ✔ |

부수적으로 **통과 가능한 최소 틈 = 2 × 304.8 = 609.6 mm** 가 도출된다.

| 틈 | 유효폭(= 틈 − 2×clearance) | 결과 |
|---|---|---|
| 600 mm | −9.6 mm | 막힘 |
| 610 mm | +0.4 mm | 막힘 (격자 50mm 해상도라 못 잡음) |
| 700 mm | +90.4 mm | 통과 |

→ 도면에 문이 600mm로 그려져 있으면 **아예 통행 불가로 판정**된다.
사용자가 개구부 뚫기를 쓰는 주된 이유가 이것이다.

---

## 2. 문제 — 뚫은 구간만 마진이 0이 된다

`carve_free()` / `apply_shapes(op="open")` 는 대상 셀을 **강제로 통행가능(False)**
으로 만든다. 벽 부풀리기가 끝난 **뒤에** 덮어쓰므로, 뚫린 영역 안에서는 clearance가
사라진다.

```python
# core.py:analyze() — 적용 순서
grid = build_obstacle_grid(..., clearance, ...)   # ① 벽 + 마진
carve_free(grid, openings, ..., width)            # ② 뚫기 — ①의 마진까지 지운다
apply_shapes(grid, shapes, ...)                   # ③ open → block
```

**실측** (벽을 통짜로 두고 개구부 뚫기만으로 통과):

| 뚫기 폭 | 경로가 벽에 붙는 최소거리 | 판정 |
|---|---|---|
| 700 mm | 5.0 mm | ✘ |
| 900 mm | 5.0 mm | ✘ |
| 1200 mm | 5.0 mm | ✘ |
| 2000 mm | 5.0 mm | ✘ |

폭을 키워도 **5.0mm로 동일**하다 — 뚫린 영역 가장자리를 그대로 타고 가기 때문.

### 결과: 같은 도면에서 두 규칙이 공존한다

| 개구부 종류 | 통과 판정 기준 | 경로 마진 |
|---|---|---|
| 자연 개구부(도면상 틈) | 틈 ≥ 609.6 mm | 304.8 mm 확보 |
| **개구부 뚫기 도구** | 뚫기 폭이 격자에 잡히기만 하면 통과 | **0** |

피난거리(EPFI 기준값)가 개구부를 어떻게 만들었느냐에 따라 달라진다.

---

## 3. 현재 UI 상태 (같이 손봐야 할 것)

- 개구부 뚫기 **선** 폭 `900mm` 이 `editor.html` 에 하드코딩 (`sh.w = 900`) — 조절 불가
- **사각형** 뚫기는 그 영역 전체가 마진 없이 뚫린다
- `CLEARANCE` 는 UI에 노출되지 않음 (결과 JSON `clearance_mm` 에 기록만)

---

## 4. 검토한 방향 (택일 — 미확정)

### ① 뚫기 폭에서 마진을 빼고 뚫는다 (제안)
`실제 뚫는 반경 = w/2 − clearance`

- 900mm 문을 뚫으면 유효 통행폭 290mm → **자연 틈 900mm와 완전히 동일**해진다.
  규칙이 하나로 통일.
- 609.6mm 이하로 뚫으면 막히지만, 그것도 자연 틈과 같은 기준이라 일관적이다.
- **주의: 기존 결과가 바뀐다.** 지금까지 뚫어둔 개구부의 유효폭이 609.6mm씩
  줄어들어, 좁게 뚫어둔 곳은 통행 불가로 바뀔 수 있다 → 재검증 필요.

### ② 뚫은 뒤 경계에 마진을 다시 입힌다
뚫기 영역 경계에서 clearance만큼 다시 벽 처리. ①과 결과는 비슷하나 구현이 복잡하고
사각형 뚫기에서 의도가 애매해진다(어느 변이 벽인가).

### ③ 폭·마진을 UI에 노출
뚫기 폭(현 900 고정)과 clearance를 편집기에서 조절 가능하게. ①과 함께 가면 좋다 —
현장마다 문 폭·마진 기준이 다르다.

---

## 5. 확정 필요 항목

1. **clearance 304.8mm(1ft)가 맞는 기준인가** — 삼성 원본 매크로 상수를 그대로
   가져온 값이다. 국내 피난 설계 기준에 맞는 값인지 고객 확인 필요.
2. **①을 적용할 때 기존 뚫기 데이터를 어떻게 할 것인가** — 자동 보정(폭 +609.6mm)
   할지, 재작업을 요구할지.
3. **사각형 뚫기의 마진 규칙** — 영역 전체를 뚫되 경계만 마진? 아니면 안쪽으로 축소?

## 6. 재현 방법

```python
# conda activate boosttrack / repo 루트에서
import numpy as np, math
from evac import core

def wall_clear(gap_mm, carve=None):
    """벽 y=3000, 위(3000,5500)에서 아래 Exit(3000,500)로. 경로↔벽 최소거리 반환."""
    half = gap_mm / 2.0
    obst = ([(0,3000,3000-half,3000), (3000+half,3000,6000,3000)] if gap_mm > 0
            else [(0,3000,6000,3000)])
    shapes = ([{"op":"open","kind":"line","w":carve,"pts":[3000,3000,3000,3000]}]
              if carve else None)
    a = core.analyze(np.array(obst,float), [(3000,500)], (0,0,6000,6000),
                     starts=[(3000,5500)], mode="occupant",
                     cell=50.0, clearance=core.CLEARANCE, shapes=shapes)
    # a.paths[0]["path_m"] 를 10mm 간격으로 densify 후 obst 까지 최단거리 min
```

`wall_clear(900)` → 425.0mm (자연 틈) · `wall_clear(0, carve=900)` → 5.0mm (뚫기).
