# 피난훈련 평가 레포트 작성

세션 종료로 산출된 4대 지표를 **해석**해 훈련평가 보고서를 쓴다.
숫자 계산은 `tools/session_digest.py`가, **해석·서술은 이 절차가** 담당한다.

기준 문서: [4대지표 요구사항](../../../docs/requirements/삼성화재-피난훈련-정량평가-4대지표-요구사항.md)
· 지표별 상세: [IDR](../../../docs/requirements/IDR-피난반응확산지표.md) ·
[EPFI](../../../docs/requirements/EPFI-경로충실도지표.md) ·
[CBS](../../../docs/requirements/CBS-병목혼잡누적지표.md) ·
[SEI](../../../docs/requirements/SEI-비상구활용효율지표.md)

## 🚫 절대 하지 않는 것 (요구사항이 못 박은 것)

1. **종합점수·A/B/C 등급을 만들지 않는다.** 요구사항 D-8: "본 문서 범위에서 제외.
   4대 지표는 개별 산출까지만. 종합점수·등급·가중치는 고객 승인 기준 확정 후 별도 반영."
   → 4지표를 가중합·평균내거나 "종합 82점", "B등급", "양호/보통/미흡 종합판정" 같은
   표현을 쓰지 않는다. 지표 간 **교차 관찰**은 하되 **합산은 하지 않는다**.
2. **`null`을 0으로 읽지 않는다.**
   - `sei: null` = `insufficient_data` (통과 인원 0) — "SEI 0점"이 아니다.
   - zone `idr: null` + `status: "not_started"` = **피난 미개시**. 값이 낮은 게 아니라
     **아예 시작하지 않은 것**이며, 대개 그 세션에서 가장 중요한 발견이다.
   - `epfi: null` = 경로 미배정.
3. **임계값을 확정 기준처럼 쓰지 않는다.** 요구사항 §9: 모든 임계값
   (`v_th, a_th, r_th, Δt_hold, d_allow, ρcrit, w_k`)은 **고객 미확정**.
   판정 문장에는 항상 "현 임계값(<값>) 기준"이라는 단서를 붙인다.
4. **다이제스트에 없는 수치를 지어내지 않는다.** 모든 숫자는 다이제스트에서 온 것만
   쓰고, 필요하면 원본 JSON을 직접 읽는다.

## 절차

### 1. 대상 세션 확정

사용자가 세션을 지정하지 않았으면 **먼저 묻는다** (임의로 최신 세션을 고르지 않는다):

```bash
conda run -n boosttrack python tools/session_digest.py --list
```

목록을 표로 보여주고 — 세션 id·층·지속시간·트랙 수·SEI/EPFI/CBS·미개시 구역 수·
녹화(db) 유무 — 어느 세션을 쓸지 확인받는다. 후보가 하나뿐이면 그것으로 진행하되
어떤 세션인지 밝힌다.

### 2. 다이제스트 + 차트 생성

```bash
conda run -n boosttrack python tools/session_digest.py <session_id> \
  --out /tmp/.../digest.json          # 차트는 docs/reports/훈련평가/img/ 에 자동 저장
```

산출: 다이제스트 JSON(수 KB) + 차트 5종 PNG
(`<id>_idr.png`, `_epfi.png`, `_cbs.png`, `_sei.png`, `_timeline.png`).

`--site`/`--json-only` 옵션은 도구 `--help` 참조. 차트 렌더가 실패해도 다이제스트는
나오므로(`chart_error` 필드), 그 경우 차트 없이 서술하고 실패 사실을 레포트에 남긴다.

### 3. 신뢰도 게이트 — 해석 전에 판정

`reliability.verdict`를 먼저 본다.

| verdict | 뜻 | 대응 |
|---------|-----|------|
| `ok` | 플래그 없음 | 정상 해석 |
| `caution` | 맵 투영 실패 15~30% 또는 세션 30초 미만 | 해석하되 **§2에 한계를 명시**하고 결론 강도를 낮춘다 |
| `insufficient` | 투영 실패 30%+ 또는 트랙 10개 미만 | **지표 해석을 유보**한다. 레포트는 쓰되 "이 데이터로는 판단 불가"를 결론으로 하고 원인·재측정 조건을 제시 |

`cameras_observed`도 확인 — 등록됐는데 관측에 안 잡힌 카메라가 있으면 그 구역
지표는 과소평가된 것이므로 반드시 언급한다.

### 4. 4대 지표 해석

각 지표의 **방향**을 틀리지 않는다:

| 지표 | 단위 | 방향 | 없을 때 |
|------|------|------|---------|
| IDR | m/s (구역별) | 높을수록 = 반응이 빠르고 멀리 확산 | `not_started` = 미개시 |
| EPFI | 0~100 | 높을수록 좋음 | 경로 미배정 |
| CBS | 누적 적분 | **낮을수록 좋음**, 0 = 전 구간 임계 이하 | — |
| SEI | 0~100 | 높을수록 좋음 | `insufficient_data` |

해석에서 반드시 다룰 것:

- **IDR**: `not_started` 구역을 **가장 먼저** 서술한다. 참여율(`participant_ratio`)이
  0이면 "그 구역에 사람이 없었다"와 "있었는데 안 움직였다"가 구분되지 않으므로
  단정하지 말고 두 가능성을 제시한다. 다중 경보원이면 `idr_per_origin` 편차를 본다.
- **EPFI**: 평균만 쓰지 말고 **분포**(중앙값·사분위·최소)를 본다. 평균이 높아도
  하위 몇 명이 크게 이탈했으면 그게 발견이다. `worst` 목록의 이탈 거리
  (`mean/max_deviation_m`)를 `d_allow`와 대조한다.
- **CBS**: `risk_level`이 `high`인 병목을 우선한다. `timeline_surges`의
  `peak_at_sec`·`nonzero_sec`으로 **언제·얼마나 오래** 혼잡했는지 시점 서사를 만든다.
  CBS=0인 병목은 "문제 없음"이 아니라 "사람이 지나가지 않았을 수도" 있으므로
  통과량과 함께 본다.
- **SEI**: `unused_exits`(설계 분담이 있는데 통과 0명)가 있으면 **최우선 발견**이다.
  `max_abs_delta`로 쏠림 크기를 말하고, 설계 분담과의 차이를 %p로 쓴다.

### 5. 레포트 작성

[`TEMPLATE.md`](TEMPLATE.md)를 그대로 따른다. 저장 위치·파일명:

```
docs/reports/훈련평가/<YYYY-MM-DD>_<session_id>.md
docs/reports/훈련평가/img/<session_id>_*.png      (도구가 이미 생성)
```

날짜는 세션의 `alarm_ts` 기준(레포트 작성일이 아님). 이미지는 `![...](img/...)`
상대경로로 삽입한다.

작성 후 `docs/reports/훈련평가/README.md` 인덱스에 한 줄 추가한다.

### 6. 말투

- **명사형 종결(개조식)** — 기존 `docs/reports/` 컨벤션과 통일.
- 단정과 추정을 구분한다. 데이터가 말하는 것은 단정, 원인은 "~로 추정" / "~ 가능성".
- 수치에는 단위를 붙인다 (m/s, 초, %p, 명/㎡).
- 개선 권고는 **근거 지표를 명시**한다 ("b1 병목 CBS 5.75·초과 17초 → …").

## 참고: 세션 데이터 위치

```
data/sites/<site>/sessions/[<floor>/]<session_id>.json   지표 결과 (해석 입력)
data/sites/<site>/sessions/[<floor>/]<session_id>.db     raw 트랙 (재계산용)
```

`.db`가 있으면 임계값을 바꿔 재계산할 수 있다(`POST /api/session/{id}/replay`).
"임계값을 이렇게 바꾸면 어떻게 되나"라는 후속 질문이 나오면 이 경로를 안내한다.
