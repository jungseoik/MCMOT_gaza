# AI hub 리허설 — 시나리오별 출구 통과 측정 결과

측정일 2026-09-14 · 프로파일 `yolox_fastreid` · 분석 5fps · 층 `floor4`(AI hub 3층)
재구성은 **정밀**(저장 crop ReID 재임베딩 + 트랙 내부 분할 0.30 + 파편 기준 80).

각 시나리오를 `loop=false` 로 1주기만 녹화하고, 경보 시각을 영상 t=0(`alarm_at`)에
맞췄다(오차 0.000s). 반복 재생이 켜져 있으면 2주기 앞부분이 섞여 끝에 ID 가
쏟아진다 — 실측에서 사람 수가 10 → 11 로 부풀었다.

## 판정 기준

**출구 통과 합계가 10** 이면 정확. 출구별 분배는 시나리오마다 다르다(5+5 도 10 도 있다).
**전체 인원은 10명을 넘을 수 있다** — 대피 그룹 외의 사람이 다른 구역에 등장한다.
그래서 사람 수가 아니라 **게이트 통과 수**로 판정한다.

## 시나리오 09 — 측정 불가 (데이터 결손)

촬영 기록의 이동 경로:

```
A: 15 → 18 → 12 → 14 → 11(누락) → 10 → 05 → 09(누락) → 08
B: 15 → 18 → 12 → 14 → 07 → 04 → 05 → 09(누락) → 08
```

두 그룹 모두 마지막이 `→ 09 → 08` 인데 **cam09 가 해당 구간 배터리 소진으로
미촬영**이다. cam09 는 `exit-0` 의 `count_cam` 이므로 출구1 통과를 셀 수단이 없다.

cam12 는 이 시나리오에서 경로의 **세 번째 통과 지점**(15→18→**12**→14)이라
사람들이 문 앞 존을 지나지 않는다 — 관측 164 개 중 존 안 0 개. 정상 동작이다.

→ **설정으로 고칠 수 없다. 지표 검증 대상에서 제외한다.**
매니페스트에 `scenarios[].data_gaps: ["cam09","cam11"]` 로 남겼고,
⑤ 리허설 탭에서 시나리오를 고르면 경고로 표시된다.

## 시나리오 05 · 02 — 출구 미설정 (고칠 수 있음)

```
05: 16 → 17 → 10 → 11 → 12 → 13     ← 끝이 cam13
02: 03 → 01 → 02 → 04 → 05 → 06 → 14 → 07 → 12 → 13   ← 끝이 cam13
```

경로의 **끝이 cam13** 인데 출구 정의는 `exit-0`(cam09)·`exit-1`(cam12) 둘뿐이라
**cam13 에 출구가 없다**. cam12 가 문 앞에서 일부를 잡아 05 는 5, 02 는 9 가 나왔다.
② 맵 설정에서 cam13 구역에 출구를 추가하면 둘 다 개선될 것으로 본다(미검증).

## 시나리오 07 — 초과 +1

`exit-0` 은 10 으로 정확하다. `exit-1`(cam12)에서 존 안 관측이 0 인데도 1 건이
나왔는데, `ZoneGate` 가 발끝점뿐 아니라 **bbox 겹침 30%** 로도 안으로 판정하기
때문이다. 복도를 스쳐 가는 사람이 문틀에 걸쳐 한 번 세졌다.
줄이려면 `cam_zone` 을 문 안쪽으로 당기거나 `cam_zone_dwell` 을 2 → 4 로 올린다.

## 참고 — 왜 영역(ZoneGate)인가

같은 녹화(시나리오 01)에서 맵 통과선으로 바꿔 재보면:

```
① 화면 영역(현재)  out 10건 · {cam09: 10}                  ← 정확
② 맵 통과선        out 12건 · {cam05: 8, cam09: 3, cam08: 1}
```

맵 통과선은 맵 좌표계라 그 근처를 보는 **모든 카메라**가 각각 세서 중복된다.
게다가 문이 프레임 가장자리라 사람이 들어가며 화면에서 사라져 "선 반대편 관측"이
발생하지 않는다. `count_cam` + `cam_zone` 은 두 문제를 동시에 피한다.
