# 맨 서버 부트스트랩 — 순정 우분투에서 전 기능 재현

> **대상**: "**NVIDIA 드라이버만 깔린 순정 Ubuntu 서버**"에 이 레포를 clone해서
> 전 기능(① 모델 추론 · ② RTSP 송출 · ③ 자체 평가(4대 지표) · ④ CAD 추출/편집)을
> 처음부터 올리는 담당자/에이전트.
>
> **이 문서 = "0단계: 시스템 준비" 체크리스트.** 아래 apt/curl 명령을 위에서부터 복붙하면
> 시스템 레벨 의존이 전부 갖춰진다. 그 다음 코드·환경·대용량 자산을 붙인다.
>
> - **GPU 아키텍처가 바뀌면** TRT 엔진 재빌드·한계 재측정이 추가로 필요하다
>   → [이관가이드-다른-GPU-서버로.md](이관가이드-다른-GPU-서버로.md) (이 문서는 그 §0 "시스템 준비"를 채운다).
> - 검증 기준 환경(이 문서 작성 서버): **Ubuntu 24.04.4 · 드라이버 580.173.02 / CUDA 13.0 ·
>   Docker 29.1 · nvidia-container-toolkit 1.19 · ffmpeg 6.1 · node 24 / pm2 7 · conda 26.**

## 전제 (이것만 있으면 시작)

- Ubuntu 22.04 / 24.04 (x86_64)
- **NVIDIA GPU 드라이버 설치 완료** — `nvidia-smi`가 동작하고 `CUDA Version`이 보일 것.
  (드라이버 자체 설치는 이 문서 범위 밖. CUDA **툴킷**은 호스트에 따로 안 깔아도 된다 — 아래 참조.)
- 인터넷 접근(apt·pip·docker pull·HuggingFace). 오프라인이면 각 절의 "오프라인" 주석 참조.
- sudo 권한.

```bash
nvidia-smi   # 드라이버·CUDA 버전 확인. 안 나오면 여기서 멈추고 드라이버부터.
```

## 기능별 필수 시스템 의존성 (무엇이 왜 필요한가)

| 시스템 의존 | ① 추론(단일/webui) | ② RTSP 송출 | ③ 자체평가(멀티카메라 :8900) | ④ CAD 추출/편집 | 비고 |
|-------------|:---:|:---:|:---:|:---:|------|
| **NVIDIA 드라이버** | ✅ | – | ✅ | – | 전제(직접 설치). CUDA 13 지원 드라이버 |
| **conda + env `boosttrack`** | ✅ | (hf CLI만) | ✅ | ✅(렌더 py) | Python 3.12. `requirements.txt`+`install_yolox.sh` |
| **CUDA 런타임 / TRT** | ✅ | – | ✅ | – | **호스트 툴킷 불필요** — pip `torch+cu130`·`tensorrt-cu12`가 런타임 반입. DS는 컨테이너가 제공 |
| **docker + nvidia-container-toolkit** | – | ✅(mediamtx) | ✅(DeepStream 백엔드) | – | ffmpeg 인제스트 모드면 DS 컨테이너 불필요하나 mediamtx엔 docker 필요 |
| **ffmpeg / ffprobe** | ✅(webui 스냅샷·인코딩) | ✅ | ✅(ffmpeg 인제스트·스냅샷) | – | 시스템 패키지 |
| **node + pm2** | – | ✅(송출 프로세스) | ✅(서버 상시 기동) | – | pm2로 mediamtx 송출·:8900 관리 |
| **CAD 스택**(ezdxf·matplotlib·CJK폰트·xvfb·libredwg/ODA) | – | – | (도면 시드는 커밋됨) | ✅ | `tools/setup_cad_convert.sh`가 일괄 |
| **hf CLI**(huggingface_hub) | ✅(가중치) | ✅(테스트영상) | ✅ | ✅(CAD 원본) | env `boosttrack`에 포함(`requirements.txt`) |

> **핵심**: 호스트엔 **드라이버만** 있으면 된다. CUDA 툴킷/cuDNN/TensorRT는
> ① pip 휠(`torch==2.9.0+cu130`, `tensorrt-cu12<11`)이, ③의 DeepStream 경로는
> **컨테이너 이미지**(`nvcr.io/nvidia/deepstream:9.0`)가 반입한다.

## 0단계: 시스템 준비 (복붙)

### 0-1. 기본 apt 패키지 (ffmpeg 포함)

```bash
sudo apt-get update
sudo apt-get install -y \
  ffmpeg \
  git curl wget ca-certificates gnupg build-essential
ffmpeg -version | head -1 && ffprobe -version | head -1   # 확인
```
> ②·③ 공통. Ubuntu 기본 ffmpeg(6.x)로 충분(WebRTC 호환 인코딩·스냅샷·NVDEC 디코드).

### 0-2. Miniconda + env `boosttrack` (①③④ 파이썬)

```bash
# Miniconda 설치(이미 conda 있으면 생략)
if ! command -v conda >/dev/null; then
  curl -fsSL https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh -o /tmp/mc.sh
  bash /tmp/mc.sh -b -p "$HOME/miniconda3"
  eval "$("$HOME/miniconda3/bin/conda" shell.bash hook)"
  conda init bash    # 새 셸부터 conda 활성화
fi

# ⚠️ 신규 Miniconda 필수: 채널 ToS 동의 안 하면 conda create가 CondaToSNonInteractiveError로
#    막힌다(2024~ Anaconda 정책, 순정 서버 실측). 아래 2줄 먼저.
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r

# 프로젝트 환경 (레포 루트에서)
conda create -n boosttrack python=3.12 -y
conda activate boosttrack
pip install -r requirements.txt      # torch cu130·tensorrt·hf·fastapi·uvicorn·ezdxf 등
                                     # (:8900 자체평가·:8910 편집기 서버 의존 전부 포함)
bash install_yolox.sh                 # yolox는 torch 빌드의존이라 별도
pip install -r webui/requirements.txt # (선택) ① 단일채널 webui :8000 전용 — ③/④엔 불필요
```
> `requirements.txt`의 `--extra-index-url .../cu130`이 CUDA13용 torch를 가져온다.
> 드라이버가 CUDA13 미지원이면 [이관가이드 §1](이관가이드-다른-GPU-서버로.md)대로 버전을 낮춘다.

### 0-3. Docker + NVIDIA Container Toolkit (②의 mediamtx, ③의 DeepStream)

```bash
# --- Docker Engine ---
if ! command -v docker >/dev/null; then
  curl -fsSL https://get.docker.com | sudo sh
fi
sudo usermod -aG docker "$USER"       # 로그아웃/로그인 후 sudo 없이 docker 사용
                                       # (또는 현재 셸에서: newgrp docker)

# --- NVIDIA Container Toolkit (GPU를 컨테이너에서 쓰기) ---
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey \
  | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -fsSL https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list \
  | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' \
  | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker

# 확인: 컨테이너에서 GPU 인식
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi | head -12
```
> ③의 DeepStream 백엔드(`INGEST_BACKEND=deepstream`)만 이 toolkit이 필수. 기본 ffmpeg
> 인제스트로만 쓰면 toolkit은 불필요하지만, ② mediamtx 컨테이너엔 docker 자체가 필요하다.

### 0-4. Node.js + pm2 (②③ 프로세스 관리)

```bash
if ! command -v node >/dev/null; then
  curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
  sudo apt-get install -y nodejs
fi
sudo npm i -g pm2 && pm2 -v
```

### 0-5. CAD 변환 스택 (④ 도면 추출/편집)

```bash
# libredwg(OSS, dwg2dxf) + ezdxf/matplotlib + CJK폰트 + xvfb 를 한 번에.
PYTHON="$HOME/miniconda3/envs/boosttrack/bin/python" bash tools/setup_cad_convert.sh
```
- 이 스크립트가 커버: ezdxf·matplotlib, `fonts-noto-cjk`, `xvfb`+xcb 라이브러리, libredwg
  빌드/설치(+빌드 의존 `python3`·`libpcre2-dev`), opencv 런타임 `libgl1`·`libglib2.0-0`
  (CAD 렌더·도면 편집기의 cv2 import — 순정 서버엔 없어 필수).
- **ODA File Converter(선택, 정합도 최상)** 는 프리웨어지만 EULA상 재배포 금지라 **자동설치 불가** →
  아래 "남은 수동 단계" 참조. OSS libredwg만으로도 DWG→DXF는 된다.
- CAD 원본(dwg/dxf)은 git 제외 → **2단계**에서 `fetch_assets.sh --cad`로 받는다.

## 1단계: 코드 (이미 clone 했다면 생략)

```bash
git clone <repo> && cd MCMOT_gaza
git checkout feature/deepstream-ingest   # 또는 병합된 브랜치
```

## 2단계: 대용량 자산 내려받기 (git 미포함분)

```bash
conda activate boosttrack       # hf CLI 필요(requirements.txt에 포함)

# 가중치(공개) + ONNX + CAD 원본을 알맞은 경로로 (멱등)
export HF_TOKEN=hf_xxxxxxxx      # backseollgi/MCMOT가 비공개인 동안 필요. 커밋 금지!
bash tools/fetch_assets.sh
```
받는 것 · 경로: [tools/fetch_assets.sh](../tools/fetch_assets.sh) 상단 주석 / `backseollgi/MCMOT` README.
- 가중치(`external/weights/*.tar,*.pth`)는 **공개**라 토큰 없이도 되고, 추론코드가
  `import assets` 할 때 자동으로도 받아진다.
- **ONNX**(`external/weights/trt/*.onnx`)와 **CAD 원본**(`cad/*.dwg,*.dxf`)은 `backseollgi/MCMOT`에
  있고 이 스크립트로만 확보된다(원본 서버 복사도 가능).
- **TRT `.engine`은 안 받는다** — GPU 아키텍처·TRT 버전 결합이라 **재빌드가 정답**(다음 단계).
- **RTSP 테스트 영상은 `fetch_assets.sh`에 없다**(역할 분리) — `backseollgi/MCMOT`(model)의
  `videos/` 12개 영상은 다운로드+송출까지 하는 `tools/rtsp/setup_rtsp_streams.sh` 소관이다
  (`--all`로 12개 전부, 기본 3채널). MCMOT가 비공개라 여기도 `HF_TOKEN` 필요.
  상세: [RTSP-송출서버-구성.md](RTSP-송출서버-구성.md).

## 3단계: TRT 엔진 빌드 (①③ 최초 1회 · GPU 종속)

```bash
# (a) 호스트 conda 엔진 → external/weights/trt/  (단일영상/webui)
CUDA_VISIBLE_DEVICES=<빈GPU> conda run -n boosttrack python -m src.build_trt --fp16

# (b) DeepStream 컨테이너 엔진 → external/weights/trt_ds/  (멀티카메라 deepstream 백엔드)
docker build -t macs-deepstream:9.0 system/ingest_ds/docker
#  이후 trtexec 빌드 커맨드는 system/ingest_ds/README.md "엔진 빌드 가이드" 참조
```
상세·복붙: [이관가이드 §2-4](이관가이드-다른-GPU-서버로.md) · [system/ingest_ds/README.md](../system/ingest_ds/README.md).

## 기능별 실행 + 최종 재현 판정

| 기능 | 실행 | 필요 선행(0~3단계) | 문서만으로 재현? |
|------|------|-------------------|:---:|
| **① 단일영상 추론(CLI)** | `python -m src -i in.mp4 -o out.mp4` (또는 `src.inference_gpu`) | 0-1,0-2 · 2단계(가중치) · 3(a) TRT | ✅ OK |
| **① 단일채널 webui :8000** | `python -m webui` | +`webui/requirements.txt`. Depth 자동모드는 별도 da3 env(선택) | ✅ OK (Depth는 선택) |
| **② RTSP 송출** | `bash tools/rtsp/setup_rtsp_streams.sh` | 0-1(ffmpeg),0-3(docker),0-4(pm2) · hf CLI | ✅ OK |
| **③ 멀티카메라 :8900 (ffmpeg 인제스트)** | `pm2 start tools/run_system_server.sh --name macs-system` | 0-1~0-4 · 2단계 · 3(a). 시드(17F/19F)는 커밋됨 | ✅ OK |
| **③ DeepStream 인제스트** | `INGEST_BACKEND=deepstream ... pm2 restart macs-system --update-env` | +0-3 toolkit · 3(b) DS 이미지·엔진 | ✅ OK (재빌드 필요) |
| **③ 4대 지표 세션** | 운영뷰 🔔 경보 시작 → 종료 시 산출 | ③ 기동 + RTSP 소스(②) | ✅ OK |
| **④ CAD DWG→DXF→PNG** | `python tools/cad_convert.py ...` (또는 `cad-convert` 스킬) | 0-5 · 2단계(`--cad`) | ✅ OK (libredwg). ODA는 수동(아래) |
| **④ 도면 편집기 :8910 / 최단경로** | `cd cad/CAD_API_Based_Optimal_Evacuation_Route_Algorithm && pm2 start "$(...python...) -m uvicorn evac.web:app --host 0.0.0.0 --port 8910" --name evac-editor` (아래 ④ 기동 블록) | 0-1·0-2·0-5 · **별도 서비스로 기동해야** ③ 맵설정의 [CAD 도면에서 만들기]가 연결됨 | ✅ OK |

> **파이썬 의존성 주의**: `③ :8900`·`④ :8910`은 **FastAPI 서버**라 `fastapi·uvicorn·python-multipart`가
> 필요하다 — 이제 **core `requirements.txt`에 포함**(0-2단계에서 설치됨). 별도 `webui/requirements.txt`는
> `① :8000` 단일채널 webui 전용(선택)이다.

### ④ 도면 편집기(:8910) 기동
:8900과 **별개 서비스**다. 안 띄우면 :8900 맵설정의 [CAD 도면에서 만들기](새 창 :8910)가 연결 거부된다.
```bash
PY="$HOME/miniconda3/envs/boosttrack/bin/python"   # 또는 활성 venv의 python
cd cad/CAD_API_Based_Optimal_Evacuation_Route_Algorithm
pm2 start "$PY -m uvicorn evac.web:app --host 0.0.0.0 --port 8910" --name evac-editor
# 수동: 위 cd 후  $PY -m uvicorn evac.web:app --host 0.0.0.0 --port 8910
```
- 의존: fastapi·uvicorn·numpy·scipy·opencv·ezdxf·matplotlib(전부 core `requirements.txt`) + libredwg(0-5).
- DWG 변환은 ODA 없으면 libredwg 자동 폴백(0-5) — 순정 서버에서 그대로 동작(도커 실측).

**결론: 순정 우분투에서 `clone → 0단계(복붙) → fetch_assets → 기능별 실행`이 문서만으로 전 기능
재현 가능.** 단 아래 두 가지는 성격상 수동/자동화 불가.

## 남은 수동 단계 (자동화 불가분 — 명확히)

1. **NVIDIA 드라이버 설치** — 이 문서의 전제. 하드웨어·커널 종속이라 여기서 다루지 않음.
2. **ODA File Converter (선택)** — Open Design Alliance 프리웨어지만 **EULA상 재배포 금지**라
   레포/HF에 담을 수 없다. 최신·복잡 DWG의 정합도가 필요할 때만:
   - https://www.opendesign.com/guestfiles/oda_file_converter 에서 Linux `.deb`(QT6 x64) 수동 다운로드(EULA 동의).
   - `ODA_DEB=/받은/경로.deb bash tools/setup_cad_convert.sh` 로 설치.
   - **OSS libredwg만으로도 DWG→DXF는 동작**하므로 대부분 불필요.
3. **TRT 엔진 재빌드** — 자동화는 돼 있으나(3단계) **대상 GPU에서 실행**해야 하는 GPU-종속 단계다.
   아키텍처가 원본(Blackwell)과 다르면 [이관가이드 §2-6](이관가이드-다른-GPU-서버로.md) 한계 재측정도.
4. **HF_TOKEN** — `backseollgi/MCMOT`(ONNX·CAD·RTSP 영상)가 **비공개**인 동안 2단계와
   RTSP 재현(`setup_rtsp_streams.sh`)에 토큰 필요. 공개로 전환하면 토큰 없이 재현 가능
   (가중치 2개는 별도 공개 레포라 이미 토큰 불필요).
