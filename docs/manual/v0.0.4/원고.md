# 1. 문서 개요

## 1.1 목적

이 문서는 다중 CCTV 영상에서 재실자의 이동을 추적하고, 건물 평면도 좌표로 변환하여
피난훈련을 정량적으로 평가하는 시스템의 사용 절차를 설명합니다.

시스템은 경보 발생 이후의 피난 행동을 네 가지 정량지표로 산출합니다.

| 지표 | 명칭 | 평가 대상 |
| IDR | 피난 반응 확산 지표 | 구역별로 얼마나 빨리 피난을 개시했는가 |
| EPFI | 경로 충실도 지표 | 권장 피난경로를 얼마나 충실히 따랐는가 |
| CBS | 병목 혼잡 누적 지표 | 병목 구역에 혼잡이 얼마나 누적되었는가 |
| SEI | 비상구 활용 효율 지표 | 비상구가 설계 의도대로 분산 사용되었는가 |

## 1.2 적용 범위

본 문서는 다음 두 개 화면의 사용 절차를 다룹니다. 실제 사용 순서와 동일하게
도면 준비를 먼저 설명하고, 이어서 운영 화면을 설명합니다.

| 구분 | 접속 주소 | 역할 |
| 도면 편집기 | http://<서버주소>:8910 | CAD 도면을 평면도 이미지로 변환하고 비상구·피난경로를 검증 |
| 멀티카메라 시스템 | http://<서버주소>:8900 | 공간 요소 설정, 카메라 매핑, 실시간 운영, 평가 세션 |

본 문서의 화면 예시는 기본 제공되는 **17F·16F·지상1층** 세 개 층으로 구성된
사이트를 사용합니다. 대부분의 절차는 **17F 평면도**로 설명하며, 여러 층을 함께 다루는
건물 훈련(7.5)에서 16F를 함께 사용합니다.

## 1.3 용어

| 용어 | 설명 |
| 세션 | 경보 시작부터 종료까지의 평가 단위. 이 구간에서만 지표가 산출됩니다 |
| 건물 훈련 | 여러 층에서 **하나의 공유 경보 시각**으로 동시에 진행하는 세션. 층별 결과를 건물 단위로 합산합니다 (7.5) |
| 구역 | IDR 산출 단위가 되는 평면도상의 다각형 영역 |
| 병목 | CBS 산출 대상이 되는 혼잡 우려 영역 |
| 통과선 | 비상구 통과 인원을 계수하기 위해 지정하는 가상의 선 |
| 경보 발생원 | IDR 거리 계산의 기준점. 경보가 실제 발생한 위치 |
| 대응점 | 카메라 화면의 한 점과 평면도의 같은 지점을 짝지은 좌표쌍 |
| 호모그래피 | 대응점으로부터 산출되는, 카메라 좌표를 평면도 좌표로 바꾸는 변환 행렬 |
| 유효 ROI | 카메라 화면에서 분석에 사용할 영역. 이 밖의 검출은 제외됩니다 |

# 2. 시스템 구성

## 2.1 처리 흐름

시스템은 다음 순서로 동작합니다.

@flow
CCTV(RTSP) → GPU 디코딩 → 사람 검출·추적 → 평면도 좌표 변환
→ 구역·병목·비상구 이벤트 판정 → 4대 지표 산출 → 화면 표시 및 저장
@end

카메라별로 추적된 사람의 발 위치를 호모그래피로 평면도 좌표로 옮긴 뒤,
그 좌표가 어느 구역에 있는지, 권장 경로에서 얼마나 벗어났는지, 병목을 지났는지,
어느 비상구를 통과했는지를 판정하여 지표를 계산합니다.

## 2.2 사용 순서

@steps
① 도면 준비 — CAD 도면에서 평면도 이미지를 만들고 비상구를 지정합니다 (:8910)
② 맵 설정 — 축척을 정하고 구역·병목·비상구·피난경로를 그립니다 (:8900 ① 탭)
③ 카메라 등록·매핑 — 카메라를 등록하고 평면도와 좌표를 맞춥니다 (:8900 ② 탭)
④ 운영 — 실시간 화면을 확인하고 훈련 시 평가 세션(또는 건물 훈련)을 진행합니다 (:8900 ③ 탭)
⑤ 결과 확인 — 세션을 재생하고 필요 시 임계값을 바꿔 다시 계산합니다 (:8900 ④ 탭)
@end

①과 ②는 현장 최초 구축 시 한 번만 수행하며, 이후 훈련에서는 ④부터 시작합니다.

# 3. 도면 준비

CAD 도면(DWG/DXF)에서 평면도 이미지를 만들고, 비상구 위치와 피난경로가
올바른지 검증하는 단계입니다. 이미 평면도 이미지가 준비되어 있다면 이 장을 건너뛰고
4장으로 진행하십시오.

## 3.1 편집기 접속

브라우저에서 `http://<서버주소>:8910` 에 접속합니다.

@img 01_editor_start.png
도면 편집기 초기 화면
@end

화면 상단에 작업 단계가 표시됩니다. 왼쪽부터 순서대로 진행합니다.

@steps
① 업로드 → ② 정리 → ③ Exit → ④ 검증 → ⑤ 적용
@end

오른쪽 패널에 모드(도구), 편집 요소 목록, 도면 단위, 검증, 적용 영역이 위에서
아래 순서로 배치되어 있습니다.

## 3.2 도면 업로드

화면 가운데 점선 영역에 DWG 또는 DXF 파일을 끌어다 놓거나, **파일 선택** 버튼으로
파일을 지정합니다.

@note
PDF 도면은 직접 업로드할 수 없습니다. AutoCAD에서 PDF Import를 실행한 뒤
DWG로 저장하여 업로드하십시오.
@end

## 3.3 도면 단위

업로드하면 오른쪽 **도면 단위** 영역에 도면에 기록된 단위(예: mm, m)가 자동으로
인식되어 표시됩니다. 단위가 없는 도면은 **단위 선택** 목록에서 직접 지정하거나,
**실측 2점으로 지정**으로 실제 길이를 아는 두 점을 찍어 축척을 부여합니다.

@note
단위가 잘못되면 이후 모든 거리·밀도 계산이 어긋납니다. 도면 단위가 자동 인식되지
않은 경우 반드시 직접 지정한 뒤 다음 단계로 넘어가십시오.
@end

## 3.4 도면 정리

업로드된 도면에는 치수선, 주석, 범례 등 분석에 불필요한 요소가 포함되어 있습니다.
오른쪽 **모드** 영역에서 도구를 선택하여 정리합니다.

@img 06_editor_del.png
요소 삭제 도구 선택 상태
@end

| 도구 | 조작 | 용도 |
| 이동/줌 | 휠·드래그 | 도면을 확대하거나 이동합니다 |
| 삭제 (치수선 등) | 박스 드래그 | 선택 영역의 요소를 지웁니다 |
| 개구부 풀기 | 선 그리기 | 닫힌 것으로 인식된 문을 통행 가능하게 만듭니다 |
| 공간 차단 | 선/사각형 | 통행 불가 영역(설비실·계단 밖 등)을 막습니다 |
| Exit 지정 | 선 그리기 | 비상구 위치를 지정합니다 |
| 출발점 지정 | 클릭 | 피난 시작 지점을 지정합니다 (3.6) |

그린 요소는 오른쪽 **편집 요소** 목록에 쌓이며, 목록의 🗑 아이콘으로 하나씩
개별 삭제할 수 있습니다. 잘못 조작한 경우 **실행취소**(Ctrl+Z)로도 되돌립니다.

@note
**개구부 처리를 빠뜨리지 마십시오.** CAD 도면에서 문은 대개 닫힌 선으로 그려져
있어, 그대로 두면 통행이 불가능한 벽으로 인식됩니다. 이 상태에서는 피난경로가
실제와 다르게 산출됩니다. 오른쪽 **보기 → 연결성 오버레이**를 켜면 연결된 공간은
초록, 고립된 공간은 주황으로 표시되므로 개구부 누락을 확인할 수 있습니다.
@end

## 3.5 Exit 지정

**Exit 지정** 도구를 선택하고 비상구 위치에 선을 그립니다.

@img 05_editor_exit.png
Exit 지정 도구
@end

여기서 지정한 비상구는 이후 경로 검증의 도착점이 됩니다.

## 3.6 출발점 지정과 경로 검증

오른쪽 **검증** 영역에서 피난경로가 올바르게 산출되는지 확인합니다.

@img 07_editor_verify.png
경로 검증 및 열지도
@end

| 항목 | 기본값 | 설명 |
| 기준거리(m) | 30 | 이 거리를 넘는 지점을 문제 구간으로 표시합니다 |
| worst | 5 | 가장 불리한 경로를 몇 개까지 표시할지 지정합니다 |
| 출발점 | 자동(가장 먼 곳) | 경로 산출의 시작 지점. **출발점 지정** 도구로 직접 찍거나 자동 선택 |
| 경로 표시 | 사용 | 산출된 피난경로를 도면 위에 그립니다 |
| 거리 열지도 | 미사용 | 모든 지점에서 가장 가까운 비상구까지의 거리를 색으로 표시합니다 |

출발점은 기본적으로 비상구에서 가장 먼 지점이 자동 선택됩니다. 특정 위치를
기준으로 검증하려면 **출발점 지정** 도구로 직접 클릭하십시오. 통행 불가 지점을
찍으면 인접한 통행 가능 지점으로 보정되며, 보정 사유가 함께 표시됩니다.

**경로 검증 (worst-N)** 을 누르면 가장 불리한 경로가 표시됩니다. 경로가 벽을
통과하거나 비정상적으로 우회한다면 3.4의 개구부 처리가 누락된 것이므로
도면 정리로 돌아가 보완하십시오.

## 3.7 적용

검증이 끝나면 오른쪽 **적용** 영역에서 대상 사이트와 **교체할 층**을 고르고
**저장 & 적용**을 누릅니다. 새 층으로 추가하려면 **새 층**을 사용합니다.

@note
저장과 운영 반영은 한 번에 이루어집니다. **교체할 층**에 선택된 층의 기존 도면이
이 도면으로 대체되며, 그 층에 매핑된 카메라 수가 안내로 표시됩니다. 기존에 설정해
둔 구역·병목·비상구 위치가 새 도면 기준으로 어긋날 수 있으므로, **운영·평가 세션
진행 중에는 적용하지 마십시오.**
@end

@end

# 5. 맵 설정

평면도에 축척을 부여하고, 지표 산출의 기준이 되는 공간 요소를 그리는 단계입니다.

## 5.1 화면 구성

@img 11_map_overview.png
① 맵 설정 화면 전체
@end

화면은 세 부분으로 구성됩니다.

| 영역 | 위치 | 내용 |
| 도구 막대 | 상단 | 맵 업로드, 드로잉 도구, 격자·스냅 설정, 미터 격자 표시 |
| 도면 | 가운데 | 평면도와 그려진 요소. 휠로 확대, 드래그로 이동. 축·스케일바·미터 격자 표시 |
| 사이트 설정 | 오른쪽 | 층 관리, 축척, 요소 목록, 임계값. 아래에 [Reset]·[사이트 저장] |

오른쪽 패널은 세 개의 탭으로 나뉩니다.

| 탭 | 내용 |
| 설정 | 층·축척·요소 목록·판정 임계값 (기본 표시) |
| 지표 설명 | 4대 지표가 어떤 요소로 어떻게 산출되는지 |
| 추론 모델 | 영상 분석에 사용할 검출·ReID 모델 선택 (5.10 참조) |

예시 도면에는 기본 설정이 이미 적용되어 있습니다. 오른쪽 목록에서
피난경로 2개, 구역 3개, 병목 2개, 출입구 2개를 확인할 수 있습니다. 도면에는
가로·세로 축(m), 스케일바(10 m), 미터 격자가 함께 표시되어 위치를 실측 단위로
가늠할 수 있습니다.

@note
오른쪽 아래 **↺ Reset**은 사이트를 기본 제공 설정(seed)으로 되돌립니다.
설정을 시험하다 처음 상태로 복원할 때 사용하며, 저장된 세션 기록은 보존됩니다.
되돌리면 현재 편집 중인 구역·경로·카메라 설정이 기본값으로 바뀌므로 주의하십시오.
@end

## 5.2 층 선택

건물의 여러 층을 각각 별도의 도면으로 관리합니다.

@img 12_floor_select.png
층 선택
@end

화면 오른쪽 위 **층** 선택 상자에서 대상 층을 고릅니다. 예시에는 17F, 16F,
지상1층 세 개 층이 등록되어 있습니다. 구역·병목·비상구·피난경로와 4대 지표는
모두 층별로 따로 관리됩니다.

@note
층을 넘나드는 동일인 연결(계단·엘리베이터 이동)은 현재 버전에서 지원하지 않습니다.
각 층은 독립된 좌표계로 처리됩니다. 여러 층을 하나의 훈련으로 함께 평가하려면
7.5의 건물 훈련을 사용합니다.
@end

## 5.3 축척 지정

거리와 밀도를 미터 단위로 계산하려면 축척이 필요합니다.

@img 13_scale.png
축척 2점 도구
@end

@steps
1. 도구 막대에서 **축척 2점**을 선택합니다.
2. 도면에서 실제 길이를 아는 두 지점을 차례로 클릭합니다.
3. **실거리** 입력란에 두 지점 사이의 실제 거리를 미터 단위로 입력합니다.
4. **완료**를 누릅니다.
@end

오른쪽 **맵 · 축척** 영역에 현재 축척과 그 **출처**가 표시됩니다. CAD 도면에서
만든 맵은 도면 단위로부터 축척이 자동으로 정해지며(예: "CAD 자동"), 축척 2점으로
직접 지정하면 그 값이 우선합니다. 예시 도면은 73.2 m 기준으로 0.02391 m/px가
"직접 지정한 2점"으로 표시되어 있습니다.

@note
CAD 자동 축척이 이미 잡혀 있는 도면에 축척 2점을 다시 지정하면 자동값을
덮어쓴다는 확인이 표시됩니다. 도면 단위가 정확하다면 굳이 덮어쓰지 마십시오.
축척을 지정하지 않으면 이동속도·구역 밀도·경보원까지의 거리를 미터 단위로
산출할 수 없습니다.
@end

## 5.4 구역 지정 (IDR)

구역은 피난 개시 시점을 판정하는 단위입니다.

@img 14_zone.png
구역 드로잉 도구
@end

@steps
1. 도구 막대에서 **구역 IDR**을 선택합니다.
2. 도면에서 구역 경계를 따라 클릭하여 다각형을 그립니다.
3. **이름** 입력란에 구역 이름을 입력합니다.
4. **완료**를 누릅니다.
@end

예시 도면에는 z3, z4, z5 세 개 구역이 지정되어 있습니다. 오른쪽 **구역** 목록에서
각 구역의 꼭짓점 수를 확인할 수 있으며, 휴지통 아이콘으로 삭제합니다.

구역은 사람이 머무는 공간 단위로 나눕니다. 사무실, 회의실, 복도처럼 피난 개시
시점이 서로 다를 것으로 예상되는 공간을 각각 하나의 구역으로 지정하십시오.

## 5.5 병목 지정 (CBS)

병목은 혼잡이 누적되는지 감시할 영역입니다.

@img 15_bottleneck.png
병목 드로잉 도구
@end

@steps
1. 도구 막대에서 **병목 CBS**를 선택합니다.
2. 도면에서 병목 구간의 경계를 따라 다각형을 그립니다.
3. **임계밀도** 입력란에 기준 밀도를 명/㎡ 단위로 입력합니다.
4. **완료**를 누릅니다.
@end

예시에는 b1, b2 두 개 병목이 지정되어 있으며, 임계밀도는 각각 0.1 명/㎡,
가중치는 1로 설정되어 있습니다. 오른쪽 **병목** 목록에서 값을 직접 수정할 수 있습니다.

| 항목 | 의미 |
| ρcrit | 이 밀도를 넘는 동안만 CBS에 누적됩니다 |
| w | 병목의 중요도. 값이 클수록 같은 혼잡도라도 CBS가 크게 산출됩니다 |

계단 입구, 복도 합류점, 출입문 앞처럼 사람이 몰릴 것으로 예상되는 지점을
병목으로 지정하십시오.

## 5.6 출입구 지정 (SEI)

비상구 통과 인원을 계수할 통과선을 지정합니다.

@img 16_exit.png
출입구 드로잉 도구
@end

@steps
1. 도구 막대에서 **출입구 SEI**를 선택합니다.
2. 비상구를 가로지르는 선을 그립니다. 통과 방향과 직각이 되도록 그립니다.
3. 설계 총인원을 입력합니다.
4. **완료**를 누릅니다.
@end

예시에는 e1(설계 32명), e3(설계 30명) 두 개 비상구가 지정되어 있습니다.

@note
**설계 총인원은 SEI 산출의 기준값입니다.** 이 값은 소방 설계 도서에 명시된
비상구별 수용 인원을 입력해야 합니다. 임의로 입력하면 SEI가 실제 설계 의도와
무관한 값이 됩니다.
@end

## 5.7 피난경로 지정 (EPFI)

권장 피난경로를 선으로 그립니다. 각 사람이 이 경로에서 얼마나 벗어났는지가
EPFI로 산출됩니다.

@img 17_route.png
피난경로 드로잉 도구
@end

@steps
1. 도구 막대에서 **피난경로 EPFI**를 선택합니다.
2. 경로를 따라 여러 지점을 차례로 클릭합니다.
3. **완료**를 누릅니다.
@end

예시에는 r1, r2 두 개 경로가 지정되어 있습니다.

@note
경로는 실제 사람이 걷는 동선의 중심을 지나야 합니다. 경로가 실제 동선과
평행하게 어긋나 있으면 모든 대상자의 EPFI가 일정하게 낮아집니다.
@end

## 5.8 공간 그래프 (IDR 보조)

경보 발생 위치에서 각 구역까지의 거리를 계산할 때 사용하는 노드 그래프입니다.

## 5.10 추론 모델

오른쪽 패널의 **추론 모델** 탭에서 영상 분석에 사용할 모델 조합을 선택합니다.
검출기(사람을 찾는 모델)와 ReID(같은 사람인지 판별하는 모델)가 한 벌로 묶여
있으며, 목록에서 클릭하면 전환됩니다.

@img 20b_model.png
추론 모델 선택
@end

| 조합 | 구성 | 특징 |

출입구 설정과 저장된 세션 기록은 그대로 유지되며, 재기동 구간 동안 추적이 잠시

**평가 세션이 진행 중이면 전환되지 않습니다.** 한 세션 안에서 앞 구간과 뒤 구간이

전환하십시오.

bash tools/fetch_assets.sh --onnx
bash tools/build_profile_engines.sh --ds
@end

# 6. 카메라 등록 및 매핑

카메라를 등록하고, 카메라 화면의 좌표를 평면도 좌표로 바꾸는 대응 관계를
설정하는 단계입니다.

## 6.1 화면 구성

@img 21_cams_overview.png
② 카메라 등록·매핑 화면 전체
@end

왼쪽에 카메라 목록, 가운데에 카메라 프레임, 오른쪽에 평면도가 표시됩니다.

@img 22_cam_list.png
카메라 목록
@end

각 카메라 항목에는 다음 정보가 표시됩니다.

| 표시 | 의미 |
| 매핑 ✓ / 매핑 필요 | 대응점 지정 여부. 매핑되지 않은 카메라는 지표 산출에서 제외됩니다 |
| 활성 / 비활성 | 분석 대상 여부 |
| 층 | 이 카메라가 매핑된 도면 |
| 검출 신뢰도 | 카메라별 최소 검출 신뢰도. 비워 두면 사이트 기본값을 따릅니다 |

## 6.2 카메라 한 대 등록

@steps
1. 왼쪽 아래 **카메라 추가** 영역에 이름과 RTSP 주소를 입력합니다.
2. 매핑할 층을 선택합니다.
3. **+ 추가 후 연결 테스트**를 누릅니다.
@end

등록과 동시에 연결을 확인하고 첫 프레임을 가져옵니다. 연결에 실패하면 주소와
계정 정보를 확인하십시오.

## 6.3 여러 대 일괄 등록

현장 카메라가 여러 대인 경우 한 대씩 추가하지 말고 일괄 등록 기능을 사용하십시오.

@note
한 대씩 추가할 때마다 분석 작업이 재시작되며, 같은 GPU에 배정된 다른 카메라의
영상이 약 8초간 끊깁니다. 40대를 한 대씩 등록하면 약 9분 30초가 소요되고
그동안 40회 끊김이 발생합니다. 일괄 등록은 이 과정을 한 번으로 줄입니다.
@end

@steps
1. 카메라 목록 아래 **여러 대 한 번에 등록**을 누릅니다.
2. 주소를 한 줄에 한 대씩 붙여 넣습니다.
3. **목록으로 변환**을 누릅니다.
4. 표에서 이름을 수정하거나 불필요한 행을 제외합니다.
5. **연결 테스트**로 접속 가능 여부를 확인합니다.
6. 매핑 층을 선택하고 **등록**을 누릅니다.
@end

@img 23_bulk_paste.png
주소 붙여넣기
@end

입력 형식은 `이름,RTSP주소` 또는 `RTSP주소`만 입력합니다. 빈 줄과 `#`으로 시작하는
줄은 무시됩니다.

@img 24_bulk_table.png
목록 변환 후 확인 화면
@end

**연결 테스트**는 등록 전에 각 주소의 접속 가능 여부와 해상도를 확인합니다.
접속에 실패한 주소는 붉게 표시되므로, 등록 전에 제외하거나 주소를 수정할 수 있습니다.

@note
**비활성으로 등록** 항목을 선택하면 설정만 저장하고 분석은 시작하지 않습니다.
대응점 지정을 마친 뒤 한꺼번에 활성화하면 분석 자원을 낭비하지 않습니다.
매핑되지 않은 카메라도 영상 처리 자원은 그대로 소비하므로, 카메라 수가 많은
현장에서는 이 방식을 권장합니다.
@end

대응점 지정을 마친 뒤에는 카메라 목록 아래 **매핑 완료 카메라 전부 활성화**
버튼으로 한 번에 활성화합니다.

## 6.4 대응점 지정

카메라 화면의 한 점과 평면도의 같은 지점을 짝지어, 좌표 변환 관계를 만듭니다.

@img 25_mapping.png
대응점 지정 화면
@end

@steps
1. 왼쪽 목록에서 카메라를 선택합니다. 오른쪽에 첫 프레임이 표시됩니다.
2. 도구 막대에서 **대응점 (4+쌍)** 이 선택되어 있는지 확인합니다.
3. 카메라 화면(왼쪽)에서 기준이 될 지점을 클릭합니다.
4. 평면도(오른쪽)에서 같은 지점을 클릭합니다.
5. 3~4를 반복하여 **최소 4쌍** 이상 지정합니다.
6. **매핑 저장**을 누릅니다.
@end

저장하면 대응점별 재투영 오차가 미터 단위로 표시됩니다. 오차가 큰 지점은
다시 지정하십시오. 카메라 프레임과 평면도의 방향이 크게 다르면 도구 막대의
**도면 회전(90°)** 으로 평면도를 표시상 돌려 대응점을 찍기 편하게 맞출 수 있습니다
(표시 전용이며 저장되는 좌표에는 영향을 주지 않습니다).

@note
대응점은 **바닥면의 식별 가능한 지점**을 사용하십시오. 기둥 하단, 바닥 타일
모서리, 문턱이 적합합니다. 벽면 중간이나 천장, 가구 윗면처럼 바닥에서 떨어진
지점을 사용하면 변환 오차가 커집니다.

또한 대응점은 화면 전체에 고르게 분포시켜야 합니다. 한쪽에 몰리면 반대편
영역의 좌표 정확도가 떨어집니다.
@end

## 6.5 유효 ROI 지정

카메라 화면에서 분석에 사용할 영역을 제한합니다.

@img 26_roi.png
유효 ROI 지정
@end

@steps
1. 도구 막대에서 **유효 ROI**를 선택합니다.
2. 분석 대상 영역의 경계를 클릭하여 다각형을 그립니다.
3. **매핑 저장**을 누릅니다.
@end

**커버리지→ROI 자동설정**을 누르면 지정한 대응점 범위를 감싸는 영역이 자동으로
설정됩니다.

@note
**유효 ROI는 지정하지 않는 것이 기본입니다.** 지정하지 않으면 대응점들을 감싸는
범위가 자동으로 분석 영역이 되어, 좌표 보정이 이루어진 구간만 사용됩니다.
유효 ROI를 지정하면 이 자동 범위를 **대체**합니다 — 대응점 범위보다 넓게 그리면
보정되지 않은 구간까지 좌표 변환이 이루어져 위치 오차가 급격히 커집니다.
@end

유효 ROI는 **대응점 범위 안에서 일부를 제외할 때만** 사용합니다. 유리창 너머
공간, 난간 아래로 보이는 다른 층 바닥, 거울에 비친 상 등이 해당합니다.

넓은 영역을 분석하려면 유효 ROI를 넓히는 것이 아니라 **대응점을 넓게 다시
지정**합니다.

## 6.7 RTSP 미리보기

등록하기 전에 주소가 연결되는지, 검출·추적이 실제로 동작하는지 확인합니다.

@img 28_preview.png
RTSP 미리보기
@end

@steps
1. 도구 막대에서 **미리보기 ▶**를 누릅니다.
2. 확인할 RTSP 주소를 입력하고 **시작**을 누릅니다.
3. 영상에 ID 상자가 표시되면 검출·추적이 동작하는 것입니다.
4. 확인이 끝나면 **정지**를 누르고 창을 닫습니다.
@end

표시되는 정보는 다음과 같습니다.

@table
| 항목 | 의미 |
| 해상도 · 소스 fps | 스트림이 실제로 보내는 영상 규격 |
| 추론 fps | 분석이 처리한 초당 프레임 수 |
| 검출 / 프레임 | 프레임당 평균 검출 인원 |
| 고유 트랙 | 관측 구간에서 부여된 서로 다른 ID 수 |
| 첫 프레임 | 연결부터 첫 영상까지 걸린 시간 |
@end

@note
미리보기는 **등록·저장을 하지 않습니다.** 확인 후 정지하고 정식으로 등록하십시오.
분석 자원을 운영과 나누어 사용하므로 켜 둔 채로 두지 마십시오(10분 후 자동 종료).
현장 NVR에 연결할 경우 미리보기도 카메라 세션을 하나 사용합니다.
@end

## 6.8 출입구 화면 집계

출입문이 대응점 범위 밖에 있어 통과 인원이 집계되지 않을 때 사용합니다.

출입문 부근은 카메라 화각이 가장 눕는 구간이어서 대응점을 문까지 넓히기
어렵습니다. 이 경우 통과 판정만 **카메라 화면에서** 수행하도록 지정할 수 있습니다.
통과 인원은 평면도 좌표 없이도 셀 수 있기 때문입니다.

판정 방식은 두 가지이며, 문이 화면에 어떻게 보이는지에 따라 고릅니다.

| 방식 | 쓰는 경우 | 판정 |
| 선 | 문 전체가 화면 안쪽에 보임 | 그은 선을 넘어가면 1명 |
| 영역 | 문이 화면 가장자리에 걸려 절반만 보임 | 칠한 영역에 들어오면 1명 |

### 6.8.1 선으로 집계

@img 29_exline.png
출입구 화면 통과선 지정
@end

@steps
1. 통과를 관측할 카메라를 목록에서 선택합니다.
2. 도구 막대에서 **출입구 통과선**을 선택하고, 담당할 출입구를 고른 뒤 **선**을 선택합니다.
3. 카메라 화면에서 문지방을 가로지르도록 **두 점**을 클릭합니다.
4. 건물 **안쪽** 방향에 한 번 더 클릭합니다.
5. **매핑 저장**을 누릅니다.
@end

### 6.8.2 영역으로 집계

문이 화각 가장자리에 걸리면 사람이 절반만 보인 채 지나가 선 판정이 자주
실패합니다. 이때는 선 대신 나가는 공간을 **영역**으로 칠합니다.

@img 29b_exzone.png
출입구 화면 영역 지정
@end

@steps
1. 담당할 출입구를 고른 뒤 **영역**을 선택합니다.
2. 문(나가는 공간)을 감싸도록 카메라 화면에서 **3점 이상** 클릭합니다.
3. **체류** 값을 확인합니다. 같은 사람이 이 프레임 수만큼 연속으로 영역 안에
   잡혀야 1명으로 집계됩니다. 5 fps 기준 기본값 2가 적당합니다.
4. **매핑 저장**을 누릅니다.
@end

같은 사람은 영역에 아무리 오래 머물러도 **한 번만** 집계됩니다. 밖으로 나갔다가
다시 들어오면 그때 다시 셉니다.

### 6.8.3 공통 사항

지정하면 해당 출입구의 통과 집계가 카메라 화면 기준으로 바뀝니다. 평면도의
출입구 선은 그대로 남아 **위치 표시와 유효폭·설계용량 산출**에 계속 사용되며,
집계에서만 제외됩니다. 평면도에서는 점선으로 표시되고 담당 카메라 이름이
함께 표기됩니다. 사람의 움직임이 평면도에 표시되는 방식은 달라지지 않습니다.

@note
한 출입구는 **한 가지 방식으로만** 집계합니다. 선과 영역은 함께 쓸 수 없으며,
나중에 지정한 쪽이 적용됩니다. **해제**를 누르면 평면도 기준 집계로 즉시
되돌아갑니다.
하나의 출입구는 **한 대의 카메라**만 담당해야 합니다. 두 대가 같은 문을 담당하면
같은 사람이 두 번 집계됩니다.
@end

## 7.2 평가 세션 시작 (단일 층)

## 7.5 건물 훈련 (여러 층 동시)

실제 피난 훈련은 건물 하나에서 여러 층이 **동시에** 진행됩니다. 카메라가 두 개
이상의 층에 매핑되어 있으면 운영 뷰의 시작 버튼이 **🔔 건물 전체 경보 시작**으로
바뀌며, 전 층을 하나의 훈련으로 묶어 평가합니다.

경보 시작 버튼 옆에는 **경보 발생원**의 층별 지정 현황이 표시됩니다(예: `17F ○`
`16F ○`). 참여하는 모든 층에 경보 발생원이 지정되어야 훈련을 시작할 수 있습니다.

@img 35_building_drill_panel.png
건물 훈련 — 층별 경보 발생원 지정 현황과 실시간 지표
@end

@steps
1. 상단 **층** 선택 상자로 참여할 각 층으로 이동합니다.
2. 각 층에서 **+ 추가**로 그 층의 경보 발생 위치를 평면도에 지정합니다.
3. 모든 참여 층에 발생원이 채워지면(현황이 모두 `●`) **🔔 건물 전체 경보 시작**을 누릅니다.
4. 훈련이 끝나면 **세션 종료**를 누릅니다.
@end

@note
참여 층은 **카메라가 매핑된 층**입니다. 카메라가 없는 층(예: 지상1층)은 훈련에서
자동으로 제외됩니다. 발생원이 지정되지 않은 층이 있으면 시작 시 어느 층이
비었는지 안내되며, 그 층으로 이동해 발생원을 지정해야 시작됩니다. 경보 발생원은
**훈련마다 새로 지정**합니다.
@end

종료하면 층별 지표를 합산한 **건물 훈련 롤업**이 표시됩니다.

@img 43_drill_report.png
건물 훈련 롤업 리포트
@end

| 항목 | 내용 |
| SEI(건물) | 전 층 비상구를 하나의 분포로 합쳐 재계산한 값 |
| EPFI 평균 | 전 층 전 인원 평균 |
| CBS 합 | 전 층 병목 누적의 합 |
| IDR 개시 | 전 층 구역 중 피난이 개시된 구역 수 (구역별로 유지) |
| 추가 요약 | 참여 층, 총 통과 인원, 최대 혼잡 층, 층별 개시시각 |
| 층별 상세 | 층마다 SEI·EPFI·CBS·통과 인원·IDR 개시 |

건물 롤업과 층별 상세는 **JSON·CSV**로 내보낼 수 있습니다.

## 8.2 임계값 변경 후 재계산

같은 훈련 기록에 다른 판정 기준을 적용하여 지표를 다시 산출할 수 있습니다.

@steps
1. 오른쪽 패널에서 임계값을 수정합니다.
2. **이 값으로 재계산**을 누릅니다.
3. 원래 값으로 되돌리려면 **원래값**을 누릅니다.
@end

도면과 카메라 매핑은 그대로 두고 판정 기준만 바꾸므로, 임계값이 결과에
미치는 영향을 직접 확인할 수 있습니다. 건물 훈련 모드에서는 재계산이 참여
전 층에 함께 적용되어 건물 지표가 갱신됩니다.

@note
이 기능은 세션 기록 파일(.db)이 있는 세션에서만 사용할 수 있습니다.
목록에서 **재계산가능** 표시로 기록 보유 여부를 확인하십시오. 원본 저장값은
재계산으로 바뀌지 않습니다.
@end

# 9. 지표 해석 기준

## 9.1 지표별 방향

| 지표 | 범위 | 좋은 방향 | 값이 없을 때의 의미 |
| IDR | 구역별 (m/s) | 클수록 좋음 | 해당 구역에서 피난이 개시되지 않음 |
| EPFI | 0~100 | 클수록 좋음 | 권장 경로가 배정되지 않음 |
| CBS | 0 이상 | **작을수록 좋음** | 해당 없음. 0은 임계 밀도를 넘지 않았다는 뜻 |
| SEI | 0~100 | 클수록 좋음 | 비상구 통과 인원이 없어 산출 불가 |

@note
**값이 없는 것과 0점은 다릅니다.** 특히 구역의 IDR이 비어 있는 경우는 반응이
느렸다는 뜻이 아니라 피난을 시작하지 않았다는 뜻이며, 대개 훈련에서 가장 먼저
확인해야 할 사항입니다.
@end

## 9.2 결과 해석 시 확인 사항

지표를 해석하기 전에 다음을 먼저 확인하십시오.

@steps
1. 관측된 카메라 목록에 등록한 카메라가 모두 포함되어 있는가
2. 맵 투영 실패 비율이 지나치게 높지 않은가
3. 관측된 대상자 수가 실제 참여 인원과 크게 차이 나지 않는가
@end

특정 구역의 IDR, 특정 병목의 CBS, 특정 비상구의 SEI가 동시에 비어 있다면
그 공간이 카메라 화각에 잡히지 않았을 가능성이 높습니다. 지표 악화가 아니라
관측 범위 문제이므로 개선 방향이 전혀 다릅니다.

## 9.3 종합 점수에 관하여

현재 버전은 **4대 지표를 각각 산출하며, 이를 합산한 종합 점수나 등급은
산출하지 않습니다.** 가중치와 등급 기준은 발주처 승인 후 별도로 반영할 사항입니다.

# 10. 문제 해결

| 증상 | 확인 사항 |
| 카메라 연결에 실패함 | RTSP 주소, 계정, 포트를 확인합니다. 일괄 등록 화면의 연결 테스트로 개별 확인이 가능합니다 |
| 화면에 사람이 표시되지 않음 | 카메라가 활성 상태인지, 대응점이 지정되어 있는지 확인합니다. 매핑되지 않은 카메라는 평면도에 표시되지 않습니다 |
| 특정 구역만 계속 미개시로 표시됨 | 해당 구역이 카메라 화각에 포함되는지 확인합니다. 유효 ROI가 지나치게 좁게 설정되어 있을 수 있습니다 |
| 사람 위치가 평면도에서 어긋남 | 대응점 재투영 오차를 확인하고, 오차가 큰 지점을 다시 지정합니다 |
| 비상구 통과가 계수되지 않음 | 통과선이 실제 통행 방향을 가로지르는지, 카메라 화각 안에 있는지 확인합니다. 문이 화면 가장자리에 걸려 사람이 절반만 보인다면 6.8.2의 **영역** 방식으로 바꿉니다 |
| 추론 모델을 바꿀 수 없음 | 평가 세션이 진행 중이면 전환되지 않습니다. 세션 종료 후 다시 시도합니다. **엔진 없음**으로 표시되면 5.10의 준비 명령을 서버에서 실행합니다 |
| 모든 대상자의 EPFI가 비슷하게 낮음 | 권장 경로가 실제 동선과 평행하게 어긋나 있을 수 있습니다. 경로 위치를 확인합니다 |
| 건물 훈련이 시작되지 않음 | 참여(카메라 매핑) 전 층에 경보 발생원이 지정되어 있는지 확인합니다. 안내에 표시된 층으로 이동해 발생원을 지정합니다 |
| 설정을 처음 상태로 되돌리고 싶음 | ① 맵 설정 오른쪽 아래 **↺ Reset**으로 기본 제공 설정으로 복원합니다(세션 기록은 보존) |
