# 1. 문서 개요

## 1.1 목적

이 문서는 다중 CCTV 영상에서 재실자의 이동을 추적하고, 건물 평면도 좌표로 변환하여
피난훈련을 정량적으로 평가하는 시스템의 사용 절차를 설명합니다.

시스템은 경보 발생 이후의 피난 행동을 네 가지 정량지표로 산출합니다.

| 지표 | 명칭 | 평가 대상 |
| IDR | 피난 반응 확산 지표 | 구역별로 얼마나 빨리 피난을 개시했는가 |
| EPFI | 경로 충실도 지표 | 권장 피난경로를 얼마나 충실히 따랐는가 |
| CBS | 병목 혼잡 누적 지표 | 병목 구역에 혼잡이 얼마나 누적되었는가 |
| SEI | 비상구 활용 효율 지표 | 비상구가 설계 의도대로 분산 사용되었는가 |

## 1.2 적용 범위

본 문서는 다음 두 개 화면의 사용 절차를 다룹니다. 실제 사용 순서와 동일하게
도면 준비를 먼저 설명하고, 이어서 운영 화면을 설명합니다.

| 구분 | 접속 주소 | 역할 |
| 도면 편집기 | http://<서버주소>:8910 | CAD 도면을 평면도 이미지로 변환하고 비상구·피난경로를 검증 |
| 멀티카메라 시스템 | http://<서버주소>:8900 | 공간 요소 설정, 카메라 매핑, 실시간 운영, 평가 세션 |

본 문서의 모든 화면 예시는 시스템에 기본 제공되는 **17F 평면도**를 사용합니다.
독자는 동일한 도면과 동일한 위치의 구역·병목·비상구를 화면에서 확인하면서
절차를 따라갈 수 있습니다.

## 1.3 용어

| 용어 | 설명 |
| 세션 | 경보 시작부터 종료까지의 평가 단위. 이 구간에서만 지표가 산출됩니다 |
| 구역 | IDR 산출 단위가 되는 평면도상의 다각형 영역 |
| 병목 | CBS 산출 대상이 되는 혼잡 우려 영역 |
| 통과선 | 비상구 통과 인원을 계수하기 위해 지정하는 가상의 선 |
| 대응점 | 카메라 화면의 한 점과 평면도의 같은 지점을 짝지은 좌표쌍 |
| 호모그래피 | 대응점으로부터 산출되는, 카메라 좌표를 평면도 좌표로 바꾸는 변환 행렬 |
| 유효 ROI | 카메라 화면에서 분석에 사용할 영역. 이 밖의 검출은 제외됩니다 |

# 2. 시스템 구성

## 2.1 처리 흐름

시스템은 다음 순서로 동작합니다.

@flow
CCTV(RTSP) → GPU 디코딩 → 사람 검출·추적 → 평면도 좌표 변환
→ 구역·병목·비상구 이벤트 판정 → 4대 지표 산출 → 화면 표시 및 저장
@end

카메라별로 추적된 사람의 발 위치를 호모그래피로 평면도 좌표로 옮긴 뒤,
그 좌표가 어느 구역에 있는지, 권장 경로에서 얼마나 벗어났는지, 병목을 지났는지,
어느 비상구를 통과했는지를 판정하여 지표를 계산합니다.

## 2.2 사용 순서

@steps
① 도면 준비 — CAD 도면에서 평면도 이미지를 만들고 비상구를 지정합니다 (:8910)
② 맵 설정 — 축척을 정하고 구역·병목·비상구·피난경로를 그립니다 (:8900 ① 탭)
③ 카메라 등록·매핑 — 카메라를 등록하고 평면도와 좌표를 맞춥니다 (:8900 ② 탭)
④ 운영 — 실시간 화면을 확인하고 훈련 시 평가 세션을 진행합니다 (:8900 ③ 탭)
⑤ 결과 확인 — 세션을 재생하고 필요 시 임계값을 바꿔 다시 계산합니다 (:8900 ④ 탭)
@end

①과 ②는 현장 최초 구축 시 한 번만 수행하며, 이후 훈련에서는 ④부터 시작합니다.

# 3. 도면 준비

CAD 도면(DWG/DXF)에서 평면도 이미지를 만들고, 비상구 위치와 피난경로가
올바른지 검증하는 단계입니다. 이미 평면도 이미지가 준비되어 있다면 이 장을 건너뛰고
4장으로 진행하십시오.

## 3.1 편집기 접속

브라우저에서 `http://<서버주소>:8910` 에 접속합니다.

@img 01_editor_start.png
도면 편집기 초기 화면
@end

화면 상단에 작업 단계가 표시됩니다. 왼쪽부터 순서대로 진행합니다.

@steps
① 업로드 → ② 정리 → ③ Exit → ④ 검증 → ⑤ 적용
@end

## 3.2 도면 업로드

화면 가운데 점선 영역에 DWG 또는 DXF 파일을 끌어다 놓거나, **파일 선택** 버튼으로
파일을 지정합니다.

@note
PDF 도면은 직접 업로드할 수 없습니다. AutoCAD에서 PDF Import를 실행한 뒤
DWG로 저장하여 업로드하십시오.
@end

## 3.3 도면 정리

업로드된 도면에는 치수선, 주석, 범례 등 분석에 불필요한 요소가 포함되어 있습니다.
오른쪽 **모드** 영역에서 도구를 선택하여 정리합니다.

@img 06_editor_del.png
요소 삭제 도구 선택 상태
@end

| 도구 | 조작 | 용도 |
| 이동/줌 | 휠·드래그 | 도면을 확대하거나 이동합니다 |
| 삭제 (치수선 등) | 박스 드래그 | 선택 영역의 요소를 지웁니다 |
| 개구부 (문 열기) | 선 그리기 | 닫힌 것으로 인식된 문을 통행 가능하게 만듭니다 |
| Exit 지정 | 선 그리기 | 비상구 위치를 지정합니다 |

잘못 조작한 경우 **실행취소**(Ctrl+Z)로 되돌립니다.

@note
**개구부 처리를 빠뜨리지 마십시오.** CAD 도면에서 문은 대개 닫힌 선으로 그려져
있어, 그대로 두면 통행이 불가능한 벽으로 인식됩니다. 이 상태에서는 피난경로가
실제와 다르게 산출됩니다.
@end

## 3.4 Exit 지정

**Exit 지정** 도구를 선택하고 비상구 위치에 선을 그립니다.

@img 05_editor_exit.png
Exit 지정 도구
@end

여기서 지정한 비상구는 이후 경로 검증의 도착점이 됩니다.

## 3.5 경로 검증

오른쪽 **검증** 영역에서 피난경로가 올바르게 산출되는지 확인합니다.

@img 07_editor_verify.png
경로 검증 및 열지도
@end

| 항목 | 기본값 | 설명 |
| 기준거리(m) | 30 | 이 거리를 넘는 지점을 문제 구간으로 표시합니다 |
| worst | 5 | 가장 불리한 경로를 몇 개까지 표시할지 지정합니다 |
| 경로 표시 | 사용 | 산출된 피난경로를 도면 위에 그립니다 |
| 거리 열지도 | 미사용 | 모든 지점에서 가장 가까운 비상구까지의 거리를 색으로 표시합니다 |

**경로 검증 (worst-N)** 을 누르면 가장 불리한 경로가 표시됩니다. 경로가 벽을
통과하거나 비정상적으로 우회한다면 3.3의 개구부 처리가 누락된 것이므로
도면 정리로 돌아가 보완하십시오.

## 3.6 적용

검증이 끝나면 오른쪽 **적용** 영역에서 site 이름을 확인하고 **저장 & 적용**을 누릅니다.

@note
**운영 서버(:8900) 맵 즉시 교체** 항목을 선택하면 운영 중인 시스템의 평면도가
곧바로 대체됩니다. 기존에 설정해 둔 구역·병목·비상구 위치가 새 도면 기준으로
어긋날 수 있으므로, 운영 중에는 선택하지 마십시오.
@end

# 5. 맵 설정

평면도에 축척을 부여하고, 지표 산출의 기준이 되는 공간 요소를 그리는 단계입니다.

## 5.1 화면 구성

@img 11_map_overview.png
① 맵 설정 화면 전체
@end

화면은 세 부분으로 구성됩니다.

| 영역 | 위치 | 내용 |
| 도구 막대 | 상단 | 맵 업로드, 드로잉 도구, 격자·스냅 설정 |
| 도면 | 가운데 | 평면도와 그려진 요소. 휠로 확대, 드래그로 이동 |
| 사이트 설정 | 오른쪽 | 층 관리, 축척, 요소 목록, 임계값 |

예시 도면에는 기본 설정이 이미 적용되어 있습니다. 오른쪽 목록에서
피난경로 2개, 구역 3개, 병목 2개, 출입구 2개를 확인할 수 있습니다.

## 5.2 층 선택

건물의 여러 층을 각각 별도의 도면으로 관리합니다.

@img 12_floor_select.png
층 선택
@end

화면 오른쪽 위 **층** 선택 상자에서 대상 층을 고릅니다. 예시에는 17F, 19F,
지상1층 세 개 층이 등록되어 있습니다. 구역·병목·비상구·피난경로와 4대 지표는
모두 층별로 따로 관리됩니다.

@note
층을 넘나드는 동일인 연결(계단·엘리베이터 이동)은 현재 버전에서 지원하지 않습니다.
각 층은 독립된 좌표계로 처리됩니다.
@end

## 5.3 축척 지정

거리와 밀도를 미터 단위로 계산하려면 축척이 필요합니다.

@img 13_scale.png
축척 2점 도구
@end

@steps
1. 도구 막대에서 **축척 2점**을 선택합니다.
2. 도면에서 실제 길이를 아는 두 지점을 차례로 클릭합니다.
3. **실거리** 입력란에 두 지점 사이의 실제 거리를 미터 단위로 입력합니다.
4. **완료**를 누릅니다.
@end

예시 도면은 가로 방향 두 지점에 73.2 m가 지정되어 있으며, 그 결과 축척은
0.0239 m/px로 산출되어 있습니다. 오른쪽 **맵 · 축척** 영역에서 확인할 수 있습니다.

@note
축척을 지정하지 않으면 이동속도, 구역 밀도, 경보원까지의 거리를 미터 단위로
산출할 수 없습니다. 다른 요소를 그리기 전에 축척부터 지정하십시오.
@end

## 5.4 구역 지정 (IDR)

구역은 피난 개시 시점을 판정하는 단위입니다.

@img 14_zone.png
구역 드로잉 도구
@end

@steps
1. 도구 막대에서 **구역 IDR**을 선택합니다.
2. 도면에서 구역 경계를 따라 클릭하여 다각형을 그립니다.
3. **이름** 입력란에 구역 이름을 입력합니다.
4. **완료**를 누릅니다.
@end

예시 도면에는 z3, z4, z5 세 개 구역이 지정되어 있습니다. 오른쪽 **구역** 목록에서
각 구역의 꼭짓점 수를 확인할 수 있으며, 휴지통 아이콘으로 삭제합니다.

구역은 사람이 머무는 공간 단위로 나눕니다. 사무실, 회의실, 복도처럼 피난 개시
시점이 서로 다를 것으로 예상되는 공간을 각각 하나의 구역으로 지정하십시오.

## 5.5 병목 지정 (CBS)

병목은 혼잡이 누적되는지 감시할 영역입니다.

@img 15_bottleneck.png
병목 드로잉 도구
@end

@steps
1. 도구 막대에서 **병목 CBS**를 선택합니다.
2. 도면에서 병목 구간의 경계를 따라 다각형을 그립니다.
3. **임계밀도** 입력란에 기준 밀도를 명/㎡ 단위로 입력합니다.
4. **완료**를 누릅니다.
@end

예시에는 b1, b2 두 개 병목이 지정되어 있으며, 임계밀도는 각각 0.1 명/㎡,
가중치는 1로 설정되어 있습니다. 오른쪽 **병목** 목록에서 값을 직접 수정할 수 있습니다.

| 항목 | 의미 |
| ρcrit | 이 밀도를 넘는 동안만 CBS에 누적됩니다 |
| w | 병목의 중요도. 값이 클수록 같은 혼잡도라도 CBS가 크게 산출됩니다 |

계단 입구, 복도 합류점, 출입문 앞처럼 사람이 몰릴 것으로 예상되는 지점을
병목으로 지정하십시오.

## 5.6 출입구 지정 (SEI)

비상구 통과 인원을 계수할 통과선을 지정합니다.

@img 16_exit.png
출입구 드로잉 도구
@end

@steps
1. 도구 막대에서 **출입구 SEI**를 선택합니다.
2. 비상구를 가로지르는 선을 그립니다. 통과 방향과 직각이 되도록 그립니다.
3. 설계 총인원을 입력합니다.
4. **완료**를 누릅니다.
@end

예시에는 e1(설계 32명), e3(설계 30명) 두 개 비상구가 지정되어 있습니다.

@note
**설계 총인원은 SEI 산출의 기준값입니다.** 이 값은 소방 설계 도서에 명시된
비상구별 수용 인원을 입력해야 합니다. 임의로 입력하면 SEI가 실제 설계 의도와
무관한 값이 됩니다.
@end

## 5.7 피난경로 지정 (EPFI)

권장 피난경로를 선으로 그립니다. 각 사람이 이 경로에서 얼마나 벗어났는지가
EPFI로 산출됩니다.

@img 17_route.png
피난경로 드로잉 도구
@end

@steps
1. 도구 막대에서 **피난경로 EPFI**를 선택합니다.
2. 경로를 따라 여러 지점을 차례로 클릭합니다.
3. **완료**를 누릅니다.
@end

예시에는 r1, r2 두 개 경로가 지정되어 있습니다.

@note
경로는 실제 사람이 걷는 동선의 중심을 지나야 합니다. 경로가 실제 동선과
평행하게 어긋나 있으면 모든 대상자의 EPFI가 일정하게 낮아집니다.
@end

## 5.8 공간 그래프 (IDR 보조)

경보 발생 위치에서 각 구역까지의 거리를 계산할 때 사용하는 노드 그래프입니다.

@img 18_graph.png
공간 그래프 도구
@end

지정하지 않으면 직선거리로 대체 계산합니다. 벽을 우회해야 하는 구조에서는
그래프를 지정해야 실제 이동거리에 가까운 IDR이 산출됩니다.

## 5.9 판정 임계값

오른쪽 패널의 **설정** 탭에서 지표 판정 기준을 입력합니다.

@img 19_thresholds.png
판정 임계값 설정
@end

| 항목 | 기본값 | 의미 |
| v_th | 0.3 | 피난 개시로 인정할 최소 이동속도 (m/s) |
| a_th | 0.5 | 피난 개시로 인정할 최소 방향 정렬도 |
| r_th | 0.3 | 피난 개시로 인정할 최소 참여 인원 비율 |
| Δt_hold | 3.0 | 위 조건이 연속 유지되어야 하는 시간 (초) |
| d_allow | 10.0 | EPFI 산출 시 허용하는 경로 이탈 거리 (m) |
| min_conf | 0.5 | 사람 검출로 인정할 최소 신뢰도 |

@note
위 기본값은 임시값입니다. 실제 평가에 적용할 기준치는 발주처와 협의하여
확정해야 하며, 확정 전 산출된 지표는 잠정값으로 취급하십시오.
@end

# 6. 카메라 등록 및 매핑

카메라를 등록하고, 카메라 화면의 좌표를 평면도 좌표로 바꾸는 대응 관계를
설정하는 단계입니다.

## 6.1 화면 구성

@img 21_cams_overview.png
② 카메라 등록·매핑 화면 전체
@end

왼쪽에 카메라 목록, 가운데에 카메라 프레임, 오른쪽에 평면도가 표시됩니다.

@img 22_cam_list.png
카메라 목록
@end

각 카메라 항목에는 다음 정보가 표시됩니다.

| 표시 | 의미 |
| 매핑 ✓ / 매핑 필요 | 대응점 지정 여부. 매핑되지 않은 카메라는 지표 산출에서 제외됩니다 |
| 활성 / 비활성 | 분석 대상 여부 |
| 층 | 이 카메라가 매핑된 도면 |
| 검출 신뢰도 | 카메라별 최소 검출 신뢰도. 비워 두면 사이트 기본값을 따릅니다 |

## 6.2 카메라 한 대 등록

@steps
1. 왼쪽 아래 **카메라 추가** 영역에 이름과 RTSP 주소를 입력합니다.
2. 매핑할 층을 선택합니다.
3. **+ 추가 후 연결 테스트**를 누릅니다.
@end

등록과 동시에 연결을 확인하고 첫 프레임을 가져옵니다. 연결에 실패하면 주소와
계정 정보를 확인하십시오.

## 6.3 여러 대 일괄 등록

현장 카메라가 여러 대인 경우 한 대씩 추가하지 말고 일괄 등록 기능을 사용하십시오.

@note
한 대씩 추가할 때마다 분석 작업이 재시작되며, 같은 GPU에 배정된 다른 카메라의
영상이 약 8초간 끊깁니다. 40대를 한 대씩 등록하면 약 9분 30초가 소요되고
그동안 40회 끊김이 발생합니다. 일괄 등록은 이 과정을 한 번으로 줄입니다.
@end

@steps
1. 카메라 목록 아래 **여러 대 한 번에 등록**을 누릅니다.
2. 주소를 한 줄에 한 대씩 붙여 넣습니다.
3. **목록으로 변환**을 누릅니다.
4. 표에서 이름을 수정하거나 불필요한 행을 제외합니다.
5. **연결 테스트**로 접속 가능 여부를 확인합니다.
6. 매핑 층을 선택하고 **등록**을 누릅니다.
@end

@img 23_bulk_paste.png
주소 붙여넣기
@end

입력 형식은 `이름,RTSP주소` 또는 `RTSP주소`만 입력합니다. 빈 줄과 `#`으로 시작하는
줄은 무시됩니다.

@img 24_bulk_table.png
목록 변환 후 확인 화면
@end

**연결 테스트**는 등록 전에 각 주소의 접속 가능 여부와 해상도를 확인합니다.
접속에 실패한 주소는 붉게 표시되므로, 등록 전에 제외하거나 주소를 수정할 수 있습니다.

@note
**비활성으로 등록** 항목을 선택하면 설정만 저장하고 분석은 시작하지 않습니다.
대응점 지정을 마친 뒤 한꺼번에 활성화하면 분석 자원을 낭비하지 않습니다.
매핑되지 않은 카메라도 영상 처리 자원은 그대로 소비하므로, 카메라 수가 많은
현장에서는 이 방식을 권장합니다.
@end

대응점 지정을 마친 뒤에는 카메라 목록 아래 **매핑 완료 카메라 전부 활성화**
버튼으로 한 번에 활성화합니다.

## 6.4 대응점 지정

카메라 화면의 한 점과 평면도의 같은 지점을 짝지어, 좌표 변환 관계를 만듭니다.

@img 25_mapping.png
대응점 지정 화면
@end

@steps
1. 왼쪽 목록에서 카메라를 선택합니다. 오른쪽에 첫 프레임이 표시됩니다.
2. 도구 막대에서 **대응점 (4+쌍)** 이 선택되어 있는지 확인합니다.
3. 카메라 화면(왼쪽)에서 기준이 될 지점을 클릭합니다.
4. 평면도(오른쪽)에서 같은 지점을 클릭합니다.
5. 3~4를 반복하여 **최소 4쌍** 이상 지정합니다.
6. **매핑 저장**을 누릅니다.
@end

저장하면 대응점별 재투영 오차가 미터 단위로 표시됩니다. 오차가 큰 지점은
다시 지정하십시오.

@note
대응점은 **바닥면의 식별 가능한 지점**을 사용하십시오. 기둥 하단, 바닥 타일
모서리, 문턱이 적합합니다. 벽면 중간이나 천장, 가구 윗면처럼 바닥에서 떨어진
지점을 사용하면 변환 오차가 커집니다.

또한 대응점은 화면 전체에 고르게 분포시켜야 합니다. 한쪽에 몰리면 반대편
영역의 좌표 정확도가 떨어집니다.
@end

## 6.5 유효 ROI 지정

카메라 화면에서 분석에 사용할 영역을 제한합니다.

@img 26_roi.png
유효 ROI 지정
@end

@steps
1. 도구 막대에서 **유효 ROI**를 선택합니다.
2. 분석 대상 영역의 경계를 클릭하여 다각형을 그립니다.
3. **매핑 저장**을 누릅니다.
@end

**커버리지→ROI 자동설정**을 누르면 지정한 대응점 범위를 감싸는 영역이 자동으로
설정됩니다.

유효 ROI를 지정하면 창밖 통행인, 반사된 상, 좌표 변환 정확도가 낮은 화면
가장자리를 분석에서 제외할 수 있습니다.

# 9. 지표 해석 기준

## 9.1 지표별 방향

| 지표 | 범위 | 좋은 방향 | 값이 없을 때의 의미 |
| IDR | 구역별 (m/s) | 클수록 좋음 | 해당 구역에서 피난이 개시되지 않음 |
| EPFI | 0~100 | 클수록 좋음 | 권장 경로가 배정되지 않음 |
| CBS | 0 이상 | **작을수록 좋음** | 해당 없음. 0은 임계 밀도를 넘지 않았다는 뜻 |
| SEI | 0~100 | 클수록 좋음 | 비상구 통과 인원이 없어 산출 불가 |

@note
**값이 없는 것과 0점은 다릅니다.** 특히 구역의 IDR이 비어 있는 경우는 반응이
느렸다는 뜻이 아니라 피난을 시작하지 않았다는 뜻이며, 대개 훈련에서 가장 먼저
확인해야 할 사항입니다.
@end

## 9.2 결과 해석 시 확인 사항

지표를 해석하기 전에 다음을 먼저 확인하십시오.

@steps
1. 관측된 카메라 목록에 등록한 카메라가 모두 포함되어 있는가
2. 맵 투영 실패 비율이 지나치게 높지 않은가
3. 관측된 대상자 수가 실제 참여 인원과 크게 차이 나지 않는가
@end

특정 구역의 IDR, 특정 병목의 CBS, 특정 비상구의 SEI가 동시에 비어 있다면
그 공간이 카메라 화각에 잡히지 않았을 가능성이 높습니다. 지표 악화가 아니라
관측 범위 문제이므로 개선 방향이 전혀 다릅니다.

## 9.3 종합 점수에 관하여

현재 버전은 **4대 지표를 각각 산출하며, 이를 합산한 종합 점수나 등급은
산출하지 않습니다.** 가중치와 등급 기준은 발주처 승인 후 별도로 반영할 사항입니다.

| 카메라 연결에 실패함 | RTSP 주소, 계정, 포트를 확인합니다. 일괄 등록 화면의 연결 테스트로 개별 확인이 가능합니다 |
| 화면에 사람이 표시되지 않음 | 카메라가 활성 상태인지, 대응점이 지정되어 있는지 확인합니다. 매핑되지 않은 카메라는 평면도에 표시되지 않습니다 |
| 특정 구역만 계속 미개시로 표시됨 | 해당 구역이 카메라 화각에 포함되는지 확인합니다. 유효 ROI가 지나치게 좁게 설정되어 있을 수 있습니다 |
| 사람 위치가 평면도에서 어긋남 | 대응점 재투영 오차를 확인하고, 오차가 큰 지점을 다시 지정합니다 |
| 비상구 통과가 계수되지 않음 | 통과선이 실제 통행 방향을 가로지르는지, 카메라 화각 안에 있는지 확인합니다 |
| 모든 대상자의 EPFI가 비슷하게 낮음 | 권장 경로가 실제 동선과 평행하게 어긋나 있을 수 있습니다. 경로 위치를 확인합니다 |
