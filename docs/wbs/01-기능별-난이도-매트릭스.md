## 0. 한 장 요약 (C레벨용)

> **기능을 "만드는 것"은 대부분 쉽다. 어려운 건 두 가지다 — ① 정확도가 나오게 만드는 것(모델 성능), ② 150채널에서 실시간으로 돌아가게 만드는 것(지연·경량화·GPU 리소스).**

- **단일 카메라 기준, 4개 기능 중 2개(F1·F2)는 이미 동작**하고, 나머지 2개(F3·F4)도 토대가 있다. → **기능 구현 난이도는 전반적으로 낮음~중.**
- **시수와 리스크의 80%는 "기능"이 아니라 "확장·정확도"에 있다:**
  1. **다채널(150ch) 실시간화** — 실측상 검출 연산이 배치로 빨라지지 않아(GPU 천장 고정) **검출 경량화 + GPU 증설** 없이는 채널당 ~1fps가 한계. **이것이 최대 시수·하드웨어 투자처.**
  2. **F3 2D맵·대피경로** — 다카메라 좌표 정합·핸드오프·경로탐색은 **신규 서브시스템**이라 가장 길고 불확실하다.
  3. **F2 잔류인원 정확도** — 알고리즘은 동작하나 **장시간 누적오차(드리프트)**와 가림/ID스위치 보정이 진짜 난제.
- **즉, "기능 데모"는 8월 중간보고까지 충분히 도달 가능. "150채널 실증·정확도 보증"이 6~9월 시수의 핵심.**

## 1. 난이도 정의

- **기능 구현 난이도** = 성능/정확도는 **배제**하고, 모델을 얹어 **기능 자체를 동작시키는** 개발 난이도. **이미 구현된 것은 `하`.**
- **모델 성능 난이도** = 추적이 잘 되는가, 잔류인원이 정확한가, 경로가 신뢰할 만한가 등 **결과 품질을 확보하는** 난이도(정확도·실시간성 포함).
- 척도: **`하`(쉬움/완료) · `중`(중간) · `상`(높음/불확실성 큼)**

| 시나리오 | 정의 | 실측 성능 기준선 |
|----------|------|------------------|
| **단일 카메라** | 1대, 1프로세스 | 혼잡 장면 ~12.5fps (실측) |
| **15채널** | 15대, 2GPU 멀티프로세스 | 채널당 ~7fps, 총 ~106fps (실측) — 군중분석 실용 |
| **150채널+** | 150대 이상, VMS 환경 | 현 모델 천장상 채널당 ~1~1.3fps → 경량화·GPU 증설 필요 |

| 기능 | 단일 카메라 | 15채널 | 150채널+ |

## 4. 리스크·시수 집중 지점 (C레벨 핵심)

### 4.1 "기능 구현"은 병목이 아니다
- 단일 카메라 기준 **F1·F2는 이미 동작**, F3는 토대, F4는 직선적. → **단순 기능 개발 시수는 작다.**

### 4.2 진짜 시수·리스크 Top 3

| 순위 | 리스크 | 왜 어려운가 (실측 근거) | 성격 |
|:---:|--------|------------------------|------|
| 🔴 1 | **150채널 실시간화** | 검출(YOLOX)이 **배치로 가속 안 됨** → GPU 처리량 천장 고정. 현 모델 2GPU로 유용한 fps(5~10) 기준 **~20~40채널이 한계**. 150채널엔 **검출 경량화 + GPU 4~8장**이 필수 | **시스템 성능**(지연·경량화·리소스) |
| 🔴 2 | **F3 다카메라 융합·대피경로** | 도면 정합·카메라 핸드오프·경로엔진 모두 **신규 서브시스템**. 정합 오차가 경로 신뢰도에 직결 | **신규 개발**(불확실성) |
| 🟡 3 | **F2 잔류인원 정확도** | in−out 누적오차가 **시간에 따라 발산**. 가림·ID스위치로 미카운트 | **모델 성능**(정확도) |

### 4.3 결론: 무엇이 어려운가?
> **"기능을 얹는 것"은 쉽다. 어려운 건 (A) 150채널 VMS 환경에서 실시간으로 돌게 만드는 시스템 성능 문제(지연·경량화·연산 리소스)와, (B) 정확도가 신뢰할 수준으로 나오게 만드는 모델 성능 문제다.** 하드웨어 투자(GPU 증설)와 경량화 연구가 일정·예산의 핵심 변수다.

### 4.4 완화 지렛대 (실측)

| 지렛대 | 효과 | 비고 |
|--------|------|------|
| 검출 경량화(해상도↓) | 처리량 ×1.2~1.5 | 작은/먼 사람 정확도 검증 필요 |
| 경량 검출기(YOLO26)+모션 트래커 | 단일 ×4.2 | 단, ReID 미사용 → 혼잡 정확도 저하 가능 |
| MPS(다프로세스 GPU 공유) | +20~27% | 코드 변경 0, 데몬만 |
| GPU 증설(2→4~8장) | 선형 | VRAM(192GB)은 제약 아님 |

→ **단일 지렛대로는 부족. 경량화 + GPU 증설 + 멀티프로세스 병행이 150채널의 현실 경로.**
