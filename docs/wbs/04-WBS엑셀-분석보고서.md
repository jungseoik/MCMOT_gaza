## 0. 결론 먼저

> **전면 재작성은 불필요(구조는 양호).** 단 **① 상태(체크) 즉시 갱신 + ② 부분 재구성**이 필요하다.
> 가장 큰 문제는 **모든 항목이 "예정"인데 실제로는 4장(AI 기능)의 상당수가 이미 구현**돼 있다는 것
> (= 현황 미반영). 부차적으로 **계획 기술스택이 실제 구현/ADR과 불일치**하고,
> **North Star 핵심(정렬도·피난개시·멀티캠 병합)이 명시 라인으로 없다.**

## 1. 구조 평가

**강점**
- 7개 대분류(①환경분석/아키텍처 ②시나리오/평가체계 ③환경구축/연동 ④AI기능개발 ⑤관제/리포트 ⑥실증/검증 ⑦결과/산출물)로 **논리적·제안서 수준**으로 잘 분해됨.
- 항목별 **산출결과·기한·간트(6~9월 주차)** 명시, KPI(mAP≥0.85·IDF1≥0.80·Latency≤500ms)·혼잡도 레벨 정의까지 포함.

**약점 (수정 필요)**
1. **상태 전부 "예정", 완료일정 전부 공란** — 6/16 기준 실제 진행(4장 다수 구현)이 0% 반영.
2. **계획 스택 ≠ 실제 스택**: WBS는 Kafka·Milvus·Elasticsearch·K8s·Triton·Spark·RT-DETR·BoT-SORT·RetinaFace·Genetec 가정. 실제는 **FastAPI+MJPEG+OpenCV+YOLOX(TRT)+BoostTrack++**, DB/Kafka/K8s 미사용 → [ADR](../architecture/01-기술스택-결정.md)와 어긋남.
3. **요구사항 추적성 약함**: **방향성 정렬도·사잇각·피난 개시 시점·멀티캠 ID 병합**이 명시 작업 라인으로 없음(4.5 대피경로에 일부 함의만).
4. **순서 괴리**: WBS는 6월=①②③ 먼저인데, 실제론 ④ 기능 데모가 선행. 1~3장 형식 산출물은 미작성·4장은 앞서감.
5. **기한 낙관**: 4.x가 대부분 1~2d. 실제 본질 블로커는 "구현"이 아니라 **정의·임계 결정·데이터 입수**(정렬도 G3/G7 참고)인데 이 비용이 WBS에 안 보임.

## 3. 권고 — "재작성"이 아니라 "갱신 + 부분 재구성"

**A. 체크(상태) 즉시 갱신 (필수, 지금)**
- §2 매핑대로 4.1~4.5의 ✅/🟡 항목에 **완료/진행 + 완료일정** 기입. "예정 100%"는 실제와 어긋나 보고 신뢰도를 떨어뜨림.

**B. 기술스택 정합 (산출결과/내용 열 수정)**
- 실제·[ADR] 기준으로 수정하거나 "계획 스택 → 실제 채택 스택" 주석. (Kafka·Milvus·K8s·Spark·Triton 등은 50~60ch 초과 확장/장기 단계로 명시 이관 — 2026-07-4주차 목표 하향으로 최종 50~60ch는 현 경량 스택으로 충분, 대규모 백본은 옵션)

**C. 요구사항 추적 라인 추가**
- 정렬도/피난개시/고유통과/멀티캠 병합을 **요구사항 ID와 매핑**한 라인으로 추가(추적성 확보).

**D. 기한·순서 현실화**
- 이미 앞선 4장 데모를 반영하고, 본질 블로커(**정의·임계 결정·도면/구역 데이터 입수**)를 별도 마일스톤/선결조건으로 분리. (정렬도가 코드보다 "정의"에서 막혔던 사례 반영)

**E. 버전/메타 정리**
- 파일명은 v3인데 내부 "버전 v1" — 일치. 작성일(06-04) 대비 갱신일 추가.

## 4. 한 줄 답
- **잘 짜여 있나?** 구조·범위는 양호(제안서 수준). 단 **현황 미반영 + 스택 불일치 + 요구사항 추적 누락**이 약점.
- **재구성?** 전면 X, **부분 재구성(B·C·D)** O.
- **체크 다시?** **예 — 가장 시급.** 4장 다수가 이미 구현인데 전부 "예정"이라 즉시 갱신 필요(§2 매핑 사용).
