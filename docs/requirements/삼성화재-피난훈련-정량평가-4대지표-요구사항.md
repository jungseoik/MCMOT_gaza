> 기존 [CCTV 영상분석 엔진 필수추출정보(5대 카테고리)](CCTV-영상분석-엔진-필수추출정보.md)는

## 1. 시스템 목적 및 처리 흐름

다중 CCTV에서 검출·추적된 사람의 이동 궤적을 건물 2D 평면도 좌표로 통합하고,
경보 발생 이후의 피난 행동을 분석하여 **IDR / EPFI / CBS / SEI** 4개 정량지표를 산출한다.
결과는 평면도 기반 대시보드, 평가 리포트, 성능위주설계(PBD) 시뮬레이션 입력으로 제공한다.

```
영상/트랙 입력(멀티카메라)
  → 카메라 시간 동기화(정규화)
  → 영상좌표(발위치 하단중심) → 호모그래피 → 평면도 2D 좌표
  → 카메라 내부 궤적 생성 (global_track_id 필드 보유, 병합은 최종단계)
  → 구역·경로·병목·출구 이벤트 판정
  → 4대 지표(IDR·EPFI·CBS·SEI) 산출
  → DB/API 저장
  → 대시보드(실시간·재생) · PBD 시뮬레이션 연계
```

## 2. 4대 지표 상세 (입력 → 처리 → 출력)

> 각 지표마다 **① 목적 · ② 입력 데이터 · ③ 처리/수식 · ④ 출력(데이터 계약) · ⑤ 레포 현황 · ⑥ 개발 필요** 를 정의한다.
> 레포 현황 범례: ✅ 있음 / ⚠️ 부분 / ❌ 없음.

### 2.1 IDR — 구역별 피난 반응 확산 지표 (FR-03 · FR-04)

- **① 목적**: 경보 이후 각 구역이 "얼마나 빨리, 얼마나 멀리 떨어진 곳까지" 피난을 개시했는지를 정량화. 반응이 느린 구역·거리 대비 지연을 드러낸다.
- **② 입력 데이터**
  - 경보 시각 `t_alarm`, 경보 발생 위치 `S_origin`
  - 구역 polygon 집합, 각 구역의 재실 객체 시계열(평면도 좌표·속도·방향)
  - 권장 경로 방향벡터 field(그리드 셀 대표벡터 — 방향정렬도 계산용)
  - 공간 노드그래프(구역 간 연결·거리)
  - 임계값 `v_th, a_th, r_th, Δt_hold`
- **③ 처리/수식 (FR-03 피난 개시 판정)**
  - 구역 `e`에 대해 평균 이동속도 `v_e(t)`, 권장방향과의 평균 정렬도 `a_e(t)`(그리드 셀 대표벡터와의 코사인), 두 조건을 동시 만족한 객체 비율 `r_e(t)` 계산.
  - `v_e ≥ v_th ∧ a_e ≥ a_th ∧ r_e ≥ r_th` 가 `Δt_hold` 이상 **연속 유지되는 최초 시점**을 `t_e,start`로 판정.
  - 권장 방향벡터 = 객체 위치가 속한 그리드 셀의 대표벡터(가장 가까운 권장경로 구간의 출구방향 tangent).
- **③ 처리/수식 (FR-04 IDR 산출)**
  - 경보 위치→구역 공간그래프 최단거리 `D(e, S_origin)`.
  - `IDR_e = D(e, S_origin) / max(t_e,start − t_alarm, ε)`.
  - 피난 개시 미검출 구역은 `not_started`.
- **④ 출력 (zone_metrics[])**: `zone_id, evacuation_start_at(t_e,start), response_delay_sec(t_e,start−t_alarm), graph_distance, idr, participant_ratio, status(started|not_started)`.
- **⑤ 레포 현황**
  - 속도 산출 ✅ `webui/speed.py`(sliding-window, km/h)
  - 방향정렬도(코사인) ⚠️ `webui/speed.py` — **단일 방향벡터** 기준(그리드 셀 field 아님)
  - 다중 구역 polygon ❌ (현재 단일 ROI)
  - 공간 노드그래프·최단거리 ❌
  - 피난개시 시점 판정(속도·정렬·비율 동시·유지시간) ❌
- **⑥ 개발 필요**: 다중 구역 polygon 모델 · 그리드 셀 대표벡터 field · 노드그래프+최단거리 · 구역별 피난개시 판정 엔진 · IDR 계산.

### 2.2 EPFI — 권장 경로 대비 실제 이동 경로 충실도 (FR-05)

- **① 목적**: 각 사람이 권장 대피경로를 얼마나 충실히 따랐는지(경로 이탈 정도)를 정량화.
- **② 입력 데이터**
  - 객체별 평면도 좌표 시계열 궤적 `P_i(t)` (호모그래피 변환 결과)
  - 권장 경로 polyline(관리자 자유곡선 화살표 또는 CAD 산출) — **맵 좌표계**
  - 배정 경로 `assigned_route_id`, 분석시간 `T_i`, 허용 이탈거리 `d_allow`
- **③ 처리/수식** (2026-07-14 사용자 확정 표기)
  1. 객체별 이동 시간: `T_i = t_i,end − t_i,start` (경로 평가 시작~종료 시각)
  2. 객체별 누적 경로 이탈량: `∫[t_i,start → t_i,end] d_i(t) dt`
     — 매 시각 **현재 위치↔배정 권장경로 최근접거리** `d_i(t)`(m)를 측정·적분(사다리꼴)
  3. 객체별 지표: `EPFI_i = max(0, 1 − (1/(T_i·d_allow)) · ∫ d_i(t) dt) × 100`
     — 동치 표기: `max(0, 1 − cumulative_deviation_i / (travel_time_i × allowable_deviation)) × 100`
  4. 전체 지표: `EPFI = (1/n) Σ EPFI_i` (유효 객체 평균)
  - 직관: x축 = 시각(t_start→t_end), y축 = d_i(t)로 그린 곡선의 **아래 면적**이
    누적 이탈량 — 면적이 `T_i × d_allow`(허용 사각형)에 도달하면 0점.
- **③-보강. d_i(t) 시계열 저장·지연 표출** (2026-07-14 확정)
  - 각 객체의 `d_i(t)`를 **시간대별(1초 샘플)로 저장소에 기록**하고, 대시보드는
    실시간 강제 없이 **저장본에서 지연 표출**할 수 있어야 한다(객체별 곡선+면적 시각화).
  - 점수는 최종값에서 원본 시계열까지 **역추적 가능**해야 한다(§8 역추적성과 정합).
- **④ 출력 (person_metrics[])**: `global_track_id, assigned_route_id, duration_sec(T_i), mean_deviation_m, max_deviation_m, epfi`. 전체 평균 EPFI. + 객체별 `d_i(t)` 시계열(세션 저장소).
- **⑤ 레포 현황**
  - 호모그래피 궤적(맵 좌표) ✅ `webui/speed.py`, `webui/depth_ground.py`
  - 코사인 정렬도 ⚠️ (거리기반 EPFI 아님)
  - 경로 **polyline**(다구간) ❌ (현재 단일 방향벡터)
  - 점-경로 최근접거리·시간적분 ❌
- **⑥ 개발 필요**: 경로 polyline 모델(자유곡선/CAD 입력) · 점→polyline 최근접거리 · 시간적분 정규화 · 객체별/전체 EPFI.

### 2.3 CBS — 병목 구역 혼잡 누적 지표 (FR-06)

- **① 목적**: 병목(문·계단·복도 협소부) 구역에서 임계밀도를 초과한 혼잡이 얼마나 오래·심하게 누적됐는지를 정량화.
- **② 입력 데이터**
  - 병목 후보 영역 polygon `k` (M개), 면적 `A_k (m²)`, 임계밀도 `ρcrit,k (명/m²)`, 중요도 가중치 `w_k` — 병목 구역마다 개별 지정, UI/config 입력
  - 각 병목영역의 재실 객체 수 시계열 `N_k(t)` (평면도 좌표 polygon 포함판정)
  - 전체 분석 시간 `T`
- **③ 처리/수식** (2026-07-14 확정)

  **단계 1 — 영역 밀도**
  ```
  ρ_k(t) = N_k(t) / A_k          [명/m²]
  ```

  **단계 2 — 임계 초과분 (음수는 0으로 절단)**
  ```
  e_k(t) = max(0, ρ_k(t) − ρcrit,k)
  ```
  밀도가 임계밀도 이하인 구간은 CBS 기여 없음.

  **단계 3 — 병목 k의 혼잡 누적**
  ```
  CBS_k = ∫₀ᵀ e_k(t) · w_k dt
        = ∫₀ᵀ max(0, ρ_k(t) − ρcrit,k) · w_k dt
  ```

  **단계 4 — 전체 CBS (M개 병목 합산)**
  ```
  CBS = Σ_{k=1}^{M} CBS_k
      = Σ_{k=1}^{M} ∫₀ᵀ max(0, N_k(t)/A_k − ρcrit,k) · w_k dt
  ```

  **이산 구현 (Δt = 1s 샘플)**
  ```
  CBS_k ≈ Σ_l max(0, ρ_k(t_l) − ρcrit,k) · w_k · Δt   [좌리만 적분]
  ```
  구현은 `prev_density` 기준 좌리만(`session.py:_sample()`) — 1초 샘플에서 연속·이산 동일.

  **해석**
  - 임계 초과 강도가 클수록 CBS ↑
  - 임계 초과 지속시간이 길수록 CBS ↑
  - 가중치 `w_k` 큰 구역일수록 동일 혼잡에서도 CBS ↑ (예: 비상계단 > 복도)
  - CBS = 0 → 분석 전 구간 임계밀도 이하

- **④ 출력 (bottleneck_metrics[])**: `bottleneck_id, peak_density, over_threshold_sec, cbs, risk_level`. 총 `cbs_total`. 병목별 CBS + 전체 합 동시 산출.
  - `risk_level`: 병목별 CBS를 최대 CBS 대비 3분위로 분류 (high/mid/low)
- **⑤ 레포 현황** (2026-07-14 기준)
  - 다중 병목영역 polygon·면적별 정의 ✅ `system/config/schema.py:Bottleneck` (`rho_crit`, `weight` 병목별 지정)
  - 영역별 밀도 계산 `N_k(t)/A_k` ✅ `system/metrics/session.py:_bn_densities()`
  - 임계초과 누적 시간적분·가중치 ✅ `system/metrics/session.py:_sample()` — `acc.cbs += over * b.weight * dt`
  - `over_threshold_sec`, `peak_density`, `risk_level` 산출 ✅ `system/metrics/session.py:finalize()`
  - 병목별 CBS + 전체 합(`cbs_total`) ✅ `system/metrics/session.py:_cbs_total()`
- **⑥ 잔여 과제**: 병목 임계밀도·가중치 UI 인라인 편집(현재 맵 설정에서 지정 가능, 숫자 직접 입력 불편) · 세션 리포트 내 병목별 CBS 막대차트 시각화.

### 2.4 SEI — 비상구 공간 활용 효율성 지표 (FR-07)

- **① 목적**: 실제 출구 사용 분포가 설계 통과용량 분포와 얼마나 일치하는지(출구 쏠림/저활용)를 L1 거리 기반으로 정량화. 분포가 동일하면 100, 쏠림이 심할수록 0.
- **② 입력 데이터**
  - 비상구 `j` (총 m개): 맵에 지정한 가상 통과선(2점 + 안쪽 방향), inside 반평면
  - `W_j,eff` (m): 통과선 픽셀 길이 × m_per_px — **맵 설정에서 출입구 선 길이로 자동 계산**
  - `q_design` (인/분/m): 단위 유효폭당 설계 통과기준 — **전역 임계값 입력** (기본 60, 계단 45 등)
  - `C_j,design = W_j,eff × q_design` — 자동 산출, 별도 수동 입력 불필요
  - 객체 궤적(평면도 좌표) — 방향성 crossing 검출용
- **③ 처리/수식** (2026-07-14 확정)

  **단계 1 — 설계 통과용량**
  ```
  C_j,design = W_j,eff × q_design          [인/분]
  ```
  맵 저장 시 출입구 선 길이(px) × m_per_px × q_design 으로 자동 계산되어 schema에 저장.

  **단계 2 — 실제 통과인원 (최초 out 방향만)**
  ```
  E_j,actual = Σ_i I_{i,j}
  I_{i,j} = 1  (객체 i가 비상구 j를 최초 out 방향 통과)
           = 0  (그 외)
  ```
  왕복·재진입은 debounce 제외. out = inside 반평면 → 바깥 방향.

  **단계 3 — 정규화 분포**
  ```
  P_j,design = C_j / Σ_c C_c
  P_j,actual = E_j / Σ_c E_c
  ```

  **단계 4 — SEI (L1 거리 기반)**
  ```
  SEI = (1 − ½ · Σ_j |P_j,actual − P_j,design|) × 100
      = (1 − ½ · Σ_j |E_j/ΣE − C_j/ΣC|) × 100
  ```
  범위: 0 ≤ SEI ≤ 100. 설계 = 실제이면 100. ΣE = 0이면 `insufficient_data`.

  **단계 5 — 폐쇄 비상구 동적 마스킹 (옵션)**
  ```
  C'_j,design(t) = C_j,design × M_j(t)      M_j ∈ {0, 1}
  P'_j,design(t) = C_j M_j / Σ_c C_c M_c   (재정규화)
  SEI(t) = (1 − ½ Σ_j |P_j,actual − P'_j,design(t)|) × 100
  ```
  모든 비상구 폐쇄 시(Σ C_c M_c = 0) → `insufficient_data`.

- **④ 출력**
  - `exit_metrics[]`: `exit_id, actual_count(E_j), design_capacity(C_j), actual_share, design_share`
  - 총 `sei` (0~100 또는 `insufficient_data`)
  - 시각화: 설계 통과용량 분포 · 실제 통과객체 분포 **이중 세로 바차트**
- **⑤ 레포 현황** (2026-07-14 기준)
  - 가상선 방향성 통과 카운팅(in/out, debounce) ✅ `system/metrics/engine.py:_exits`
  - 비상구별 다중 카운터 ✅ `system/metrics/engine.py` — exits dict, 카메라별 crossing
  - 설계 통과용량 자동 계산(`W_eff × q_design`) ✅ `webui/static/main/view_map.js:save()`
  - `q_design` 전역 파라미터 입력 ✅ `thresholds.q_design` + 맵 설정 임계값 UI
  - 분포비교 SEI 수식 ✅ `system/metrics/session.py:_sei()`
  - `insufficient_data` (ΣE=0) 예외 ✅ `session.py:_sei()` → `None` 반환
  - 이중 패널 세로 바차트 시각화 ✅ `webui/static/main/session.js:drawSeiBars()`
- **⑥ 잔여 과제**: 폐쇄 비상구 동적 마스킹(M_j 토글 UI) · 세션 중 실시간 SEI 라이브 업데이트 주기 튜닝.

## 8. 개발 완료 기준 (검증)

- **결정성**: 동일 입력·동일 설정 버전 → 항상 동일 결과.
- **역추적성**: 모든 지표는 최종 점수에서 원본 트랙 포인트·적용 파라미터까지 역추적 가능.
- **좌표 품질**: 카메라별 좌표변환 오차·유효영역 밖 객체 비율 확인 가능.
- **합성 자동 테스트**:
  - 권장 경로를 완전히 따른 궤적 → `EPFI = 100`
  - 임계밀도 미초과 → `CBS = 0`
  - 실제 출구 분포 = 설계 분포 → `SEI = 100`
  - 피난개시 조건이 정확히 유지시간 충족하는 데이터 → 예상 시각에 `t_e,start` 발생
- **예외 처리 명시**: 카메라 누락, ID 변경, 트랙 단절, 출구 왕복 통과, 경로 미배정, 실제 통과 0명(`insufficient_data`).
- **종합점수 분리**: 종합점수·A/B/C 등급은 개별 지표와 분리(D-8), 고객 승인 가중치 확정 후 적용.

## 9. 확정 필요 항목 (고객/추후)

인터뷰로 방식은 확정했으나, **구체 값·형식·정확도 목표**는 고객 확정이 필요하다.

1. **임계값 실제 기준치**: `v_th, a_th, r_th, Δt_hold, d_allow, ρcrit,k, w_k` (디폴트는 임의 설정, 고객 확정 필요 — D-6).
2. **CAD API 연동 형식**: 권장경로 자동산출(입력 분기 ②)의 실제 데이터 형식·프로토콜 (D-2).
3. **글로벌 ID 병합 아키텍처 시점**: 지금은 카메라별 local ID. 병합 도입 시점·정확도 목표·시간동기 허용오차·좌표변환 허용오차 (D-1).
4. **SEI 설계 총인원 값**: 비상구별 `C_j,design` 실제 값(사람이 입력) 및 평가 시간창 확정 (D-7).
5. **구역 분할·그래프 구체안**: 구역 개수·경계·노드그래프 연결 정의(수동), 그리드 셀 크기 (D-4·D-5).
6. **종합점수 가중치·등급 기준·개선 권고 규칙** (D-8).

> **핵심**: 개발 대상은 단순 검출 모델이 아니라
> `공통 공간 좌표계 + (카메라별) 궤적 + 이벤트 판정 엔진 + 4대 지표 계산 엔진 + 설정·검증 가능한 대시보드`
> 로 구성된 **피난 평가 데이터 시스템**이다.
