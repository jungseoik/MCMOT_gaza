# 08 · 속도·가속도·보정 로직 설명 

업로드(또는 RTSP 등록) → 세팅(ROI/보정) → 분석 화면에서 **속도·가속도·밀도·체류**가
어떻게 계산되는지 수식과 예시로 설명합니다. 코드는 `webui/speed.py`.

---

## 0. 한눈에

```
사람 박스 → 발끝점 → (보정으로) 미터 좌표 → 최근 1초 이동량 ÷ 실제 시간 = 속도
```

- **무엇을 재나**: 각 사람의 **발끝(바운딩박스 아래 중앙)** 위치. 발이 바닥에 닿으니
  지면 거리 계산의 기준점.
- **언제 재나**: **최근 1초(슬라이딩 윈도우)** 동안의 이동.
- **어떻게 미터로 바꾸나**: 세팅에서 고른 **보정 방식**(아래 4가지)이 픽셀↔미터를 정함.

---

## 1. 기본 공식 — 속도 = 거리 ÷ 시간

각 사람마다 최근 위치들을 시간과 함께 저장합니다: `(t, 발끝x, 발끝y)`.
윈도우(기본 1초)의 **처음점**과 **끝점**으로 계산:

```
dt        = t_끝 − t_처음                  (실제 경과 시간, 초)
거리_px    = √((x_끝−x_처음)² + (y_끝−y_처음)²)   (픽셀 이동거리)

거리_px < 2px 거나 dt ≤ 0  → 속도 0 (노이즈 제거)
```

그 다음 보정 방식에 따라:

| 보정 | 속도 공식 | 단위 |
|------|-----------|------|
| 없음 | `거리_px / dt` | **px/s** |
| 보정선(전역비율 ppm) | `(거리_px / ppm) / dt × 3.6` | **km/h** |
| 호모그래피 / Depth | `거리_m / dt × 3.6` | **km/h** |

- `ppm` = pixels per meter(미터당 픽셀 수). `거리_px / ppm` = 미터 이동거리.
- `× 3.6` = m/s → km/h.
- 호모그래피/Depth는 발끝을 **지면 미터 좌표**로 바꾼 뒤 그 위에서 미터 거리를 직접 잼.

> **왜 dt를 "실제 시간"으로 쓰나?** 파일은 모든 프레임을 처리하지만 RTSP는 따라가지
> 못해 프레임을 건너뜁니다. "프레임 수 ÷ fps"로 하면 RTSP에서 시간이 틀려 속도가
> 부풀려져요. 그래서 각 처리 프레임에 시각 도장을 찍고 그 차이를 dt로 씁니다.
> (파일은 `t = 프레임번호/fps`, RTSP는 실제 시계 → 둘 다 정확)

## 2. 가속도

각 사람의 **속도 변화율**:

```
가속도_i = |속도_지금 − 속도_직전| / (t_지금 − t_직전)
대시보드값 = 화면 내 모든 사람 가속도의 평균
```

- 단위는 "속도단위 / 초" (km/h당 초, 또는 px/s당 초) → 라벨은 `Δ/s`.
- 절댓값이라 가감속 모두 양수로 잡힘(움직임 급변 정도).

## 3. 픽셀 → 미터 보정 4가지 (세팅 화면 선택지)

여기가 핵심입니다. **"보정선 2점"과 "ROI 4점"은 역할이 다릅니다.**

### (a) 없음 → px/s
보정 안 함. 픽셀 단위 상대 속도. 비교는 되지만 실제 속도(km/h)·원근 보정 없음.

### (b) 보정선(2점) → 전역 km/h  ← "기준선"의 역할
- **2점을 찍고 그 사이 실제 거리(m)를 입력**합니다. 예: 바닥 타일 2칸이 2m라면 그 두 끝을 찍고 "2" 입력.
- `ppm = (두 점 사이 픽셀 길이) / (실제 미터)` → **화면 전체에 적용되는 단일 축척**.
- 즉 **"화면에서 N픽셀 = 1미터"라는 기준자(scale ruler)** 를 만드는 게 보정선의 역할입니다.
- ⚠️ 한계: **원근 보정 없음.** 화면 위쪽(먼 곳)과 아래쪽(가까운 곳)의 실제 축척이 다른데
  하나의 비율을 모든 곳에 쓰므로, 카메라가 비스듬하면 오차가 큽니다. (정면/평평한 경우엔 OK)

### (c) ROI 실측(4점) → 호모그래피 km/h (원근 보정)
- **ROI 4점을 바닥의 사각 구역 모서리로 찍고**, 그 구역의 **실제 가로·세로(m)** 를 입력.
- `cv2.getPerspectiveTransform(화면4점 → [[0,0],[가로,0],[가로,세로],[0,세로]] 미터)`
  로 **이미지→지면 미터** 변환(호모그래피 H)을 만듭니다.
- 발끝을 H로 지면 미터 좌표에 매핑 → 위치마다 다른 축척을 **자동 보정**(원근 해결).
- 점 순서: **좌상 → 우상 → 우하 → 좌하**.

### (d) Depth 자동 → 호모그래피 km/h (수동 측정 0)
- 첫 프레임을 Depth-Anything-3로 분석(미터 깊이) → **사람키 1.7m**로 초점거리 역산 →
  바닥 평면 RANSAC → 이미지→지면 호모그래피를 **자동 생성**.
- (c)의 4점 실측을 손으로 안 재고 AI가 만들어주는 셈. 결과는 **추정값**(사람키 가정).
- 자세한 건 [07-depth-mode.md](07-depth-mode.md).

> **ROI(4점)의 두 역할**: ① 측정 영역 필터(발끝이 ROI 안인 사람만 계산) ② 호모그래피
> 모드에선 그 4점이 지면 변환의 기준 사각형. (Depth/보정선 모드에선 ①필터로만 작동)

## 4. 다른 지표 정의

| 지표 | 정의 |
|------|------|
| **현재 인원(count)** | 지금 ROI(미설정 시 전체) 안의 추적 객체 수 |
| **세션 누적** | 분석 시작 후 ROI에 한 번이라도 잡힌 **고유 트랙 ID 수**. 신규 ID마다 +1, 잡 시작 시 0으로 리셋. (ID 스위치·재입장으로 과대될 수 있음) |
| **평균/최고 속도** | 현재 인원들의 속도 평균/최댓값 |
| **이동/정지** | 속도 > 임계값이면 이동. 임계: km/h 모드 0.5, px/s 모드 3 |
| **이동 비율** | 이동 인원 / 전체 × 100% |
| **밀도** | `인원 ÷ 면적`. 보정 시 **명/m²**(면적: 호모그래피=실측 m², 보정선=ROI px ÷ ppm²), 미보정 시 명/Mpx |
| **혼잡도(pill)** | 명/m² 기준: <0.4 여유 / <1.0 보통 / ≥1.0 혼잡 |
| **체류시간** | 각 사람의 `t_지금 − 처음_등장_t` (초). 평균/최대 표시 |

## 5. 슬라이딩 윈도우 (왜 "최근 1초")

매 프레임 순간 이동(프레임 1장 차이)으로 속도를 내면 박스 흔들림에 크게 출렁입니다.
그래서 **최근 1초 구간**의 처음↔끝으로 평균 내어 안정화합니다(`window_sec=1.0`).
- 길게(예: 2초) → 더 부드럽지만 반응 느림.
- 짧게 → 민감하지만 노이즈.

## 6. 정확도·한계 

- **보정선(전역비율)**: 원근 미보정 → 비스듬한 카메라에서 위치별 오차. 정밀하려면 호모그래피/Depth.
- **호모그래피/Depth**: 바닥이 평평하다고 가정. 계단·경사·비평면은 부정확.
- **Depth**: 절대 스케일이 사람키(1.7m) 가정 + 깊이 모델 정확도에 의존 → **추정값**.
- **프레임 스킵(RTSP)**: 경로가 급히 꺾이면 직선거리만 재서 약간 과소. 추적 연관(ID 스위치)도 늘 수 있음. dt는 정확.
- **세션 누적**: 고유 사람 수가 아니라 고유 ID 수(ID 스위치·재입장 시 중복 카운트).
- GT(정답)가 없으므로 모든 km/h는 **근사/추정**. 신뢰가 필요하면 보정선 실측으로 교차 검증.
