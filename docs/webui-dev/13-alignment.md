# 13. 방향성 정렬도 (Alignment)

요구사항([North Star](../requirements/CCTV-영상분석-엔진-필수추출정보.md)) 카테고리 3의 **방향성 정렬도**.
"사람들이 *권장 피난 방향대로* 움직이는가"를 한 숫자로 잡는 지표.

## 한 줄 정의
> 각 사람의 **이동 방향 단위벡터**와, 운영자가 지정한 **기준(피난) 방향 단위벡터** 사이의
> **코사인**. 속도 크기는 무시하고 **방향만** 본다. 구역 평균 = `avg_align`.

```
align = dir_obj · dir_ref      (둘 다 단위벡터 → 코사인, -1 ~ +1)
+1 정렬(같은 방향) · 0 직교(가로질러) · -1 역류(반대)
```

## opt-in — 그렸을 때만 동작
기준 화살표(`reference_vec`)를 **줬을 때만** 계산·표출된다. 안 주면 기존 속도/밀도 모드 그대로고
정렬도 관련 UI/지표는 전부 숨김(`has_align=false`). 매 영상마다 강제되지 않는다.

## 사용 (webui)
1. "속도/밀도" 모드 → **"정렬 방향 2점"** 버튼
2. 첫 프레임에 **출구 방향으로 꼬리→머리** 2점 클릭(파란 화살표)
3. 측정 시작 → 대시보드 **"Alignment 정렬도"** 카드 + 🗺 맵에 정렬색·기준 벡터 표출

파일에서 검증/배치: `tools/concat_viz.py vid.mp4 --align "tx,ty,hx,hy"` (원본 px, 꼬리→머리).

## 좌표계 (중요)
기준 벡터는 객체 이동벡터와 **같은 공간**에서 비교한다.
- 호모그래피(보정) 있으면 → 기준 화살표 끝점도 `_world()`로 변환해 **월드(미터) 방향**으로.
- 보정 없으면 → 둘 다 **이미지 평면** 방향(원근 보정 X, 데모용으론 충분).

## 색 기준 (현재 값 = MVP 임의 지정)
`webui/draw_utils.py::align_color(a)` — **연속 그라데이션 아님, 하드 3구간**:

| 색 | 조건(코사인 a) | 의미 | 사잇각 |
|----|----------------|------|--------|
| 🟢 녹 | `a > 0.4` | 정렬 | < ~66° |
| 🟡 황 | `-0.2 ≤ a ≤ 0.4` | 가로질러/애매 | ~66°–102° |
| 🔴 적 | `a < -0.2` | 역류 | > ~102° |
| ⚪ 회 | 방향 없음(정지) | — | — |

> ⚠️ 임계 **0.4 / -0.2 는 MVP 임의값**이다. 요구사항의 정렬 임계(보고서 G4)는 도메인 미정 —
> 확정되면 이 값으로 교체하거나 연속 그라데이션으로 바꾼다.

## 사잇각·코사인 a 는 어떻게 계산되나 (비전문가용 설명)

위 표의 "코사인 a"와 "사잇각"이 무엇인지, 전혀 모르는 사람도 이해할 수 있게 단계적으로 설명한다.

### 무엇과 무엇을 비교하나
화살표 **두 개**의 방향이 얼마나 비슷한지를 잰다.
- **화살표 ①(사람의 실제 이동 방향)**: 한 사람이 직전 구간 동안 실제로 움직인 쪽.
- **화살표 ②(기준 방향)**: 운영자가 "이쪽으로 대피해야 한다"고 지정한 권장 피난 방향.

우리가 알고 싶은 건 "이 사람이 **시키는 방향대로 가고 있나**"이고, 그건 곧 **두 화살표가
같은 쪽을 보는가**의 문제다. 속도가 빠른지 느린지(=화살표 길이)는 보지 않고 **방향만** 본다.

### 1단계 — 길이를 1로 통일 (단위벡터)
방향만 비교하려고 두 화살표의 **길이를 똑같이 1로** 맞춘다. 이렇게 길이를 1로 만든 화살표를
**단위벡터**라고 부른다.
- 예: 화살표가 오른쪽으로 3, 위로 4만큼 향했다면(좌표 `(3, 4)`), 길이는 피타고라스로
  `√(3² + 4²) = 5`. 각 성분을 길이로 나누면 `(3/5, 4/5) = (0.6, 0.8)` → 이게 길이 1짜리 단위벡터.

코드에서 사람의 이동 방향 `d`(`speed.py:_obj_map`)와 기준 방향 `ref_dir` 둘 다 이미 이렇게
길이 1로 정규화돼 있다.

### 2단계 — 코사인 a = 두 단위벡터의 "내적"
두 단위벡터의 **x끼리 곱하고, y끼리 곱해서 더한** 값이 코사인 `a`다.

```
a = (사람_x × 기준_x) + (사람_y × 기준_y)
```

길이를 1로 맞춰 놨기 때문에 이 한 줄의 결과가 곧 **두 화살표가 벌어진 각도의 코사인값**이
된다(고등학교에서 배우는 벡터 내적 = 길이 × 길이 × cos각도, 길이가 둘 다 1이라 cos각도만 남음).
결과는 항상 **-1 에서 +1 사이**.

- **+1** : 완전히 같은 방향 (시키는 대로 잘 감)
- **0** : 직각(90°)으로 가로지름
- **-1** : 정반대 방향 (역류, 거꾸로 감)

> 일상 비유: 나침반 두 개를 나란히 놓았을 때 같은 곳을 가리키면 `+1`, 한쪽이 90° 틀어지면
> `0`, 정반대를 가리키면 `-1`. `a`는 "두 나침반이 얼마나 같은 곳을 보나"를 숫자 하나로 나타낸 것.

### 3단계 — 사잇각(도, °)으로 바꾸기
"사잇각"은 두 화살표가 실제로 벌어진 **각도**다. 코사인 `a`와 사잇각 `θ`는 1:1로 연결된다.

```
a = cos(θ)        →        θ = arccos(a)        (arccos = 코사인의 역계산)
```

| 코사인 a | 사잇각 θ |
|:---:|:---:|
| 1.0 | 0° (같은 방향) |
| 0.5 | 60° |
| 0.4 | 약 66° |
| 0.0 | 90° (직각) |
| -0.2 | 약 102° |
| -1.0 | 180° (정반대) |

그래서 위 색 기준표의 **66° / 102°** 는 임계 코사인 **0.4 / -0.2** 를 각도로 환산한 값이다
(`arccos(0.4)≈66°`, `arccos(-0.2)≈102°`). 즉 색은 `a`로 가르지만, 사람이 직관적으로 읽으라고
각도를 같이 적어둔 것뿐이다. (참고: 현재 UI는 각도 수치를 직접 띄우지 않고 색/코사인으로 표시.)

### 한눈에 보는 예시
기준 방향이 "오른쪽"(`(1, 0)`)이라고 하자.
- 사람이 오른쪽 위로 `(0.6, 0.8)` 방향 이동 → `a = 1×0.6 + 0×0.8 = 0.6` → 사잇각 약 53° → 🟢 정렬.
- 사람이 위로 `(0, 1)` 이동(가로지름) → `a = 1×0 + 0×1 = 0` → 90° → 🟡 애매.
- 사람이 왼쪽으로 `(-1, 0)` 이동(역류) → `a = 1×(-1) + 0×0 = -1` → 180° → 🔴 역류.

구역 전체의 **평균 정렬도 `avg_align`** 는 이렇게 구한 사람별 `a` 를 (정지자 제외) **평균낸 값**이다.

## 산출 필드 (`SpeedEstimator.metrics`)
- `has_align` (bool) — 기준 벡터 활성 여부(UI 표출 게이트)
- `avg_align` (float|null) — 구역 평균 코사인. **이동 중 객체만**(정지=방향0 제외) 평균
- `ref_dir` ([dx,dy]|null) — 기준 단위벡터(맵 표출용)
- 객체별 `objects[].align` (float|null) — per-object 코사인

## 표출 위치
- **대시보드**: "Alignment 정렬도" 카드(Moving 다음). `avg_align` ±값·색. `has_align`일 때만.
- **2D 맵**: 객체 화살표를 정렬색으로 + **긴 기준 벡터(군중 무게중심에서, "기준 방향")**. (평균값은 맵에 수치로 안 띄우고 대시보드 카드로 — 맵 좌하단 텍스트는 가독성 이유로 제거)
- **영상(좌)**: 기준 화살표(EVAC DIR) + 박스 모서리 정렬 점.
