## 1. 목적

이번 점검의 목적은 다음과 같다. 7월 3주차에 신규 확정된 **4대 정량지표(IDR·EPFI·CBS·SEI)
요구사항**을 기준으로, 현재 레포에 이미 구현된 기능이 무엇을 충족하고 무엇이 비어 있는지를
코드 단위로 대조하여 **앞으로의 개발 범위를 확정**하는 것. 배경은 다음과 같다.

- 기존 북극성(5대 필수추출정보)은 단일 채널 기준 **대부분 충족** — 검출·추적, 호모그래피
  좌표 변환, 속도·방향, 밀도, 라인 통과 카운팅까지 동작 확인 완료
- 신규 요구사항은 그 산출물 **위에서 계산되는 4대 지표**가 궁극 산출물 — 기존 기능은
  지표 계산의 **부품(building block)** 으로 재배치
- 따라서 점검의 핵심 질문은 "부품이 있는가"가 아니라 **"부품이 지표 수식을 계산할 수 있는
  형태·개수·좌표계로 존재하는가"**

---

## 2. 점검 기준 및 방법

점검 기준은 요구사항 문서의 기능 요구 FR-01~FR-09와 4대 지표 수식이다. 방법은 다음과 같다.

- 각 FR·지표를 **구성 부품 단위로 분해**하고, 레포의 해당 구현 파일·라인 유무를 대조
- 충족도 3단계 표기: ✅ **충족**(그대로 사용 가능) / ⚠️ **부분**(로직은 있으나 형태·개수·범위
  확장 필요) / ❌ **미구현**(신규 개발)
- 인터뷰로 확정된 설계 결정(D-1~D-10, 요구사항 문서 §0) 반영 — 예: 멀티카메라 글로벌 ID
  병합은 최종 단계로 제외, 현재는 카메라별 local ID 유지가 요구 수준

## 3. 충족도 요약

전체 요약은 다음과 같다. **공통 기반(좌표 변환·속도·밀도·카운팅)은 견고, 4대 지표 계산층은
전면 신규 개발** 구간.

| 구분 | 충족 ✅ | 부분 ⚠️ | 미구현 ❌ |
|------|---------|---------|-----------|
| 공통 기반 (FR-01·02·08·09) | 호모그래피 변환, 맵 궤적, 실시간 지표 대시보드(JSON) | 좌표 품질 기록, 대시보드 오버레이, 재생 모드 | 멀티카메라 입력 집계·시간동기, 설정 JSON 영속화, EvaluationResult 저장·API |
| IDR (FR-03·04) | 속도 산출 | 정렬도(단일 벡터) | 다중 구역 polygon, 그리드 벡터 field, 공간 그래프, 피난개시 판정 엔진 |
| EPFI (FR-05) | 맵 좌표 궤적 | — | 경로 polyline, 점→경로 최근접거리, 시간적분 |
| CBS (FR-06) | 밀도 계산 로직 | 단일 ROI 한정 | 다중 병목영역, 임계초과 적분·가중치, 위험등급 |
| SEI (FR-07) | 라인 crossing·debounce | 단일 라인 한정 | 비상구별 다중 카운터, 설계 총인원 입력, 분포비교 수식 |

한 줄 결론: **지표 4개 모두 "부품은 절반 존재, 수식을 계산하는 엔진은 0%"** — 기존 기능의
다중화(구역 N개·라인 N개·경로 polyline)와 지표 계산층 신설이 이번 개발의 본체.

## 4. 기능 요구(FR) 충족도 상세

FR별 대조 결과는 다음과 같다.

| FR | 요구 내용 | 충족도 | 근거 (현재 구현 / 공백) |
|----|-----------|--------|--------------------------|
| FR-01 좌표 통합 | bbox 하단중심 → 왜곡보정 → 호모그래피 → 평면도 좌표 | ⚠️ 부분 | 발위치 호모그래피 변환 구현(`webui/speed.py:_world`, 수동 4점·캘리브선·Depth 자동보정 3모드). **공백**: 렌즈 왜곡 보정, 보정 버전·기준점 오차·유효영역 밖 좌표 기록 |
| FR-02 다중 카메라 궤적 | 시간 정규화 + 중복 제거 + 글로벌 ID | ⚠️ 부분* | 단일 카메라 궤적 완비. *D-1 확정으로 현재 요구 수준은 "멀티카메라 **입력** 수용 + 카메라별 local ID 유지" — 멀티 입력 집계 구조·`global_track_id` 필드 예약이 공백. ID 병합 자체는 최종 단계 |
| FR-03 피난 개시 판정 | `v_e·a_e·r_e` 동시 만족 `Δt_hold` 연속 유지 → `t_e,start` | ❌ | 부품: 속도 ✅(`speed.py`), 정렬도 ⚠️(단일 방향벡터 코사인 — 그리드 셀 대표벡터 field 필요). **판정 엔진 자체(조건 비율·유지시간·최초 시점) 미구현** |
| FR-04 IDR | 공간그래프 최단거리 ÷ 반응 지연시간 | ❌ | 구역 polygon·노드그래프·최단거리·`not_started` 처리 전부 미구현 |
| FR-05 EPFI | 경로까지 최근접거리 시간적분 정규화 | ❌ | 부품: 맵 좌표 궤적 ✅. **경로 polyline 모델(자유곡선 등록 UI·CAD 분기), 점→polyline 거리, 적분 미구현** |
| FR-06 CBS | 병목별 `∫max(0, ρ−ρcrit)·w dt` | ⚠️ 부분 | 밀도 `count/area_m2` 구현(`speed.py:_density`) — 단 **전역 단일 ROI 1개**. 다중 병목 polygon(면적·임계밀도·가중치별), 임계초과 시간적분, 위험등급 미구현 |
| FR-07 SEI | 비상구별 방향성 crossing → 분포비교 점수 | ⚠️ 부분 | `LineCounter` 구현(`webui/counter.py` — 방향성 crossing·마진 debounce·in/out) — 단 **라인 1개**. 비상구별 N개 동시 카운터, 왕복 재진입 debounce(최초 통과만 유효), 설계 총인원 `C_j` 입력, SEI 분포비교 수식, `insufficient_data` 처리 미구현 |
| FR-08 대시보드 | 평면도 오버레이 + 지표·추이 + 실시간/재생 | ⚠️ 부분 | 실시간 per-frame 지표 JSON(`server.py:/status`) + 맵 렌더(`map_render.py`) + 재생용 `replay_metrics` 보유. **공백**: 4대 지표 표시 자체(지표가 없으므로), 권장경로·병목·비상구 오버레이, 시간 추이 그래프, 5초 갱신 설정 |
| FR-09 저장·연계 | 원본 트랙~지표까지 저장 + JSON/CSV 내보내기 | ❌ | 현재 MOT txt 출력·잡별 인메모리 상태만. EvaluationResult 스키마 저장, 세션/평가 API, PBD 시뮬레이션 내보내기 미구현 |

## 5. 4대 지표별 부품 충족도

지표별로 계산에 필요한 부품을 분해하면 다음과 같다. (✅ 재사용 / ⚠️ 확장 / ❌ 신규)

### 5.1 IDR — 구역별 피난 반응 확산

| 부품 | 상태 | 비고 |
|------|------|------|
| 구역별 평균속도 `v_e(t)` | ⚠️ | 속도 산출은 ✅ — "구역별" 집계 구조가 공백 |
| 방향정렬도 `a_e(t)` | ⚠️ | 코사인 정렬도 ✅ — 기준이 단일 벡터 → **그리드 셀 대표벡터 field**로 교체 필요 |
| 다중 구역 polygon | ❌ | 현재 단일 ROI 1개 |
| 공간 노드그래프 + 최단거리 | ❌ | 수동 정의 그래프 + 다익스트라 수준 |
| 피난개시 판정(비율·유지시간) | ❌ | 신규 판정 엔진 |
| IDR 수식·`not_started` | ❌ | 판정 결과 위 단순 계산 |

### 5.2 EPFI — 경로 충실도

| 부품 | 상태 | 비고 |
|------|------|------|
| 객체별 맵 좌표 시계열 `P_i(t)` | ✅ | 호모그래피 변환 완비 |
| 권장경로 polyline (수동 등록) | ❌ | 자유곡선 화살표 등록 UI + config 저장 |
| 권장경로 (CAD API 분기) | ❌ | 형식 미확정(고객 확정 항목) — 후순위 |
| 점→polyline 최근접거리 `d_i(t)` | ❌ | 기하 연산 신규 |
| 시간적분·정규화·EPFI 수식 | ❌ | `d_allow` 파라미터 포함 |

### 5.3 CBS — 병목 혼잡 누적

| 부품 | 상태 | 비고 |
|------|------|------|
| polygon 내 인원·밀도 `ρ(t)` | ✅ | `count/area_m2` 로직 재사용 |
| 다중 병목영역 (면적·`ρcrit`·`w` 별) | ❌ | 단일 ROI → N개 병목 polygon 모델 |
| 임계초과 시간적분 `∫max(0,ρ−ρcrit)·w dt` | ❌ | 시계열 누적 신규 |
| peak_density·초과누적시간·위험등급 | ❌ | 지표 출력층 |

### 5.4 SEI — 비상구 활용 효율

| 부품 | 상태 | 비고 |
|------|------|------|
| 방향성 라인 crossing + debounce | ✅ | `LineCounter` 재사용 — 4대 지표 중 부품 성숙도 최고 |
| 비상구별 다중 카운터 | ❌ | 라인 1개 → 비상구 N개 동시 |
| 고유 통과(왕복 재진입 제외) | ⚠️ | 마진 debounce ✅ — ID별 "최초 통과만 유효" 로직 공백 |
| 설계 총인원 `C_j,design` 입력 | ❌ | 사람 입력 UI + 디폴트 (D-7) |
| SEI 분포비교 수식·`insufficient_data` | ❌ | 단순 계산층 |

## 6. 구현 필요사항 (우선순위)

공백을 의존 순서대로 배열하면 다음과 같다. P0가 없으면 P1 지표 계산이 불가한 구조.

### P0 — 공통 기반 (지표 4개 전부의 전제)

1. **설정 데이터 영속화(JSON)**: 구역 polygon·병목영역·비상구 라인·권장경로·노드그래프·
   임계값·설계 총인원을 버전 관리 config로 저장 (현재 전부 잡별 인메모리 → D-10 위반 상태)
2. **다중 공간 객체 모델**: 단일 ROI/단일 라인/단일 벡터 → **구역 N개·병목 N개·비상구 N개·
   경로 M개**를 하나의 2D 맵 좌표계 위에서 관리 (D-4)
3. **권장경로 polyline 등록(수동 분기)**: 평면도 줌인/줌아웃 + 자유곡선 화살표 등록 UI →
   그리드 셀 대표벡터 field 이산화 (D-2 분기 ①; CAD API 분기 ②는 형식 확정 후)
4. **판정 파라미터 UI**: `v_th·a_th·r_th·Δt_hold·d_allow·ρcrit·w` 입력 + 임의 디폴트 (D-6)

### P1 — 4대 지표 계산 엔진

5. **SEI** (부품 성숙도 최고 → 착수 1순위 권장): 다중 LineCounter + ID별 최초통과 debounce +
   `C_j` 입력 + 분포비교 수식
6. **CBS**: 다중 병목 밀도 시계열 + 임계초과 시간적분 + 위험등급
7. **EPFI**: 점→polyline 최근접거리 + 시간적분 정규화
8. **FR-03 피난개시 판정 + IDR**: 구역별 `v·a·r` 동시조건·유지시간 판정 + 노드그래프
   최단거리 + IDR 수식 (그리드 벡터 field 의존 → P0-3 뒤)

### P2 — 결과 계층·검증

9. **EvaluationResult 저장 + 최소 API**: 세션 생성 / 트랙 입력 / 평가 실행 / 지표 조회 /
   타임라인 조회 / JSON·CSV 내보내기
10. **대시보드 확장**: 평면도 위 궤적·경로·병목·비상구 오버레이 + 지표 시간 추이 +
    실시간·재생 모드(5초 갱신 설정)
11. **합성 자동 테스트**: 완전 추종 궤적 → `EPFI=100`, 임계 미초과 → `CBS=0`,
    설계 분포 일치 → `SEI=100`, 정확한 유지시간 → 예상 `t_e,start`
12. **FR-01 품질 기록**: 왜곡 보정, 보정 버전·기준점 오차·유효영역 플래그

### P3 — 최종 단계 (확정 대기 포함)

13. **멀티카메라 입력 집계 + 시간동기 정규화** (`global_track_id` 필드 예약 포함, D-1)
14. **CAD API 경로 자동산출 연동** (형식 고객 확정 후, D-2 분기 ②)
15. **글로벌 ID 병합** (기존 북극성 방침대로 전체 최종 단계)

## 7. 관찰 및 한계

점검 과정의 관찰과 이번 문서의 한계는 다음과 같다.

**강점**

- 좌표 변환(3모드 캘리브)·속도·밀도·라인 카운팅 등 **하위 부품의 재사용성 높음** — 지표
  엔진은 이 부품들의 조합·다중화로 대부분 구성 가능
- SEI는 `LineCounter`가 방향성·debounce까지 갖춰 **가장 빠른 완성 가능 지표**
