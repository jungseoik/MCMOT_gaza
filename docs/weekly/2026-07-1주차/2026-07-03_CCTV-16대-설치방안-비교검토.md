# CCTV 16대 추가 설치 방안 비교 검토

- **작성일**: 2026-07-03
- **대상**: 삼성화재 (C-Lab Outside — 투자운영파트 / 기업안전연구소)
- **요청**: CCTV **16대**(대상 층 8대 + 상층 8대) 추가 설치 가능 여부 문의
- **목적**: 설치 방식별 절차·비용·난이도·리스크를 정리해, **예산 범위에서 무엇이 가능/불가능한지**
  판단하고 PPT로 전달


> 비용은 현장 실사·정식 견적이 필요하여 **상대 비용(상/중/하)** 으로 표기. 실제 금액은 별도 견적.

---

## 1. 배경 및 대상

- 대상: **2개 층에 각 8대, 총 16대** 추가 설치.
- 용도: 피난대피훈련 시 영상분석(재실·이동·밀도·통과 등) 데이터 확보.
- 방식 후보 3가지 — ⓐ 유선(기존 VMS/NVR 연동), ⓑ 무선 CCTV, ⓒ 녹화본(사후 분석).
- **핵심 갈림길**: **실시간 관제·분석이 필요한가**(ⓐ·ⓑ) vs **사후 분석이면 충분한가**(ⓒ).
- **필수 전제 — 동일 시간축(시간 동기화)**: 분석 엔진이 **기존(유선) CCTV + 신규 16대**를 함께
  다루려면 모든 카메라가 **같은 시간축(동기화된 타임스탬프)** 을 공유해야 함 — 다중 카메라를 한
  시점으로 묶고(정합) 실시간 분석하는 **필수 조건**. → 이 관점에서 **유선(ⓐ)이 유리**, **무선(ⓑ)은
  정밀 동기 리스크**, **녹화(ⓒ)는 실시간 공유 불가**.

> **용어**: **RTSP** = 영상 스트림을 실시간 전송하는 프로토콜(영상 자체를 받아오는 통로).
> **ONVIF** = IP 카메라·VMS 상호연동 표준(기기 자동검색·설정·이벤트, RTSP 주소를 표준 방식으로 제공).
> **NTP** = 여러 장비의 시계를 한 기준 서버에 맞추는 시간 동기 방식.

---

## 2. 방법 ⓐ — 유선 CCTV (기존 VMS/NVR 연동)

IP 카메라를 유선(PoE)으로 설치하고 기존 관제(VMS)/녹화(NVR)에 채널을 추가, 분석 서버가 RTSP로 취득.

**절차**
1. 현장 실사 — 카메라 위치 16곳, **배선 경로**, 기존 VMS/NVR 사양·여유 채널·라이선스 확인
2. 배선 공사 — 네트워크(UTP Cat6/광), **PoE 스위치**(전원+데이터 겸용) 또는 전원선 별도, 배관/트레이
3. 카메라 설치·고정(천장/벽 마운트)·화각 조정
4. VMS/NVR 등록(ONVIF/RTSP), **라이선스 채널 추가**, 녹화 설정
5. 분석 서버 연동 — VMS/NVR의 RTSP URL → webui 실시간 연결
6. **네트워크 대역폭 검토**(16채널 동시), VLAN/방화벽

**구매·준비 리스트**

| 품목 | 수량 | 비고 |
|------|------|------|
| IP 카메라(PoE) | 16 | 해상도/화각/실내형 사양 결정 |
| PoE 스위치(기가, 16+포트) | 1~2 | 전원+데이터 |
| 네트워크 케이블(Cat6)·배관/몰딩·커넥터 | 일괄 | 층간·구간 거리에 비례 |
| NVR 또는 VMS 라이선스 채널 | 16ch | 기존 여유 없으면 추가 |
| 설치 부자재(마운트/브래킷) | 16 | — |
| 배선·설치 공사(외주) | 1식 | 최대 변수 |

**준비·고려**: 기존 VMS/NVR 호환(ONVIF)·여유 채널, 네트워크 대역폭·전기 용량, **건물 배선 인허가**(방화구획 관통 등), 층간 배선, 실증 종료 후 철거.

- **분석 엔진 관점**: 16채널 **동시 실시간 분석** 필요 → 현재 미완인 **다채널 스케일업**(실측상 15채널 수준 근거) + GPU 자원 전제.
- **시간축 동기화**: 기존 유선 CCTV와 **같은 VMS/NVR·NTP 서버**에 연결 → 신규 16대도 **동일 시간축
  공유가 가장 용이**(강점). 분석 엔진의 다중 카메라 정합에 유리.
- **난이도: 상** · **비용: 상** · **실시간성: 우수**
- **리스크**: 공사 기간·비용 큼, 건물주/시설 협의·인허가, 방화구획 관통 규정, 기존 VMS 라이선스/호환, 철거 원복.

## 3. 방법 ⓑ — 무선 CCTV

무선(Wi-Fi/LTE) IP 카메라로 배선 공사를 최소화, 전원만 확보. 무선 AP/라우터로 스트림을 관제·분석 서버로 전달.

**절차**
1. 현장 실사 — **전원 콘센트 위치**, Wi-Fi 커버리지·간섭·차폐(벽/철골) 확인
2. 전원 확보(콘센트/어댑터, 필요 시 전원선 증설)
3. 무선 인프라 구성 — 고성능 **무선 AP/공유기**(대역폭·채널 계획) 또는 **LTE 라우터+유심**
4. 카메라↔AP 연결, 스트림 수신처(무선 NVR/관제 PC/클라우드) 설정
5. **관제 수신** — 무선 스트림을 VMS/분석 서버가 RTSP로 수신, **시간 동기화(NTP)**
6. 대역폭·지연·끊김 테스트(16채널 무선 동시 부하)

**구매·준비 리스트**

| 품목 | 수량 | 비고 |
|------|------|------|
| 무선 IP 카메라(Wi-Fi 또는 LTE) | 16 | 실내형·전원 방식 결정 |
| 무선 AP/공유기(고성능·다중) 또는 LTE 라우터+유심 | 수 대 | LTE는 데이터 요금 발생 |
| 전원 어댑터/멀티탭 (필요 시 전원선) | 일괄 | 콘센트 부족 시 증설 |
| 무선 NVR 또는 수신 PC(선택) | 1 | 수신·동기화용 |
| 마운트/거치 | 16 | — |

**준비·고려**: **Wi-Fi 대역폭**(16채널 동시 스트리밍은 무선에 큰 부담), 간섭·차폐, 전원 확보, 관제에서 **무선 스트림 수신·시간 동기화** 구성.

- **분석 엔진 관점**: ⓐ와 동일 — 16채널 **동시 실시간 분석**(다채널 스케일업 전제). 무선 지연·끊김이 분석 안정성에 추가 변수.
- **시간축 동기화(핵심 약점)**: NTP 동기는 가능하나 **무선 전송 지연·지터(불규칙)·독립 클록**으로
  프레임 단위 정밀 동기가 어려움 → **기존 유선 CCTV와 동일 시간축을 맞추기 어렵고 오차·드리프트
  리스크**. 다중 카메라·기존 CCTV 정합이 필요한 실시간 분석엔 불리.
- **난이도: 중** · **비용: 중** · **실시간성: 중(무선 안정성·시간동기에 의존)**
- **리스크**: 무선 대역폭 한계로 16채널 동시 실시간 **화질 저하·끊김** 우려, 전파 간섭, 무선 보안(도청), LTE 시 데이터 비용, 시간 동기화 오차.

## 4. 방법 ⓒ — 녹화본 (실시간성 포기, 사후 분석)

독립형 녹화 캠(로컬 저장)을 설치해 훈련을 녹화하고, 파일을 회수해 분석 서버에서 **오프라인 분석**.

**절차**
1. 현장 실사 — 카메라 위치·전원
2. 전원 확보(배터리/어댑터)
3. 녹화 캠 설치(SD/내장 저장) + **카메라 간 시간 동기화**(시계 맞춤 — 다중 카메라 정합에 필수)
4. 훈련 녹화
5. 녹화 파일 회수(SD/USB) → 분석 서버 업로드 → 오프라인 분석

**구매·준비 리스트**

| 품목 | 수량 | 비고 |
|------|------|------|
| 녹화형 캠(보안/액션캠, 로컬 저장) | 16 | 실내형·해상도 결정 |
| 대용량 저장매체(SD카드 등) | 16 | 해상도×시간 기준 용량 산정 |
| 전원(배터리/어댑터/보조배터리) | 16 | 훈련 시간 커버 |
| 삼각대/거치대 | 16 | — |

**준비·고려**: **카메라 간 시간 동기화**(파일 타임스탬프 정렬 — 훈련 이벤트·다중 카메라 정합에 필수), 저장 용량 산정, 회수·업로드 워크플로.

- **분석 엔진 관점**: 파일 **순차 오프라인 분석**이라 **현재 단일 채널 엔진으로도 처리 가능**(동시 처리 불필요, 시간만 소요). → 엔진 측 추가 개발 부담 최소.
- **시간축 동기화**: 각 캠 **독립 시계** → 실시간 공유 불가. 녹화 후 **타임스탬프를 수동 정렬**해야
  하며 오차 존재. 기존 유선 CCTV와 **실시간 동일 시간축 공유는 불가**(사후 근사 정렬만).
- **난이도: 하** · **비용: 하** · **실시간성: 없음(사후만)**
- **리스크**: **실시간 관제·즉시 대응 불가**(대시보드 실시간 시연 불가), 카메라 간 시간 동기 오차, 저장 용량·회수 번거로움, 배터리 소진.

## 6. 예산 관점 판단 가이드

- **동일 시간축이 필수 조건**: 분석 엔진이 **기존 유선 CCTV와 신규 16대를 같은 시간축**으로 묶어야
  하므로, **무선(ⓑ)은 정밀 동기가 어려워 실시간 다중 카메라 분석에 불리**. 실시간이 필요하면
  기존 CCTV와 같은 NTP/VMS 도메인에 물리는 **유선(ⓐ)이 사실상 유일하게 안전**.
- **실시간 관제·대응·대시보드 시연이 필수**라면 → ⓐ(유선) 또는 ⓑ(무선). 단 ⓐ는 **공사비·기간**,
  ⓑ는 **16채널 무선 동시 대역폭**이 최대 제약. 두 방식 모두 **분석 서버의 다채널 실시간 처리
  (현재 미완, 15채널 수준 근거) + GPU 자원**이 전제 — 이 부분 미확보 시 실시간 16채널은 어려움.
- **PoC 분석·평가가 목적(사후 분석 허용)** 이면 → ⓒ(녹화본)가 **가장 저렴·빠르고 리스크 최소**.
  분석 엔진도 현행 그대로 사용 가능. 실시간 대시보드 시연만 포기.
- **예산 제약이 큰 경우 권장 순서**: ⓒ(녹화, 사후 분석)로 실증 → 필요 시 일부 구간만 ⓑ(무선)로
  실시간 시연 → 정식 운영 단계에서 ⓐ(유선) 검토.

## 7. 확인 필요 (미확정)

- 기존 **VMS/NVR 사양·여유 채널·라이선스**, ONVIF/RTSP 지원 여부
- 기존 CCTV **시간 동기화 방식**(NTP 서버 유무·주소) — 신규 16대를 같은 시간축에 맞추기 위한 전제
- 대상 층 **전원·네트워크·배선 여건**, 방화구획 관통 등 인허가
- 카메라 **사양**(해상도·화각·실내형)·설치 위치 16곳
- **실시간 시연 요구 수준**(관제 실시간 필요 vs 사후 분석 허용)
- 분석 서버 **GPU 자원**(16채널 실시간 시 증설 여부)
- 정식 **견적**(장비·공사·라이선스) — 방식 확정 후 산출
