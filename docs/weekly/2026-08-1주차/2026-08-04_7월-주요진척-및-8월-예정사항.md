## 당월(7월) 주요 진척사항

7월에는 6월의 **단일 카메라** 분석 엔진을 **여러 대 카메라를 공통 평면도 위에서 동시에 처리하는
멀티카메라 시스템**으로 전환하고, 그 위에서 **4대 피난 정량지표를 산출**하는 기능을 완성했습니다.
또한 **다채널 실시간 처리 성능을 대폭 끌어올리고**(1GPU당 4채널 → 16채널), **여러 층(N개 도면)**
운영과 **CAD 도면 자동 처리**까지 갖춰, 현장 실증에 필요한 기능 골격을 사실상 완성했습니다.

□ 멀티카메라 2D맵 분석 시스템 구축
  - 6월의 단일 영상 UI와 별개로, **여러 대의 CCTV(RTSP)를 등록해 하나의 공통 2D 평면도 위에서
    사람을 동시에 추적**하는 독립 시스템을 구축(포트 8900).
  - 사용 흐름: **① 맵(평면도) 설정 → ② 카메라 등록·매핑 → ③ 운영 뷰(실시간 지도) → ④ 경보 세션(지표 산출)**.
    카메라마다 영상 좌표를 도면 좌표로 변환(호모그래피)해 모든 카메라의 사람을 **한 평면도 위에**
    점·방향으로 표시.
  - 설정(도면·카메라·구역·경로 등)은 파일로 영속화되어, 시스템을 껐다 켜도 그대로 복원.

□ 4대 피난 정량지표(IDR·EPFI·CBS·SEI) 산출 기능 완성
  - 피난 훈련을 **수치로 평가**하는 4대 지표를 구현하고, 경보 세션(경보 시작~종료) 단위로 산출·저장.
    - **IDR (피난 반응 확산)** — 구역별로 사람들이 **실제로 대피를 시작한 시점**을 판정.
    - **EPFI (경로 충실도)** — 각 사람이 **권장 피난 경로를 얼마나 잘 따라갔는지**(경로 이탈 거리 누적, 0~100점).
    - **CBS (병목 혼잡 누적)** — 병목 구역이 **임계 밀도를 넘은 정도와 시간**을 누적한 위험도.
    - **SEI (비상구 활용 효율)** — 비상구별 **실제 이용 인원 분포가 설계 용량에 얼마나 균형 있게** 분산됐는지(0~100점).
  - 지표 계산에 쓰는 **모든 임계값은 화면에서 관계자가 직접 입력**하도록 하여(하드코딩 없음),
    고객 확정 기준을 그대로 반영.
  - 자체 검증(합성 데이터 기반 단위 테스트 86종 통과)으로 지표 산출의 **정확성·재현성** 확보.

□ 다채널(여러 대 카메라) 동시 처리 성능 대폭 향상
  - 6월 목표였던 다채널 확장에 착수, **처리 방식을 전면 개선**. 기존에는 카메라마다 영상을 GPU로
    디코딩한 뒤 다시 CPU로 꺼내 한 장씩 순서대로 추론(GPU→CPU 왕복)했으나, **디코딩부터 추론까지
    GPU 안에서 처리하고 여러 카메라를 한 번에 묶어(배치) 추론**하는 구조(DeepStream 기반)로 전환.
  - 실측 결과, **GPU 1장당 채널당 5fps 유지 한계가 4채널 → 16채널로 약 4배** 향상
    (총 처리량 약 21fps → 79fps). 채널을 더 붙여도 멈추지 않고 프레임 속도만 완만히
    낮아지도록(가장 오래된 프레임을 버리는 방식) 안정화.
  - 두 방식의 **출력이 사실상 동일함을 정량 검증**(검출 위치 일치율 99.4%, 추적 결과 일치율
    98.95%) — 즉 **속도만 4배 빨라지고 결과 정확도는 그대로**.
  - 기존 방식과 새 방식을 **설정 한 줄로 전환**(안전한 롤백 보장).

□ 여러 층(N개 도면) 동시 운영 기능
  - 건물은 여러 층으로 구성되므로, **한 현장에 여러 층 도면을 등록하고 카메라를 각 층에 배치**해
    **운영 화면에서 층을 전환하며** 보는 기능을 개발(각 층 독립 좌표계, 4대 지표도 층별 산출).
  - 3개 층 규모까지 대응하도록 설계, **17층 도면과 이를 복제한 18층 구성으로 라이브 검증** 완료
    (층 전환 시 각 층 카메라·객체·지표가 정확히 분리 표시).

□ CAD 도면 자동 처리 및 피난 경로 자동 생성
  - CAD 도면(DWG/DXF)을 **웹에서 직접 불러와 정리(문 열기)·비상구 지정·검증**하고, 그대로 2D맵으로
    적용하는 **도면 편집기**를 구축(별도 화면).
  - 비상구만 지정하면 **최적 피난 경로가 자동 계산**되어(출구 기준 거리장 방식) 운영 화면의 권장
    피난 경로로 **자동 반영**되고, 출입구 통과선도 함께 세팅 → 관리자가 경로를 일일이 그릴 필요 없음.
  - 상용 변환 프로그램(ODA) 없이도 **오픈소스만으로 도면 변환이 되도록** 하여, 새 서버에서도
    추가 라이선스 없이 재현 가능.

□ 검출·표출 정확도 및 안정성 개선
  - 카메라마다 **검출 신뢰도 기준을 개별 설정**하고, 도면에서 **유효 분석 영역(다각형)을 지정**해
    사람이 다니지 않는 구역(의자·집기 등)의 **오탐을 제거**하는 기능을 추가.
  - 다채널 부하 상황에서 드물게 발생하던 **추적 붕괴(깨진 영상 프레임이 오검출을 유발하던 문제)**의
    근본 원인을 찾아 해결.

□ 현장 실증·타 서버 이관을 위한 재현 환경 정비
  - 실증 서버(GPU 4장, 다른 기종)로의 이관을 대비해, **모델·영상·도면 등 대용량 자산을
    중앙(HuggingFace)에서 관리**하고, 새 서버에서 **명령 몇 줄로 환경을 구성**할 수 있도록
    설치 절차·다운로드 스크립트를 정비.
  - 아무것도 없는 우분투 서버를 가정해 **실제 컨테이너에서 재현을 검증**하여, 실증 현장에서 갑자기
    동작하지 않는 상황을 사전에 차단.

## 익월(8월) 주요 예정사항

□ **CJ제일제당 현장 실증 수행** *(8월 말~9월 초 실증 대비)*
  - 현장 CCTV 구성·분석 구역 정의·캘리브레이션(카메라 화면을 실제 도면 좌표에 맞추는 보정)을 확정.
  - 규모별(예: 50/100/200인) 피난 시나리오를 실제 훈련에 적용해 4대 지표를 산출.

□ **실증 서버(GPU 4장) 이관 및 성능 재측정**
  - 실증 서버는 현재 서버와 GPU 기종이 달라, 추론 엔진을 그 서버에 맞게 재빌드하고
    **채널당 처리 성능을 재측정**해 필요한 GPU 대수를 확정(최종 목표 50~60채널).

□ **종합평가(KPI) 및 회차 비교 기능**
  - 4대 지표를 넘어 훈련 전체를 평가하는 지표(총 대피 시간·구간별 통과 시간·최대 혼잡도·
    병목 구간 등)를 산출하고, **회차별로 비교**하는 대시보드 기능 개발.

□ **녹화본 재생(리플레이) 모드**
  - 실시간뿐 아니라 **저장된 훈련 영상을 다시 돌려보며** 지표를 확인하는 기능 —
    훈련 종료 후 분석·보고에 활용.

□ **검출·거리 측정 정확도 고도화**
  - 사람이 밀집하거나 멀리 있을 때 놓치는 인원 감소, 원거리 거리 측정 오차 보정.

□ **카메라 간 동일 인물 연결(Multi-Camera ID) 착수 검토**
  - 여러 카메라에 걸쳐 나타나는 **같은 사람을 하나로 연결**하는 최종 단계 기능의 설계 검토
    (현재는 카메라별 개별 추적 — 층·현장 규모 확정 후 진행).
