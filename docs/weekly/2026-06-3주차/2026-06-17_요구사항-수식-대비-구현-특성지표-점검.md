## 1. 목적

이 점검의 목적은 다음과 같다. 요구사항이 명세한 산출 수식과, 우리가 자체 구현해 실제
산출하는 특성지표를 나란히 대조해 **무엇이 충족됐고**, **요구사항에 명시는 없으나 자체
구현한 것**이 무엇인지 구분. 각 지표는 **맨 오른쪽 칼럼에 실제 산정 수식**을 함께 명시.

범례: ✅ 충족 · ◐ 부분 충족 · ❌ 미충족 · 🅐 요구사항 미언급(자체 구현).
좌표 표기 — 발끝점 `foot=((x1+x2)/2, y2)`, 월드좌표 `W=H·foot`(호모그래피), `Δt`=윈도우 실경과초.

## 2. 요구사항 수식 대비 구현

요구사항 5개 카테고리별로 명세 지표와 구현을 대조한 결과는 다음과 같다.

### 2.1 객체 인식 및 고유 ID 추적

| 요구사항 지표 | 충족 | 구현 지표 / 위치 | 산정 수식 |
|---|:---:|---|---|
| 대표점 픽셀 좌표(하단중심 등 최소 1종) | ✅ | 발끝점(bbox 하단중심) `speed.py:_foot`, `counter.py:_foot` | `foot = ((x1+x2)/2, y2)` |
| 시계열 고유 ID 궤적 | ✅ | BoostTrack++ MOT + per-ID 시간 큐 `speed.py:update` | id별 `deque[(t, fx, fy)]`, `window_sec` 초과분 폐기 |
| Multi-Camera ID 병합 ⚠️(최종 단계) | ❌ | 미구현(단일 카메라 동작) | — (요구사항도 최종 단계로 명시) |

### 2.2 실제 평면도 좌표 기반 공간 위치

| 요구사항 지표 | 충족 | 구현 지표 / 위치 | 산정 수식 |
|---|:---:|---|---|
| 호모그래피 도면 2D 좌표 실시간 변환 | ◐ | 지면 미터 좌표 `speed.py:_world` (H: 4점 실측 또는 Depth 자동) | `W = perspectiveTransform(foot, H)` |
| └ 캘리브레이션 파라미터 산출 | ✅ | Depth 기반 자동 캘리브 `depth_ground.py` | focal `f = median(h_px·Z / 1.7)`, 지면 RANSAC `n·P=d`, `H=getPerspectiveTransform(4 img→ground)` |

> ◐ 사유: 픽셀→지면 미터 변환은 동작. 단 **실제 건물 평면도(도면)와의 정합**은 미적용
> (현재는 ROI 실측·Depth 기준의 로컬 ground 좌표).

### 2.3 실시간 이동속도 및 방향 벡터

| 요구사항 지표 | 충족 | 구현 지표 / 위치 | 산정 수식 |
|---|:---:|---|---|
| 개별 이동속도 | ✅ | `speed.py:_speed` | 호모그래피: `‖W₁−W₀‖/Δt·3.6` (km/h) · 글로벌: `(‖p₁−p₀‖/ppm)/Δt·3.6` · 미보정: `‖p₁−p₀‖/Δt` (px/s) |
| 개별 이동 방향 벡터 | ✅ | `speed.py:_obj_map` | `d = (W₁−W₀)/‖W₁−W₀‖` (단위벡터) |
| 구역 평균 이동속도(절대값 평균) | ✅ | `metrics.avg` | `avg = Σ speedᵢ / n` (ROI 내 present) |
| 방향성 정렬도(코사인·구역 평균) | ◐ | `_obj_entry.align`, `metrics.avg_align` | `align = d · r` (r=권장방향 단위벡터), `avg_align = mean(alignᵢ, 이동객체만)` |

> ◐ 사유: **코사인 유사도**는 산출. 요구사항의 **사잇각(deg)** 은 미산출(코사인만 표출).

### 2.4 구역별 객체 점유 및 밀도

| 요구사항 지표 | 충족 | 구현 지표 / 위치 | 산정 수식 |
|---|:---:|---|---|
| 구역별 실시간 재실자 수(기하 포함 판정) | ◐ | `metrics.count`, `speed.py:_in_roi` | `count = (pointPolygonTest(ROI, foot) ≥ 0 인 객체 수)` |
| 병목영역 실시간 밀도(바닥면적 대비) | ✅ | `metrics.density`, `speed.py:_density` | `density = n / area_m²`, `area_m² = shoelace(perspectiveTransform(ROI, H))` 또는 `area_px / ppm²` |

> ◐ 사유: 포함 판정·카운팅은 동작. 단 **ROI 1개 기준**이며 문·계단 등 **다구역 동시 정의**는 미지원.

### 2.5 시간 기반 이벤트 및 통과 카운팅

| 요구사항 지표 | 충족 | 구현 지표 / 위치 | 산정 수식 |
|---|:---:|---|---|
| 가상선 통과 이벤트 감지 | ◐ | `counter.py:update` (부호거리 측면 전환) | 부호거리 `s = (AB×AP)/‖AB‖`, 부호 전환 + 선분 근처 → in/out 집계 |
| 비상구별 고유 통과 인원(중복 제외, 최초 통과만) | ❌ | 미구현(통과마다 무조건 +1, dedup 없음) | 현재 `in/out += 1` (왕복·재진입 중복 집계) |
| 구역별 피난 개시 시점(임계 지속 최초 타임스탬프) | ❌ | 미구현 | — |
| 가상선 통과 타임스탬프 = 피난 완료 시점 기록 | ❌ | 미구현(누적 카운트만, 객체별 시점 미기록) | — |

## 3. 자체 구현 특성지표 (요구사항 미언급)

요구사항에 직접 명시는 없으나 분석·운영 편의를 위해 자체 구현해 산출하는 지표는 다음과 같다.

| 🅐 자체 구현 지표 | 구현 위치 | 산정 수식 | 비고 |
|---|---|---|---|
| 누적 인원(cumulative) | `metrics.cumulative` | `cumulative = (지금까지 본 고유 ID 수, seen_ids)` | 연인원 추정 |
| 체류시간(dwell) | `metrics.avg_dwell / max_dwell` | `dwell = last_t − first_seen` (초) | 요구사항 5번은 통과시점, 체류 지표 자체는 미언급 |
| 가속도(accel) | `metrics.accel` | `accel = mean(abs(Δspeed) / Δt)` | 이동 급변 감지 |
| 이동/정지 분류·이동비율 | `metrics.moving / stationary / moving_ratio` | `moving = (speed > thresh 인원)`, `moving_ratio = moving/n·100` (thresh: km/h 0.5, px/s 3) | 정성 상태 표시 |
| 혼잡도 레벨(level) | `metrics.level` | 명/m² 기준 `<0.4 여유 / <1.0 보통 / ≥1.0 혼잡` | 밀도 → 3단계 분류 |
| 현재 재실(occupancy) + 음수 경보 | `counter.py:metrics` | `occ = start + in − out`, `occ < 0 → 경보` | 요구사항 통과카운팅에서 파생 확장 |
| Depth 기반 자동 캘리브(사람키 앵커) | `depth_ground.py` | `f = median(h_px·Z / 1.70)` 등 | 요구사항은 캘리브 허용, 자동화 방식은 자체 |

## 4. 종합 충족 현황

카테고리별 충족 현황을 집계한 결과는 다음과 같다.

| 카테고리 | ✅ 충족 | ◐ 부분 | ❌ 미충족 |
|---|:---:|:---:|:---:|
| 1. 객체 인식·ID 추적 | 2 | – | 1 (Multi-Cam, 최종 단계) |
| 2. 평면도 좌표 | 1(캘리브) | 1(도면 정합) | – |
| 3. 이동속도·방향 | 3 | 1(사잇각) | – |
| 4. 점유·밀도 | 1(밀도) | 1(다구역) | – |
| 5. 시간 이벤트 | – | 1(통과 감지) | 3 |

- **강한 축**: 카테고리 1·3·4 — 추적·속도·방향·밀도의 **핵심 수식은 모두 산출**.
- **약한 축**: 카테고리 5 — 통과 **감지**는 되나 **고유 dedup·피난 개시·완료 시점 기록**이 미구현.
- 카테고리 2는 변환 수식은 충족이며, **실제 건물 도면 정합**만 과제.

## 5. 관찰 및 다음 단계

- **충족 핵심**: 발끝점·궤적·속도(km/h)·방향벡터·구역 평균속도·밀도(명/m²)·코사인 정렬도까지
  북극성 핵심 수식을 실제 코드로 산출.
- **현재 한계**:
  - 카테고리 5의 시간 이벤트(피난 개시 시점, 고유 통과 dedup, 완료 시점 기록) 미구현.
  - 정렬도는 코사인만(사잇각 미산출), ROI 1개(다구역 미지원), 도면 정합 미적용.
- **다음 단계**:
  1. 비상구 통과 **고유 ID dedup**(최초 통과만 유효) + 객체별 **통과 타임스탬프 기록**.
  2. 구역 평균속도·정렬도·밀도 임계의 시간 충족 판정 → **피난 개시 시점** 산출.
  3. 정렬도에 **사잇각(deg)** 병기, **다구역 ROI** 동시 정의 지원.

## 6. 통합 특성지표 표

전체 특성지표를 한 표로 통합한 결과는 다음과 같다. 각 지표가 **실제 요구사항인지(✅요구사항 /
🅐자체)**, **구현 상태(✅구현 / ⏳예정)**, 그리고 **산정 수식**을 함께 표기한다.
좌표 표기 — `foot=((x1+x2)/2, y2)`, `W=H·foot`(호모그래피 지면 미터), `Δt`=윈도우 실경과초.

| 특성지표 | 요구사항 여부 | 구현 상태 | 산정 수식 | 수식 설명 |
|---|:---:|:---:|---|---|
| 대표점(발끝 좌표) | ✅요구사항 | ✅구현 | `foot = ((x1+x2)/2, y2)` | 사람 박스 아래 변 중앙점. 바닥에 닿는 지점을 위치 기준으로 사용 |
| 시계열 ID 궤적 | ✅요구사항 | ✅구현 | id별 `deque[(t, fx, fy)]`, `window_sec` 초과분 폐기 | 같은 사람에 같은 id 유지, (시간·발끝x·발끝y)를 시간순 저장(오래된 건 버림) |
| 평면 좌표(맵) `mx,my` | ✅요구사항 | ✅구현 | `(mx,my) = perspectiveTransform(foot, H)` (미보정 시 이미지 발끝 px) | 화면 속 발끝점을 H로 실제 바닥 미터 좌표(위에서 본 2D)로 변환 |
| 개별 이동속도 | ✅요구사항 | ✅구현 | km/h `‖W₁−W₀‖/Δt·3.6` · px/s `‖p₁−p₀‖/Δt` | 최근 구간 이동거리 ÷ 걸린 시간. 보정 시 미터→km/h, 미보정 시 픽셀/초 |
| 이동 방향 벡터 | ✅요구사항 | ✅구현 | `d = (W₁−W₀)/‖W₁−W₀‖` (단위벡터) | 시작→끝을 잇는 화살표를 길이 1로 만든 것(어느 쪽으로 가는지만) |
| 구역 평균속도 | ✅요구사항 | ✅구현 | `avg = Σ speedᵢ / n` | 구역 안 모든 사람 속도를 더해 인원수로 나눈 평균 |
| 방향성 정렬도 | ✅요구사항 | ✅구현(코사인) | `align = d·r` (r=권장방향), `avg_align = mean(align, 이동객체만)` | 이동 방향과 권장 대피 방향의 일치도(코사인 −1~+1). 상세는 13-alignment |
| 최고 속도 | 🅐자체 | ✅구현 | `max(speedᵢ)` | 구역 안에서 가장 빠른 사람의 속도 |
| 가속도 | 🅐자체 | ✅구현 | `mean(abs(Δspeed) / Δt)` | 속도 변화량 크기 ÷ 시간을 사람별로 구해 평균(급변 감지) |
| 현재 인원(구역 재실자) | ✅요구사항 | ✅구현 | `count = (pointPolygonTest(ROI, foot) ≥ 0 인 객체 수)` | 발끝점이 관심구역(ROI) 다각형 안에 들어온 사람 수 |
| 밀도 | ✅요구사항 | ✅구현 | `density = n / area_m²`, `area_m² = shoelace(perspectiveTransform(ROI, H))` 또는 `area_px / ppm²` | 인원 ÷ 실제 바닥면적(m²). 면적은 ROI를 미터로 바꿔 다각형 넓이(shoelace) → 1m²당 명 |
| 혼잡도 레벨 | 🅐자체 | ✅구현 | 명/m² `<0.4 여유 · <1.0 보통 · ≥1.0 혼잡` | 밀도를 보기 쉽게 여유/보통/혼잡 3단계로 분류(0.4·1.0 경계) |
| 이동/정지 수 | 🅐자체 | ✅구현 | `moving = (speed > thresh 객체 수)` (thresh: km/h 0.5, px/s 3) | 일정 속도를 넘으면 '이동', 아니면 '정지'로 분류한 인원 수 |
| 이동 비율 | 🅐자체 | ✅구현 | `moving_ratio = moving / n · 100` | 전체 중 이동 중인 사람 비율(%) |
| 누적 인원 | 🅐자체 | ✅구현 | `cumulative = (고유 ID 누적 수, seen_ids)` | 지금까지 한 번이라도 등장한 서로 다른 id 개수(연인원) |
| 체류시간(dwell) | 🅐자체 | ✅구현 | `dwell = last_t − first_seen` (초) | 한 사람이 처음 보인 시각부터 지금까지 머문 시간 |
| 가상선 통과 IN/OUT | ✅요구사항 | ✅구현 | 부호거리 `s = (AB×AP)/‖AB‖`, 부호 전환 + 선분 근처 → in/out 집계 | 선 기준 어느 쪽인지를 부호거리로 보고, 반대쪽으로 넘으면 통과(안쪽 IN·바깥 OUT) |
| 현재 재실(occupancy) | 🅐자체(파생) | ✅구현 | `occ = start + in − out`, `occ < 0 → 경보` | 시작 인원 + 들어온 수 − 나간 수. 음수면 집계 오류로 보고 경보 |
| 비상구 고유 통과(dedup) | ✅요구사항 | ⏳예정 | 고유 ID '최초 통과'만 유효(현재는 왕복·재진입 중복 집계) | 같은 사람이 왔다 갔다 해도 최초 1회만 집계(중복 제거) |
| 피난 개시 시점 | ✅요구사항 | ⏳예정 | 평균속도·정렬도·임계충족비율 ≥ 기준 상태가 지속시간 이상 유지된 최초 timestamp | 속도·정렬도 기준을 동시에 넘은 상태가 일정 시간 지속된 첫 순간 |
| 통과 타임스탬프(완료 시점) | ✅요구사항 | ⏳예정 | 객체별 통과 순간 `t` 기록 = 피난 완료 시점 | 사람마다 선을 넘은 시각을 기록 = 그 사람의 피난 완료 시각 |
| Multi-Camera ID 병합 | ✅요구사항(최종) | ⏳예정 | 외형·이동 방향·카메라 간 이동시간으로 동일 객체 ID 통합 | 여러 카메라에 나뉘어 잡힌 같은 사람을 하나의 id로 합침 |

## 7. 수식 기호 설명

위 표 `산정 수식` 칼럼에 공통으로 쓰는 기호의 뜻은 다음과 같다(지표별 의미는 표의
`수식 설명` 칼럼 참조).

- **발끝점 `foot`** : 사람 박스의 **아래 변 중앙점** `((x1+x2)/2, y2)`. 바닥에 닿는 지점이라
  위치·거리 기준으로 사용(머리나 박스 중심보다 바닥 위치가 정확).
- **호모그래피 `H`** : 카메라 화면의 픽셀 위치를 **실제 바닥 평면의 미터 좌표**로 바꿔 주는
  변환표(3×3 행렬). 위에서 내려다본 도면 좌표를 만드는 열쇠.
- **월드 좌표 `W = H·foot`** : 발끝점을 `H`로 바꾼 **실제 바닥 좌표(미터)**. `W₀`=구간 시작점,
  `W₁`=구간 끝점. 보정을 안 했으면 대신 이미지 픽셀 좌표 `p`(`p₀/p₁`)를 그대로 사용.
- **거리 `‖A−B‖`** : 두 점 A·B 사이 **직선거리**. 피타고라스 `√(Δx² + Δy²)`.
- **시간 `Δt`** : 비교한 두 시점 사이 **실제 흐른 시간(초)**.
- **`n`** : 지금 구역 안 사람 수. **`id`** : 추적이 사람마다 붙이는 고유 번호.
- **`ppm`** : 1미터가 몇 픽셀인지(스케일). 보정선 2점으로 구함. **`ROI`** : 분석 관심 구역(다각형).

- **부호거리 `s`** : 가상 통과선 기준 어느 쪽에 있는지를 +/−로 나타낸 값. 부호가 바뀌면 선을 넘은 것.
- **shoelace** : 다각형 꼭짓점 좌표만으로 넓이를 구하는 공식(밀도의 바닥면적 계산에 사용).
