## 1. 배경과 목표

현재 webui는 "영상/RTSP 1개 = 잡 1개, 동시 1잡(`_model_lock`), 전부 인메모리"의 PoC 구조.
이를 **여러 카메라가 등록되어 공통 2D 맵 위에서 상시 동작하는 시스템**으로 전환한다.

- 기존 UI는 유지하고 **첫 페이지(main 탭)를 시스템 화면으로 개편** — 기존 단일영상 PoC 흐름은 별도 탭으로 보존
- 카메라 RTSP 등록 → 카메라마다 **공통 2D 맵과의 매핑(호모그래피)** 설정 → 카메라 1대 설정 완료 후 다음 카메라 등록 — 반복
- 공통 2D 맵 위에 **피난대피 경로·병목(임계치)·출입구·구역** 등 기존 기능 요소를 모두 배치, 전체 로직이 맵 좌표계에서 동작
- 등록된 전체 카메라의 RTSP가 **상시 순환 처리**(디코드→추론→맵 투영→지표)
- **실시간 카메라 영상 오버레이 표출은 하지 않는다** — 산출은 2D 맵 표출(데이터)뿐. 카메라 원본은 셋업 시 첫 프레임/온디맨드 스냅샷만

## 3. 시스템 요구사항

### 3.1 카메라 관리
- RTSP URL로 카메라 등록/수정/삭제 (이름·URL·활성 여부·분석 fps)
- 등록 시 연결 테스트 + 첫 프레임 스냅샷 반환 (셋업용)
- 카메라별 상태 조회: 연결됨/재접속 중/끊김, 수신 fps, 마지막 프레임 시각
- RTSP 끊김 시 자동 재접속 (지수 백오프 5→10→20→40→60s, 3중 신호: EOS/stall/error)

### 3.2 공통 2D 맵
- 사이트당 맵 1장: 이미지 업로드 + 축척(맵 위 2점 + 실거리 m → m/px). cad-convert 메타 JSON 존재 시 자동
- 맵 위 공간 요소 드로잉·저장 (모두 맵 px 좌표, m/px로 실단위 환산):
  - **피난대피 경로**: 자유곡선 polyline (다중 등록 가능)
  - **구역(zone)**: polygon N개
  - **병목영역**: polygon N개 + 임계밀도(명/m²) + 가중치
  - **출입구/비상구**: 방향성 통과선 N개 (+ 설계 인원, 후속 SEI용 필드 예약)

### 3.3 카메라 ↔ 맵 매핑
- 카메라 첫 프레임 ↔ 맵 이미지에 대응점 4점 이상 클릭 → 호모그래피 산출 (기존 "지도 정합" UI 재사용)
- 카메라별 유효영역(ROI polygon, 카메라 px) — 밖의 검출은 제외
- 매핑 저장 → 즉시 반영 (서버 재시작 없이 카메라별 활성/비활성 전환)

### 3.4 처리 파이프라인 (상시)
- 활성 카메라 전체: NVDEC 디코드 → analyze_fps로 시간 게이트 → 공유 프레임 큐(oldest-drop) → 단일 분석 스레드
- 분석: TRT 검출(공유) → 카메라별 BoostTrack 트래커(ID 격리) → 발끝점 → 카메라별 H로 맵 좌표 변환
- 지표(맵 좌표계): 객체별 속도·방향, 경로 방향 정렬도, 구역별 인원·밀도, 병목 임계 초과 여부, 통과선 in/out 카운트
- 산출: 최신 맵 상태(JSON)를 SSE로 송출 + 프론트 canvas 렌더. 카메라 주석 영상 없음

### 3.5 영속화·복원
- `data/sites/<site_id>/site.json`(맵·축척·경로·구역·병목·출입구·임계값) + `cameras/<cam_id>.json`(URL·H·ROI·fps)
- 서버 재시작 시 설정 자동 로드 → 활성 카메라 자동 기동
- 설정 변경 시 파일 저장 (git으로 버전 추적 가능)

## 4. 아키텍처

### 4.1 모듈 구조 (신규 `system/` 패키지)

```
system/
  config/        # site.json·cameras/*.json 스키마(pydantic)·로드/저장
  ingest/        # 카메라별 GStreamer 파이프라인(NVDEC), FrameQueue(oldest-drop),
                 # SourceReconnector(EOS/stall/error + 백오프), analyze_fps 게이트
  tracking/      # 공유 TRT 검출·ReID + 카메라별 트래커 인스턴스, 분석 스레드(단일)
  mapping/       # 카메라별 호모그래피 → 맵 좌표, 유효영역 필터, 맵 축척
  spatial/       # 구역/병목/통과선/경로 지오메트리 (point-in-polygon, 선분 crossing,
                 # 점→polyline 거리 — 후속 4대 지표가 그대로 쓰는 공용층)
  metrics/       # 맵 좌표 기반 지표: 속도·정렬도·구역 인원/밀도·카운팅 (기존
                 # speed.py/counter.py 로직 이식·다중화)
  api/           # FastAPI 라우터: 카메라 CRUD·맵·매핑·드로잉·SSE 맵 상태
webui/           # 기존 단일영상 PoC 유지(별도 탭) + index.html main 탭 개편
```

### 4.2 데이터 흐름·스레딩

```
[cam1..16 RTSP]                                (GStreamer 스레드들)
   │ nvurisrcbin(NVDEC) → fps게이트(5fps) → appsink
   ▼
FrameQueue (thread-safe, maxsize=64, 가득 차면 oldest drop)   ← FrameItem{cam_id, ts, frame}
   ▼
Analyzer 스레드 (1개)                          (GPU 직렬 사용 → 락 불필요)
   detect(TRT) → tracker[cam_id].update → foot(u,v)
   → H[cam_id]·(u,v) → 맵(x,y) → metrics.update(cam_id, objects)
   ▼
MapState (최신 스냅샷, 락 보호)                 {objects[], zones[], counters[], cams[]}
   ▼
FastAPI: GET /api/map/state (폴링) + /api/map/stream (SSE 1초)
   ▼
프론트 canvas: 맵 이미지 + 객체 점·벡터 + 경로·구역·병목·출입구 오버레이
```

- 처리량 검산: 16ch × 5fps = 80프레임/초. 검출(TRT FP16 ~6-8ms) + ReID(~3-5ms) ≈ 초당 0.7~1.0s GPU — 단일 스레드로 감당, 부족 시 채널 fps 하향이 1차 노브 (M0·M7에서 실측)
- 트래커 격리: `KalmanBoxTracker.count` 등 클래스(전역) 상태를 인스턴스 상태로 리팩토링 → 카메라별 독립 ID 공간. ECC(카메라 모션 보정)는 고정 CCTV라 비활성
- 트래커 5fps 동작: max_age 등 시간 파라미터를 fps 기준으로 환산 조정

### 4.5 main 탭 UI 플로우 (기존 index.html 개편)

1. **맵 설정**: 맵 업로드 → 축척 2점(또는 CAD 메타 자동) → 경로/구역/병목/출입구 드로잉 → 저장
2. **카메라 등록**: RTSP 입력 → 연결 테스트(첫 프레임) → 좌: 카메라 프레임 / 우: 맵 — 대응점 4+점 → 유효영역 ROI → 저장 → "카메라 추가" 반복
3. **운영 뷰**: 맵 canvas(전 카메라 객체 점·방향·구역 하이라이트·카운터) + 좌측 카메라 목록(상태 뱃지) + 지표 패널. 카메라 영상 없음

|------|------|-------------|------|
| **M0** 환경 검증 | GStreamer/DeepStream 플러그인 가용성 확인(`nvurisrcbin`/`nvh264dec`), NVDEC 1ch 디코드 스모크, 16ch 동시 디코드 부하 실측 → **디코딩 스택 확정** | 실측 메모(fps·CPU·GPU-dec 사용률), 폴백 결정 | 1일 |

| **M3** tracking | BoostTrack 전역 상태 인스턴스화(ID 격리), 분석 스레드, TRT 공유, 5fps 파라미터 튜닝 | 2ch 동시 추적 데모, 기존 단일영상 모드 회귀 테스트 | 2일 |
| **M4** mapping+spatial | 카메라별 H 투영·유효영역 필터·맵 축척, 구역/통과선/경로 지오메트리 모듈 | 합성 좌표 단위 테스트(투영 오차·polygon 포함·crossing) | 2일 |
| **M5** metrics | 속도·정렬도·구역별 인원/밀도·병목 임계·다중 카운터 (맵 좌표 기반, 기존 로직 이식) | MapState JSON 스키마 확정 + 지표 정합 확인 | 2일 |
| **M6** API+프론트 | 카메라 CRUD·맵 업로드·매핑 UI(기존 지도정합 재사용)·드로잉 UI·SSE·운영 뷰 canvas | main 탭 e2e: 등록→매핑→맵 표출 | 3일 |
