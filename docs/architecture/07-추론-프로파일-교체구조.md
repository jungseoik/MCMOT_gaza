# ADR 07 — 추론 프로파일(검출기·ReID·트래커 교체 구조)

- 날짜: 2026-08-20
- 상태: **채택** — 기본값은 기존 스택(`yolox_fastreid`)이라 안 건드리면 동작 불변
- 관련: [ADR 04 DeepStream 인제스트](04-DeepStream-zero-copy-인제스트-전환.md),
  [실측 보고서](../reports/2026-08-20_신규-추론스택-YOLO26-CLIPReID-도입-실측.md)

## 배경

추론 스택(검출기 + ReID + 트래커)을 호출하는 곳이 세 군데인데, 엔진 경로·입력
크기·crop 크기·임계값이 각자 하드코딩돼 있었다.

| 호출 지점 | 쓰임 |
|---|---|
| `src/inference_gpu.py` | 단일영상/RTSP (webui :8000, :8900 미리보기) |
| `system/tracking/analyzer.py` | :8900 ffmpeg 백엔드 (호스트 직렬 추론) |
| `system/ingest_ds/worker.py` | :8900 DeepStream 백엔드 (컨테이너 배치 추론, **현 운영**) |

모델을 하나 바꾸려면 세 파일을 모두 고쳐야 했고, 검출기마다 다른 전처리(입력
크기·패딩 위치)와 ReID마다 다른 crop 크기·정규화가 코드 곳곳에 흩어져 있었다.
PIASPACE가 제공한 신규 스택(YOLO26-L + CLIP-ReID)을 붙이면서 이 구조를 정리했다.

## 결정

**프로파일**(검출기·ReID·트래커 조합)을 레포 루트 `model_zoo.py` 한 곳에 선언하고,
세 호출 지점은 프로파일 id 하나만 받는다.

```
model_zoo.PROFILES
  yolox_fastreid   YOLOX-X(MOT20) 896×1600  + FastReID SBS-S50 2048d   det_thresh 0.4
  yolo26_clipreid  YOLO26-L v6.3 640×640    + CLIP-ReID ViT-B/16 768d  det_thresh 0.6
```

선택 우선순위: **호출자 인자 → `data/infer_profile.json`(:8900 UI가 씀) →
`INFER_PROFILE` 환경변수 → 기본값(`yolox_fastreid`)**.

### 왜 레포 루트인가

DS 컨테이너는 `src/__init__.py`가 끌어오는 무거운 의존(pycocotools 등)을 설치하지
않는다. `src/` 아래 두면 워커가 import 자체를 못 한다(실측). `default_settings.py`·
`dataset.py`와 같은 층에 둬서 호스트·컨테이너 양쪽에서 동일하게 import된다.

### 컨테이너는 스펙만 공유하고 구현은 벤더링

`model_zoo`의 **팩토리**(`build_detector`/`build_reid`)는 `src.inference_trt`
(→ yolox 패키지)를 끌어오므로 컨테이너에서 못 쓴다. 컨테이너는 `model_zoo`의
**데이터클래스 스펙만** 읽고, 구현은 `system/ingest_ds/trt_infer.py`에 배치용으로
따로 둔다 — 기존 `yolox_post.py` 벤더링과 같은 이유·같은 방식이다.

### 검출기 공통 인터페이스

```
detect_frame(bgr) -> (dets[N,5] xyxy+conf, scale_ref_tensor)
```
`scale_ref_tensor`는 shape만 쓰여 `scale = min(ref.h/frame.h, ref.w/frame.w)`를 낸다
(BoostTrack.update 규약). 좌표계가 검출기마다 다른 것을 이 한 값으로 흡수한다 —
YOLOX는 letterbox 좌표(scale<1), YOLO26·RF-DETR은 원본 좌표(ref=원본 shape → scale=1).

### 모델별로 다른 것들

| | YOLOX + FastReID | YOLO26 + CLIP-ReID |
|---|---|---|
| 검출 입력 | 896×1600, 패딩 **좌상단** | 640×640, 패딩 **중앙**(Ultralytics LetterBox) |
| 검출 후처리 | NMS 필요(yolox postprocess) | end2end — 그래프 내장 NMS, (B,300,6) |
| ReID crop | 128×384, 0~255 그대로 | 128×256, **/255 + CLIP mean/std** |
| 임베딩 | 2048d | 768d |

ReID 정규화는 **모델 래퍼 안**에서 끝낸다(`CLIPReIDTRT.forward`). 임베더
(`GPUEmbeddingComputer`·`DsGpuEmbeddingComputer`)는 "0~255 RGB 배치를 넘기고 결과를
L2 정규화한다"는 계약을 그대로 유지하므로, ReID 모델을 갈아끼워도 임베더 코드는
crop 크기만 바뀐다.

## 엔진 관리

엔진은 GPU 아키텍처·TRT 버전마다 따로 구워야 한다(호스트 conda TRT 10.16.1 /
DS 컨테이너 10.14.1 — 서로 못 읽는다).

```
external/weights/onnx/     원천 ONNX (HF backseollgi/MCMOT — tools/fetch_assets.sh --onnx)
external/weights/trt/      호스트 엔진
external/weights/trt_ds/   DS 컨테이너 엔진
```

빌드: `tools/build_profile_engines.sh [--ds]` (내부적으로 `tools/build_trt_engine.py`).

## 전환 동작

`:8900 → ① 설정 → 추론 모델`에서 클릭 → `POST /api/infer/profile`:

1. 진행 중인 평가 세션이 있으면 **409로 거부** — 같은 세션 안에서 앞뒤 구간이 서로
   다른 검출기로 계산되면 4대 지표를 신뢰할 수 없다(맵·구역 변경 금지와 같은 이유).
2. 엔진 파일이 없으면 400 + 없는 파일명 안내.
3. `data/infer_profile.json`에 저장 후 **추론 계층만** 재기동
   (DS: 워커 컨테이너 재기동 / ffmpeg: AnalyzerThread 재생성).
   사이트 설정·세션 녹화본은 건드리지 않는다. 추적 상태(트랙 ID)는 초기화된다.

## 대안 검토

- **참조 구현(`ultralytics.YOLO`)을 그대로 쓴다** — 기각. AGPL 패키지와 torch 백엔드가
  운영 경로(DS 컨테이너 포함)에 끌려 들어온다. RF-DETR 때와 같이 전·후처리만
  복제했다(`src/yolo26_trt.py`, 라이브러리 불필요).
- **참조 구현의 트래커(BoostTrack++ 재구현)도 함께 이식** — 보류. 우리 트래커와 같은
  계열이고, 트래커까지 동시에 바꾸면 성능 차이의 원인을 분리할 수 없다. `TrackerSpec`
  자리는 만들어 뒀으므로 나중에 `kind`만 늘리면 된다.
