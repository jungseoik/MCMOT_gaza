## 1. 배경 · 문제

실제 피난 훈련은 **건물 하나에서 동시에** 일어나는 1건의 이벤트다. 그러나 현재 시스템은
**세션이 층 단위**로만 존재한다.

- `POST /api/session/start?floor=X` → 한 층 엔진에만 세션을 연다(`server.py`).
- 프론트 "🔔 경보 시작"은 **현재 선택된 층만** 시작(`session.js` — `startSession`이 current floor).
- 저장·조회·리포트·녹화(v1.10) 전부 층 스코프. **건물 통합값을 산출하는 코드가 없다.**
- 결과: 한 세션 = 한 층. 4대 지표 리포트도 **그 한 층만** 반영. 건물 전체 합/평균이 없다.

즉 세션→지표→저장→리포트→UI 전 구간이 **층 독립**으로만 설계돼, 건물 단위 훈련을 담지 못한다.

## 2. 요구사항 분석 — 경보 위치 의존성 (레퍼런스 기준)

문서 수식 기준으로 각 지표의 **경보 위치(S_origin)** 의존성은 다음과 같다.

| 지표 | 수식 | 경보 위치 필요? |
|---|---|---|
| **IDR** | `D(e, S_origin) / max(t_e,start − t_alarm, ε)` | **필수** (거리항) |
| **EPFI** | `max(0, 1 − ∫d_i dt/(T_i·d_allow))×100` | 불필요 |
| **CBS** | `Σ_k ∫ max(0, ρ_k−ρcrit,k)·w_k dt` | 불필요 |
| **SEI** | `(1 − ½Σ|P_actual−P_design|)×100` | 불필요 |

- **IDR만 경보 위치가 필수**(없으면 거리 정의 불가). EPFI·CBS·SEI는 경보 위치와 무관(개별 문서에 origin 언급 0건).
- **경보 시각 t_alarm** 은 네 지표 모두 필요(평가 시간창 시작·지연 기준). → **드릴은 t_alarm을 전 층 공유**해야 성립.

## 3. 결정 (Decision)

### D1. "드릴(Drill) = 건물 세션" 도입
훈련 1건 = **전 층에 걸친 하나의 드릴**. 전 층 엔진에 **공유 t_alarm**으로 세션을 동시 개시/종료한다.
- `session_id`는 이미 t_alarm에서 유도(`sess-<round(t_alarm*1000)>`)되므로, **공유 t_alarm이면 전 층 session_id가 동일** → 자연스러운 드릴 키. (별도 drill_id 없이 session_id로 층을 가로질러 묶는다.)

### D2. 시작 게이트 — **모든 (참여) 층에 경보 원점이 지정돼야 시작** ★ (사용자 결정)
- 지금처럼 "한 층에 원점 1개 찍혔다고" 시작되면 안 된다. **드릴은 참여 전 층 각각에 경보 원점 ≥1개가 지정돼 있을 때만** 시작한다.
- 이유: 그래야 **전 층에서 IDR까지** 산출된다(§2 — IDR은 층별 원점 필수). 부분 지정 상태로 시작해 일부 층 IDR이 코너 `(0,0)` 폴백(무의미)으로 오염되는 현재 문제를 원천 차단.
- **참여 층 정의**: 기본 = 카메라가 매핑된 층(추적이 실제로 이뤄지는 층). 카메라 없는 층(예: 현재 지상1층)은 드릴에서 제외하거나, 명시적으로 포함할 때만 원점을 요구한다. → §7 결정 필요 1.
- 미충족 시 `409`로 "원점 미지정 층: [floor2, …]" 안내.

### D3. 지표 집계 — 층별 산출 → 건물 롤업
좌표계는 층마다 독립이라 지표는 **층별로 산출**하고, 그 위에서 건물값을 집계한다.

| 지표 | 건물 롤업 | 근거 |
|---|---|---|
| **EPFI** | 전 층 전 인원 평균(인원 가중): `Σ EPFI_i / Σ n` | 인당 점수 |
| **CBS** | 전 층 병목 합: `Σ_floor Σ_k CBS_{floor,k}` | 누적량 |
| **SEI** | 전 층 출구를 **하나의 분포로 합쳐 재계산**: `(1 − ½Σ_j |E_j/ΣE − C_j/ΣC|)×100` (E·C는 건물 전체 출구) | 분포 통합 |
| **IDR** | 층별 IDR을 **구역 수(또는 인원) 가중 평균** | 층별 산출 후 평균 |

- **롤업 리포트 = 건물 4대 지표 + 층별 상세 표** 병기. (건물값만 보지 않고 층별로도 볼 수 있게.)
- IDR 원점: 각 층은 **자기 층의 경보 원점**으로 자기 층 거리·IDR을 낸다(건물 3D 거리 아님). 발생 층 외 층은 그 층의 "대표 기준점"을 원점으로 지정(D2가 이를 강제).

### D4. 저장 · 조회
- 저장은 **층별 유지**(`sessions/[<floor>/]<session_id>.json`·`.db`) — 기존 구조·계약 v1.10 그대로.
- **드릴 조회는 session_id로 전 층을 모아** 롤업. 즉 저장 스키마 변경 없이, "같은 session_id를 전 층 디렉토리에서 수집 → 집계"로 건물 리포트를 만든다.

### D5. 하위 호환
- 단일 층 사이트는 "참여 층 1개"이므로 기존과 동일하게 동작(그 층만 원점 요구).
- 기존 층별 `POST /api/session/start?floor=` 는 **유지**(개별 층 테스트용). 드릴은 그 위의 상위 오케스트레이션.

## 4. 계약 v1.11 (신규 API — 제안)

- **`POST /api/drill/start`** — body `{floor_origins: {floor_id: [[x,y],…], …}, t_alarm?}`.
  참여 전 층 원점을 한 번에 받고, **모든 참여 층에 원점이 있어야** 각 층 엔진에 **공유 t_alarm**으로 세션 개시. 하나라도 없으면 409(어느 층인지 명시). resp: `{session_id, floors:[{floor_id, live}…]}`.
- **`POST /api/drill/stop`** — 전 층 세션 종료·저장. resp: 드릴 롤업 결과.
- **`GET /api/drill/{session_id}/result`** — 저장된 전 층 결과를 session_id로 모아 **건물 롤업 + 층별 상세** 반환.
- **`GET /api/drills`** — 드릴 이력(전 층에 공통 존재하는 session_id 기준).
- **`GET /api/drill/{session_id}/export`** — 건물 롤업 + 층별 JSON/CSV.
- 스키마(`contracts.py`): `DrillResult{session_id, alarm_ts, building:{sei,epfi_avg,cbs_total,idr_avg,exit_metrics…}, floors:[EvaluationResult…]}` 신설. 기존 `EvaluationResult` 무개정.

## 5. 프론트(UI) 변경

- 운영 뷰: "🔔 경보 시작"을 **"🔔 건물 전체 경보 시작"** 흐름으로. 층 셀렉터로 각 층을 돌며 원점을 찍게 하고, **전 층 원점이 채워지면** 시작 버튼 활성화(미충족 층 배지 표시).
- 세션/리포트 패널: 드릴 롤업(건물 4대 지표) + 층별 탭.
- ④ 리플레이: 드릴 = 전 층 리플레이(session_id로 층별 .db를 함께 재생·재계산).

## 6. 단계별 구현 계획

- **Phase 1 — 드릴 시작/종료**: `/api/drill/start·stop`(전 층 원점 게이트 + 공유 t_alarm), 층별 세션은 기존 로직 재사용. 프론트 "건물 전체 경보" 흐름.
- **Phase 2 — 롤업 리포트**: `/api/drill/{id}/result`·`/drills`·export + `DrillResult` 스키마 + 집계(§3). 리포트 패널 건물/층별.
- **Phase 3 — 드릴 리플레이**: session_id로 전 층 .db 동시 리플레이·재계산.

## 7. 결정 필요 (구현 전 확정)

1. **참여 층 범위** — (a) 카메라 매핑된 층만 자동 참여(권장), (b) 사이트 전 층 무조건, (c) 드릴마다 층 선택. D2의 "모든 층"을 어디로 볼지.
2. **IDR 가중** — 건물 IDR 평균 가중치를 구역 수 / 인원 / 균등 중 무엇으로.
3. **건물 롤업 추가 요약** — 4대 지표 외 "총 대피 요약(층별 개시시각·최대 혼잡 층·총 통과 인원 등)"을 넣을지.
4. **원점 없는 참여 층 허용 여부** — 원칙은 전 층 필수(D2)지만, "그 층은 EPFI·CBS·SEI만, IDR 제외"를 허용하는 완화 모드를 둘지(문서상 3개 지표는 원점 불필요).

> 기본 채택(현재 사용자 결정): **D2 = 참여 전 층에 원점 필수**, 참여 층 = 카메라 매핑된 층. 위 1~4를 확정하면 Phase 1부터 구현한다.
