# 미구현·부분충족 항목 구현을 위한 선결요건 보고서 (WBS 입력용)

- 작성일: 2026-06-13
- 기준 보고서: [구현 점검 보고서](2026-06-12_요구사항-대비-webui-구현-점검-보고서.md) · 요구사항: [North Star](../requirements/CCTV-영상분석-엔진-필수추출정보.md)
- 목적: 점검 보고서의 🟡부분/🔴미구현 항목을 **실제 구현하려면 무엇이 더 필요한가**를
  (1) **받아와야 할 데이터·자산** (2) **확정해야 할 요구사항 디테일·파라미터** (3) **선행 의존성** 으로 분해.
- 용도: 이 리스트를 근거로 WBS 작성.

---

## 0. 읽는 법 — 선결요건 4유형

| 아이콘 | 유형 | 뜻 | 누가 |
|:------:|------|----|------|
| 📦 | **데이터·자산** | 외부에서 받아와야 함(도면·캘리브·구역정의 등) | 발주처/시설팀/현장 |
| ❓ | **요구사항 디테일** | 스펙이 비어 있어 **결정해야** 함(방식·규칙) | 도메인+제품 |
| 🎚️ | **파라미터·임계값** | 숫자값을 정해야 함(임계/지속시간 등) | 도메인+현장튜닝 |
| 🏗️ | **인프라·선행** | DB/시간동기 등 또는 다른 항목 선행 | 개발 |

> **핵심 통찰**: 미구현의 진짜 병목은 "코딩"이 아니라 **"정의·데이터가 비어 있는 것"** 이다.
> 특히 **G3(피난 경로 정의)와 G7(피난 개시 임계)** 은 요구사항에 방식·숫자가 아예 없어
> 이게 풀리기 전엔 P1 절반이 착수 불가다.

## 1. 한눈 요약 — 갭 × 필요한 입력

> **표 안 기호 뜻** —  **● = 필수**(반드시 필요) · **△ = 일부**(부분적으로 필요) · **– = 해당 없음**
> (열 제목 📦데이터·❓디테일·🎚️파라미터·🏗️선행 의 뜻은 위 §0 표 참고)

| ID | 갭 항목 | 요구 | 상태 | 📦데이터 | ❓디테일 | 🎚️파라미터 | 🏗️선행 | 블로커 |
|----|---------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **G1** | 건물 평면도 좌표 정합 | 2 | 🔴 | ● | △ | – | △ | **상** |
| **G2** | 렌즈 왜곡 보정 | 2 | 🟡 | ● | △ | – | – | 하 |
| **G3** | 권장 피난 경로 벡터 필드 | 3 | 🔴 | △ | **●** | – | G1 | **최상** |
| **G4** | 방향성 정렬도(코사인) | 3 | 🔴 | – | △ | ● | **G3** | 중 |
| **G5** | 다수 분석구역·병목영역 | 4 | 🔴 | ● | △ | △ | G1 | **상** |
| **G6** | 비상구별 고유 통과수+타임스탬프 | 5 | 🔴 | ● | ● | – | G9,트래커 | **상** |
| **G7** | 피난 개시 시점 | 5 | 🔴 | – | △ | **●** | G4,G9 | **최상** |

> 🏗️선행 칸의 **G1·G9 등은 "그 항목이 먼저 끝나야 함"** 을 뜻한다.

## 2. 항목별 상세 (구현하려면 무엇이 더 필요한가)

### G1. 건물 평면도 좌표 정합  〔요구2 · 🔴 · 블로커 상〕
현재: 카메라별 **로컬 미터평면**(0,0)-(rw,rh)만. 건물 도면 절대좌표 없음.
- 📦 **건물 평면도 원본**(이미지/CAD/PDF) + **축척**(m/px) + 층 구분
- 📦 카메라별 **정합 기준점(GCP)**: 영상↔도면 대응점 4점 이상 (또는 설치좌표+방위)
- 📦 카메라 **설치 메타**: 도면상 위치·설치높이·팬/틸트 각도·렌즈 화각
- ❓ **좌표계 규약**: 원점·단위·축방향, 층별 로컬 vs 건물 글로벌
- ❓ **정합 허용오차** 기준(예: ±0.5 m) — 검수 기준이 없음
- 🏗️ 카메라별 도면 호모그래피 저장(PostGIS SRID/스키마)

### G2. 렌즈 왜곡 보정  〔요구2 · 🟡 · 블로커 하〕
현재: 왜곡보정 단계 없음 → 광각/어안서 좌표 오차.
- 📦 카메라 **내부 파라미터**(초점·주점·왜곡계수 k1~k3,p1,p2) **또는** 체커보드 캘리브 촬영본
- 📦 설치 **카메라 기종·화각 목록**(일반/광각/어안 분류)
- ❓ 현장 카메라 **캘리브 촬영 가능 여부**(접근성) — 불가 시 자동추정으로 대체할지

### G3. 권장 피난 경로 벡터 필드  〔요구3 · 🔴 · **블로커 최상**〕
현재: 참조 경로 벡터 자체가 없음. **요구사항이 "시스템이 산출한 권장 경로"라고만 하고 산출 방식을 규정 안 함.**
- ❓ **경로 정의 방식 결정(가장 큰 미정)**:
  - (a) **정적 수동** — 도면 위에 구역/그리드별 화살표 작도
  - (b) **동적 계산** — 출구까지 최단경로(혼잡 반영 여부 포함)
- ❓ **벡터 필드 해상도**: 구역당 1벡터 / 그리드셀 / 연속필드
- ❓ **다출구 처리 규칙**: 위치별로 어느 출구의 경로를 따르나
- 📦 (정적 시) 경로 작도 데이터 / (동적 시) 출구위치 + 통행가능영역(navmesh)
- 🏗️ 선행 **G1**(경로는 도면좌표계 위에 정의)
> ⚠️ **이 항목이 P1 전체의 최대 블로커.** 방식·해상도·다출구 규칙이 정해져야 G4·G7이 줄줄이 풀린다.

### G4. 방향성 정렬도(코사인)  〔요구3 · 🔴 · 블로커 중〕
현재: 미구현. 단, **G3만 있으면 수식은 단순(코사인 유사도/사잇각).**
- 🎚️ **정렬 판정 임계**: cosθ 또는 사잇각 cutoff (예: cosθ≥0.7)
- ❓ 산출 단위 정의: 객체별 + 구역 평균 산식
- 🏗️ 선행 **G3** (참조 경로 없으면 계산 불가)

### G5. 다수 분석구역 · 병목 후보영역  〔요구4 · 🔴 · 블로커 상〕
현재: ROI 단일 폴리곤만.
- 📦 **분석구역 목록·경계**: 문/계단/복도협소부/병목후보 각 폴리곤 + **실제 바닥면적**
- ❓ 구역을 **영상좌표 vs 도면좌표** 중 어디에 정의(도면 권장 → G1 의존)
- 🎚️ **밀도 위험등급 임계**: 현재 0.4/1.0 하드코딩 — 구역유형별로 달라야 하는지, 근거(군중밀도 LOS 등)
- 🏗️ 다폴리곤 구역 데이터 모델(PostGIS)

### G6. 비상구별 고유 통과수 + 통과 타임스탬프  〔요구5 · 🔴 · 블로커 상〕
현재: 라인 1개·매 교차마다 +1(왕복 중복). 고유 dedup·타임스탬프 없음.
- 📦 **비상구별 가상통과선** 정의(다수)
- ❓ **dedup 규칙 확정**: ID별 최초 1회만, 재진입 제외 — **방향 조건(밖으로만 카운트?)**
- ❓ **ID 스위치 대응**: 트래커가 ID 바꾸면 중복/누락 → 허용오차 또는 ReID 보강 정책
- 🏗️ 선행 **트래커 ID 안정성**(품질바) + **G9 타임스탬프 규약**

### G7. 피난 개시 시점  〔요구5 · 🔴 · **블로커 최상**〕
현재: 판정 로직 전무. **요구사항이 "기준치/설정된 지속시간"이라고만 하고 숫자가 전부 빔.**
- 🎚️ **4개 임계 전부 미정**:
  - 속도 임계 (예: >0.5 m/s)
  - 정렬도 임계 (= G4)
  - **동시 만족 객체 비율** 임계 (예: ≥60%)
  - **지속시간** (예: ≥3초 연속)
- ❓ 구역별 vs 전역 파라미터 적용
- 🏗️ 선행 **G4**(정렬도) + 시계열 상태저장(G9)

### G8. 라이브 궤적/이벤트 영속화  〔요구1·5 · 🟡 · 블로커 중〕
현재: 파일 모드만 궤적 보유, 라이브는 휘발.
- 🏗️ DB(궤적·이벤트) + 핫상태 Redis
- ❓ **보존기간·다운샘플 정책**, **개인정보(영상/궤적) 처리 규정**

### G9. (횡단) 시간동기 + DB 스키마  〔요구2·4·5 공통 · 🔴 · 블로커 상〕
G5·G6·G7·G8·멀티캠의 **공통 선결 인프라**.
- 🏗️ **NTP/PTP 시간동기**(멀티캠·통과 타임스탬프 정합)
- 🏗️ **PostGIS/Timescale 스키마**: 카메라·구역·라인·경로·이벤트·궤적
- ❓ 타임스탬프 **규약**(소스·정밀도·단일 클럭 기준)
- 📦 (멀티캠 대비) 카메라 식별/그룹 메타

### G0. (보류) 멀티캠 ID 병합 선결요건  〔요구1 · ⚪ 최종단계〕
지금 구현 아님. 단 **착수 전 갖춰야 할 것**만 기록:
- 📦 카메라 **토폴로지**(인접/중첩 관계), 카메라간 **이동시간 prior**
- 🏗️ ReID **임베딩 저장·매칭**(pgvector) + 글로벌 ID 서비스
- ❓ 동일인 판정 임계·시간창 규칙
- 🏗️ 선행 **G1**(공통 도면좌표) + **G9**(시간동기) 필수

## 3. ★ 받아와야 할 데이터·자산 체크리스트 (외부 의존)

> 발주처/시설팀/현장에 **요청해야 할 것**. 이게 안 들어오면 해당 작업 착수 불가.

- [ ] **건물 평면도** 원본(CAD/이미지) + 축척 + 층 구분 〔G1·G3·G5〕
- [ ] **카메라 설치 메타**: 도면상 위치·높이·각도·화각·기종 〔G1·G2〕
- [ ] **카메라↔도면 정합 기준점(GCP)** 또는 캘리브 촬영본 〔G1·G2〕
- [ ] **분석구역·병목영역 정의**: 폴리곤 경계 + 실제 바닥면적 〔G5〕
- [ ] **비상구·가상통과선 위치** 목록 〔G6〕
- [ ] **(정적 경로 시) 피난 경로 작도** / (동적 시) 출구위치+통행영역 〔G3〕
- [ ] **(멀티캠 대비) 카메라 토폴로지·이동시간 prior** 〔G0〕

## 4. ★ 확정해야 할 의사결정·파라미터 체크리스트 (요구사항 디테일 부족)

> **요구사항에 비어 있어 도메인/제품이 결정해야** 하는 것. WBS 착수 전 가장 시급.

**방식·규칙 (❓)**
- [ ] **피난 경로 산출 방식**: 정적 작도 vs 동적 최단경로 + 해상도 + 다출구 규칙 〔G3〕 ← **최우선**
- [ ] **고유 통과 dedup 규칙**: 최초 1회/재진입 제외/방향 조건 〔G6〕
- [ ] **ID 스위치 허용오차 / ReID 보강** 여부 〔G6〕
- [ ] 구역 정의 좌표계(영상 vs 도면) 〔G5〕
- [ ] 좌표계 규약·정합 허용오차 〔G1〕
- [ ] 데이터 보존기간·개인정보 처리 정책 〔G8〕

**숫자 임계값 (🎚️)**
- [ ] **피난 개시**: 속도임계 / 정렬도임계 / 객체비율 / 지속시간 (4개) 〔G7〕 ← **최우선**
- [ ] **정렬 판정** 코사인/각도 cutoff 〔G4〕
- [ ] **밀도 위험등급** 임계(현 0.4/1.0의 도메인 근거) 〔G5〕

## 5. 구현 의존성 순서 (착수 가능 순)

```
[선결 인프라/데이터]
  G9(시간동기·DB스키마) ──┬─────────────┐
  G1(도면 정합) ──────────┤             │
        │                 ▼             ▼
        ▼            G5(다구역·밀도)  G6(고유통과·타임스탬프)
  G3(피난경로 정의)*       │             │
        │                 └──────┬──────┘
        ▼                        ▼
  G4(정렬도) ──────────▶ G7(피난 개시 시점)
                                 │
  (G2 왜곡보정·G8 영속화는 독립적, 병행 가능)
  (G0 멀티캠은 G1·G9 완료 후 최종단계)

  * G3는 "데이터/코딩"보다 "정의 결정"이 먼저 — §4 최우선 항목
```

**해석**
- **가장 먼저 풀 것**: §4의 두 "최우선"(G3 경로방식 · G7 임계값) 결정 + G9/G1 인프라·데이터 확보.
- 이 둘이 막히면 **P1(정렬도·피난개시)이 통째로 대기**한다 → WBS의 임계경로.
- G5·G6은 G1/G9만 서면 독립 착수 가능. G2·G8은 언제든 병행.

## 6. WBS로 넘길 작업 후보 (요건 충족 시)

| 작업 | 선결(§3·§4) | 비고 |
|------|------------|------|
| DB 스키마·시간동기 구축 (G9) | 타임스탬프 규약 | 모든 이벤트의 토대 |
| 도면 정합 모듈 + 캘리브 UI (G1) | 도면·GCP·설치메타 | 다구역·멀티캠 토대 |

## 7. 결론 — WBS 착수 전 단 2가지부터

> 미구현 항목 대부분은 **코딩이 아니라 "비어 있는 정의·데이터"가 블로커**다.
> WBS를 의미 있게 짜려면 **§4의 두 최우선 결정**부터 받아야 한다:
> 1. **피난 경로를 어떻게 산출할 것인가**(G3, 정적 vs 동적) — P1 전체의 임계경로.
> 2. **피난 개시 4개 임계값**(G7) — 도메인/현장이 정해줄 숫자.
>
> 그 다음 **§3 데이터 자산**(도면·카메라 메타·구역/통과선 정의)을 확보하면,
> 나머지(정렬도·다구역·고유통과)는 대부분 "정의가 채워지면 구현은 명확한" 작업이다.
