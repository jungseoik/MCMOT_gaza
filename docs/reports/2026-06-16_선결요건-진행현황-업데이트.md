## 1. 해결된 항목

### G3 — 권장 피난 경로 벡터 → 🟡(부분 해결, MVP)
- **결정**: 동적 경로탐색(navmesh/Dijkstra) 대신 **"운영자가 2D 맵/영상에 출구 방향 화살표를 직접 작도(정적 수동)"** 채택. 보고서에서 가장 큰 미정이었던 "경로 산출 방식"을 이 단순화로 해소.
- **구현**: 단일 구역 1개 방향 벡터(`align_vec`). [13-alignment](../webui-dev/13-alignment.md).
- **남은 부분**: 꺾이는 통로/다출구용 **구역당 벡터(다구역, =G5 의존)**. 동적 경로는 향후(요구사항이 "시스템 산출 경로"를 강제하면).

### G4 — 방향성 정렬도 → ✅
- 객체 이동벡터 vs 기준벡터 코사인, 구역 평균(`avg_align`), opt-in. 표출(대시보드·맵) 완료.
- **남은 디테일**: 정렬 임계(0.4/−0.2는 MVP 임의값) 도메인 확정.

## 2. 미해결 + 성격 변화

- **G7 피난 개시 시점** — 여전히 🔴이나 **블로커 해소**: (평균속도 + 평균정렬도)가 산출되므로,
  이제 필요한 건 **숫자 4개(속도임계/정렬임계/객체비율/지속시간) 결정 + 시계열 상태유지 로직**.
  데이터·코드보다 **도메인 임계값 결정**이 착수 트리거.
- **G6 비상구 고유 통과수+타임스탬프** — `LineCounter`가 교차는 잡지만 매 교차 카운트.
  ID 최초통과 dedup + 통과 시각 기록 + 다비상구로 **재설계 필요**.
- **G5 다구역·병목** — 단일 ROI만. 다폴리곤 + 구역별 지표(정렬도 포함) 확장.
- **G1 도면 정합 / G9 시간동기·DB / G2 왜곡 / G8 영속화** — 데이터·인프라 의존, 미착수.
