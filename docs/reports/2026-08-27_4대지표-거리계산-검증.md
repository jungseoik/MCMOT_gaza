# 4대 지표 거리·속도 계산 검증 (2026-08-27)

> "이게 실제 이동거리를 근사하는 지표가 맞나, 계산식이 잘못된 게 있나" 점검.
> 결론: **수식 4개는 요구사항과 일치. 거리 근사에서 버그 1건을 찾아 고쳤다.**

## 0. 먼저 — 이동거리 지표는 없다

`MapObject`·`PersonMetric` 어디에도 **누적 이동거리가 없다.** 거리가 쓰이는 곳은
세 군데뿐이고, 각각 성격이 다르다.

| 쓰임 | 무엇 | 성격 |
|---|---|---|
| 속도 | 1초 윈도 양끝 **직선거리** / dt | 궤적 길이가 아니라 **현(chord)** |
| IDR 분자 | `D(zone, origin)` 격자 최단거리 | **정적** 경로거리 (관측 아님) |
| EPFI | 경로까지의 **수직 이탈거리** | 궤적 길이와 무관 |

## 2. 🐞 찾은 버그 — IDR 거리가 맨해튼이었다

`grid.py:77` 의 BFS 이웃이 **상하좌우 4방향뿐**이었다. 격자에 장애물이 하나도
없으므로 홉 수가 곧 **맨해튼 거리**가 된다.

```
경보원 (0,0) → 구역        직선      수정 전     오차
  ( 30,  0)  0°           30.00m    29.50m    -1.7%
  ( 30, 10) 18°           31.62m    39.00m   +23.3%
  ( 30, 30) 45°           42.43m    59.00m   +39.1%   ← √2
  (  0, 30) 90°           30.00m    29.50m    -1.7%
```

**IDR = D / 지연** 이므로 D 가 41% 부풀면 IDR 도 41% 부푼다. 더 나쁜 건
**오차가 각도에 따라 달라진다**는 점이다 — 같은 30m 거리라도 정면이면 30m,
대각이면 42m 로 나온다. 즉 **도면을 45° 돌리면 IDR 이 바뀐다.**

### 수정 — 8방향 다익스트라 (대각 √2)

```
                      직선      수정 전            수정 후
  ( 30, 10) 18°     31.62m    39.00m (+23.3%)   33.44m (+5.7%)
  ( 30, 30) 45°     42.43m    59.00m (+39.1%)   41.87m (-1.3%)
  ( 40, 15) 21°     42.72m    54.00m (+26.4%)   45.51m (+6.5%)

최대 오차   +39.1%  →  ±6.5%
```

장애물이 없는 지금은 결과가 octile 거리(유클리드 대비 최대 +7.6%)이고,
나중에 통행 불가 셀을 넣으면 그대로 우회 경로 거리가 된다.

### 곁가지 — 테스트가 우연히 통과하고 있었다

`test_start_detected_at_expected_time` 이 `graph_distance == 5.0` 을 단언하며
주석엔 "그래프 거리: n1→n2 = 500px = 5m" 라고 적혀 있었다. 그런데 **5.0 은
맨해튼 격자값**이었다(우연히 일치). 실제로 `_origin_distance_m` 은 격자를
1순위로 쓰므로 **수동 SpatialGraph 는 IDR 거리에 관여하지 않는다.**
설계상 의도된 우선순위지만, 그리신 경로가 IDR 거리에 반영될 거라 기대하면
어긋난다 — 별도 판단이 필요하면 이 점을 짚어야 한다.

## 3. 속도 — 현(chord) 근사의 한계 (버그 아님)

윈도 양끝점 직선거리라 곡선 경로는 과소평가된다.

```
실제 보행 1.4 m/s (호 길이 기준)
  직선                    1.4000 m/s   +0.00%
  원호 R=10m (1초에  8°)  1.3989      -0.08%
  원호 R= 5m (1초에 16°)  1.3954      -0.33%
  원호 R= 2m (1초에 40°)  1.3716      -2.03%
  원호 R=1.5m(1초에 53°)  1.3497      -3.59%
  직각 코너 통과 순간     1.0096      -27.9%   ← 일시적
```

일반 보행 곡률에서는 1% 미만이고, 직각 코너에서만 순간적으로 크게 낮아진다.
속도는 **거리 누적에 안 쓰이고** 피난개시 판정(v ≥ v_th)에만 쓰이므로,
v_th=0.5~0.8 기준에서 1.01 m/s 는 여전히 통과한다. 실사용 영향은 작다.

## 4. 함께 확인한 것

- **fps 독립** — 윈도가 시간 기준(1.0s)이고 dt 가 실제 ts 차이라, 샘플링
  2·5·10·15·30fps 에서 속도가 전부 동일하다(등속 1.4000, 등가속 1.1250).
- **1초 윈도는 구간 평균** — 순간속도가 아니다. 등가속 예에서 참 순간속도
  1.25 인데 1.125 가 나온다. `window_sec` 의 성질.
- **fps 를 올려도 잡음이 안 준다** — 양끝점만 쓰므로 중간 표본이 평균에
  기여하지 않는다(±3px 잡음: 5fps σ=0.023, 30fps σ=0.024).

## 4-2. 구역을 도면 전체에 깔면 어떻게 되나

현장에서는 구역을 몇 개만 그리는 게 아니라 **도면 전체에 타일처럼 깐다**고 한다.
두 가지를 확인했다.

### 값 — 문제없다

5×5 타일(100×100 m, 셀 1 m, 경보 좌상단)의 D:

```
  15.4   33.4   53.4   73.4   93.4
  33.4   43.7   61.7   81.7  101.7
  53.4   61.7   72.0   90.0  110.0
  73.4   81.7   90.0  100.2  118.3
  93.4  101.7  110.0  118.3  128.5
```

구역별로 잘 벌어지고(15.4~128.5 m), **대각 대칭**이 정확히 성립한다 —
`(i,j)`와 `(j,i)`가 같은 값이라 고유값이 상삼각 개수인 15개다. 회전 불변이
지켜진다는 뜻이다(4방향 시절엔 값 자체가 부풀었을 뿐 대칭은 성립했다).

**다만 도면 전체를 한 구역으로 잡으면** D 는 "그 구역까지의 거리"가 아니라
**면적 평균**이 된다(100×100 m 전체 = 79.1 m, 중심까지 직선은 70.7 m). 값이
틀린 건 아니지만 IDR 이 구역별로 나뉘는 의미가 사라진다 — 타일로 까는 건 괜찮고,
하나로 덮는 건 피해야 한다.

### 구역을 하나로 덮으면 — 실제 엔진으로 시뮬레이션

사람 25명을 100×100 m 에 5×5 로 배치, 경보는 좌상단, 인지 확산 8 m/s
(가까운 사람이 먼저 움직인다). 같은 상황을 구역 나눔만 바꿔 돌렸다.

| 구역 나눔 | 구역 | 개시 판정 | 구역당 인원 | IDR 범위 | 평균 |
|---|---|---|---|---|---|
| **1×1** | 1 | 1 | 25.0명 | 11.29 | **11.29** |
| 2×2 | 4 | 1 | 6.2명 | 5.54 | 5.54 |
| 3×3 | 9 | 4 | 2.8명 | 5.19~7.24 | 6.58 |
| 5×5 | 25 | 7 | 1.0명 | 3.81~7.16 | 5.25 |
| 10×10 | 100 | 8 | 0.2명 | 2.49~8.17 | 5.47 |

**① 값이 작아지는 게 아니라 2배 부푼다** (5.25 → 11.29).
`D` 가 면적 평균이라 79.1 m 로 나오는데, 이는 실제 개시된 어느 구역보다도
멀다(최대 71.2 m). 분모(지연 7.0 s)는 3~18 s 의 중간이라 그만큼 안 커진다.

**② 확산 패턴이 통째로 사라진다.** 5×5 로 보면 지연이 공간에 퍼져 있다:

```
지연 (s)                     IDR
  3.0  5.0   —    —    —      4.89 6.55   —    —    —
  5.0  6.0  16.0  —    —      6.55 7.16 3.81   —    —
   —  16.0  18.0  —    —       —   3.81 3.96   —    —
```

경보 근처 3 s → 멀어질수록 16·18 s. **IDR 은 "피난 반응 *확산* 지표"인데,
확산을 못 본다.** 1개면 "7.0 초"라는 숫자 하나뿐이라 3 초에 시작한 데도,
18 초 걸린 데도 안 보인다 — 개선이 필요한 구역이 정확히 그 늦은 곳인데.

**③ 노이즈는 비슷하다** (예상과 달랐다). 개시 시각에 ±1.5 s 흔들림을 주고
5회 반복:

| 구역 | IDR 평균 | 편차 | 상대 |
|---|---|---|---|
| 1×1 | 11.39 | 1.05 | 9.2% |
| 2×2 | 5.59 | 0.51 | 9.1% |
| 3×3 | 6.52 | 0.50 | 7.7% |
| 5×5 | 5.27 | 0.60 | 11.4% |

상대 편차는 8~11% 로 다 비슷하다. 1개 구역의 절대 편차가 커 보이는 건
**값 자체가 부풀어서**지 더 흔들려서가 아니다.

### 검토 — D 를 '사람 위치' 기준으로 바꾸면 (제안 검토)

현재 §4.1 은 $D$ 를 **구역 polygon 안 모든 셀의 평균**으로 정의한다. 대신
**사람이 실제로 있는 셀**의 평균으로 재면 어떤가.

```
도면 전체 1개 구역 · 100×100 m · 경보 좌상단

  사람 배치              면적평균(현재)   사람셀평균   직선평균
  고르게 퍼짐 (5×5)          79.1 m       80.1 m     76.2 m
  경보 근처에 몰림            79.1 m       16.1 m     16.1 m
  반대편 구석에 몰림          79.1 m      114.9 m    113.4 m
  복도 한 줄로 (대각)         79.1 m       73.4 m     73.5 m
  양끝에 반반                79.1 m       64.2 m     63.9 m
```

**면적 평균은 사람이 어디 있든 79.1 m 로 고정이다.** 경보 바로 옆에 전원이
몰려 있어도 79.1 m 가 나온다 — "얼마나 멀리 떨어진 곳까지"라는 정의(§1)와 맞지 않다.

**두 안은 사실상 같은 구현이다** (격자 해상도 2 m 만큼만 차이). 격자셀 쪽이 낫다:
이미 캐시된 거리장에서 O(1) 조회라 비용이 없고, 나중에 통행 불가 셀을 넣으면
우회 경로가 자동 반영된다.

### 더 밀면 — 사람별 IDR

거리를 사람 기준으로 잡을 수 있다면 개시 판정도 사람별로 할 수 있다.
그러면 구역 의존성이 아예 사라진다.

```
시뮬레이션 참값: 반응이 8.0 m/s 로 퍼짐

  사람별 IDR (흔들림 없음)            8.00 m/s   1.00x
  사람별 IDR 중앙값 (±3초 흔들림)      8.03 ±0.44  1.00x
  구역별 (5×5 타일)                  5.25 m/s   0.66x
  구역별 (도면 전체 1개)              11.29 m/s   1.41x
```

사람별은 구역을 어떻게 나누든 **참값을 되찾는다.**

**그런데 `r_th` 보호를 잃는다.** 구역별 판정의 $r_e \geq r_{\mathrm{th}}$ 는
"혼자만 움직이는 건 무시한다"는 잡음 필터인데, 사람별에는 그게 없다:

```
  헛움직임   검출실패율    사람별 IDR 중앙값   참값대비
    없음        0%          7.62         0.95x
    2초        0%          7.62         0.95x   ← dt_hold 가 걸러냄
    4초        0%         15.81         1.98x   ← 2배 부풀어짐
    없음       25%          6.03         0.75x
```

$\Delta t_{\mathrm{hold}}$(3초)보다 긴 헛움직임은 그대로 통과해 IDR 을 2배
부풀린다. 구역별이면 한 사람의 4초짜리 오동작이 구역 전체를 못 움직인다.

**결론** — 거리(안 2)만 바꾸는 건 안전하다: 개시 판정은 구역 기준 그대로라
`r_th` 보호가 유지되고, $D$ 만 의미를 되찾는다. 사람별 IDR 은 이론적으로
더 깨끗하지만 잡음 방어를 따로 설계해야 해서 별건으로 다룬다.

### 반대쪽 함정 — 너무 잘게 쪼개도 문제

개시 판정된 구역 수를 보면 5×5 는 25개 중 **7개뿐**이다. 구역이 작으면 사람이
`dt_hold` 동안 머물지 않고 지나가버려 판정이 안 선다. 10×10 은 100개 중 8개.

**구역당 3~6명이 남는 크기**가 무난했다(3×3에서 9개 중 4개 개시, IDR 범위도
5.19~7.24 로 의미 있게 벌어짐). 실제 현장에서는 방·복도 같은 **공간의 의미
단위**로 나누는 게 맞고, 그게 대체로 이 범위에 들어온다.

### 속도 — 낭비를 찾아 고쳤다

거리장(distance field)은 **원점이 같으면 어느 구역을 재든 동일**한데 구역마다
처음부터 다시 돌리고 있었다. 셀 목록도 구역마다 다시 만들고, 전체 셀을 구역마다
점-다각형 판정했다.

- 원점별 **거리장 캐시** (LRU 32)
- 격자 모양별 **셀 목록 캐시** (LRU 4)
- `cells_in_polygon` 에 **bbox 선필터** — 대부분의 셀은 구역 근처도 아니다

```
구역  셀크기      전       후      배    경보 3개
  4   2.0m    0.02s   0.005s   3.9x     0.02s
 16   2.0m    0.06s   0.005s  12.5x     0.01s
 25   2.0m    0.10s   0.005s  18.8x     0.02s
 25   1.0m    0.38s   0.024s  16.1x     0.07s
 25   0.5m    1.61s   0.115s  14.0x     0.34s
```

최악(0.5 m 셀·25구역·경보 3개)이 **4.8초 → 0.34초**. 값은 그대로다(회귀로 고정).
