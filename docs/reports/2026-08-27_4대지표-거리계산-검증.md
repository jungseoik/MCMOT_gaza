# 4대 지표 거리·속도 계산 검증 (2026-08-27)

> "이게 실제 이동거리를 근사하는 지표가 맞나, 계산식이 잘못된 게 있나" 점검.
> 결론: **수식 4개는 요구사항과 일치. 거리 근사에서 버그 1건을 찾아 고쳤다.**

---

## 0. 먼저 — 이동거리 지표는 없다

`MapObject`·`PersonMetric` 어디에도 **누적 이동거리가 없다.** 거리가 쓰이는 곳은
세 군데뿐이고, 각각 성격이 다르다.

| 쓰임 | 무엇 | 성격 |
|---|---|---|
| 속도 | 1초 윈도 양끝 **직선거리** / dt | 궤적 길이가 아니라 **현(chord)** |
| IDR 분자 | `D(zone, origin)` 격자 최단거리 | **정적** 경로거리 (관측 아님) |
| EPFI | 경로까지의 **수직 이탈거리** | 궤적 길이와 무관 |

## 2. 🐞 찾은 버그 — IDR 거리가 맨해튼이었다

`grid.py:77` 의 BFS 이웃이 **상하좌우 4방향뿐**이었다. 격자에 장애물이 하나도
없으므로 홉 수가 곧 **맨해튼 거리**가 된다.

```
경보원 (0,0) → 구역        직선      수정 전     오차
  ( 30,  0)  0°           30.00m    29.50m    -1.7%
  ( 30, 10) 18°           31.62m    39.00m   +23.3%
  ( 30, 30) 45°           42.43m    59.00m   +39.1%   ← √2
  (  0, 30) 90°           30.00m    29.50m    -1.7%
```

**IDR = D / 지연** 이므로 D 가 41% 부풀면 IDR 도 41% 부푼다. 더 나쁜 건
**오차가 각도에 따라 달라진다**는 점이다 — 같은 30m 거리라도 정면이면 30m,
대각이면 42m 로 나온다. 즉 **도면을 45° 돌리면 IDR 이 바뀐다.**

### 수정 — 8방향 다익스트라 (대각 √2)

```
                      직선      수정 전            수정 후
  ( 30, 10) 18°     31.62m    39.00m (+23.3%)   33.44m (+5.7%)
  ( 30, 30) 45°     42.43m    59.00m (+39.1%)   41.87m (-1.3%)
  ( 40, 15) 21°     42.72m    54.00m (+26.4%)   45.51m (+6.5%)

최대 오차   +39.1%  →  ±6.5%
```

장애물이 없는 지금은 결과가 octile 거리(유클리드 대비 최대 +7.6%)이고,
나중에 통행 불가 셀을 넣으면 그대로 우회 경로 거리가 된다.

### 곁가지 — 테스트가 우연히 통과하고 있었다

`test_start_detected_at_expected_time` 이 `graph_distance == 5.0` 을 단언하며
주석엔 "그래프 거리: n1→n2 = 500px = 5m" 라고 적혀 있었다. 그런데 **5.0 은
맨해튼 격자값**이었다(우연히 일치). 실제로 `_origin_distance_m` 은 격자를
1순위로 쓰므로 **수동 SpatialGraph 는 IDR 거리에 관여하지 않는다.**
설계상 의도된 우선순위지만, 그리신 경로가 IDR 거리에 반영될 거라 기대하면
어긋난다 — 별도 판단이 필요하면 이 점을 짚어야 한다.

## 3. 속도 — 현(chord) 근사의 한계 (버그 아님)

윈도 양끝점 직선거리라 곡선 경로는 과소평가된다.

```
실제 보행 1.4 m/s (호 길이 기준)
  직선                    1.4000 m/s   +0.00%
  원호 R=10m (1초에  8°)  1.3989      -0.08%
  원호 R= 5m (1초에 16°)  1.3954      -0.33%
  원호 R= 2m (1초에 40°)  1.3716      -2.03%
  원호 R=1.5m(1초에 53°)  1.3497      -3.59%
  직각 코너 통과 순간     1.0096      -27.9%   ← 일시적
```

일반 보행 곡률에서는 1% 미만이고, 직각 코너에서만 순간적으로 크게 낮아진다.
속도는 **거리 누적에 안 쓰이고** 피난개시 판정(v ≥ v_th)에만 쓰이므로,
v_th=0.5~0.8 기준에서 1.01 m/s 는 여전히 통과한다. 실사용 영향은 작다.

## 4. 함께 확인한 것

- **fps 독립** — 윈도가 시간 기준(1.0s)이고 dt 가 실제 ts 차이라, 샘플링
  2·5·10·15·30fps 에서 속도가 전부 동일하다(등속 1.4000, 등가속 1.1250).
- **1초 윈도는 구간 평균** — 순간속도가 아니다. 등가속 예에서 참 순간속도
  1.25 인데 1.125 가 나온다. `window_sec` 의 성질.
- **fps 를 올려도 잡음이 안 준다** — 양끝점만 쓰므로 중간 표본이 평균에
  기여하지 않는다(±3px 잡음: 5fps σ=0.023, 30fps σ=0.024).
