## 0. 한눈 요약

| # | 요구 카테고리 | 상태 | 핵심 코멘트 |
|---|---------------|:----:|-------------|
| 1 | 객체 인식·고유 ID 추적 | 🟢 대부분 | 대표점(발끝)·ID·궤적 OK. Multi-Cam 병합은 **의도된 최종 단계 보류** |
| 2 | 평면도 좌표(호모그래피) | 🟡 부분 | 픽셀→**로컬 미터 평면** 변환 OK. 단 *실제 건물 도면 좌표 정합*·렌즈 왜곡보정 없음 |
| 3 | 이동속도·방향 벡터 | 🟡 부분 | 개별/구역평균 속도·방향벡터 OK. **방향성 정렬도(코사인) 전무** |
| 4 | 구역 점유·밀도 | 🟡 부분 | 밀도 수식 정확. 단 **분석구역 1개만**(다구역·다비상구 미지원) |
| 5 | 시간 이벤트·통과 카운팅 | 🔴 미흡 | 라인 교차 감지 OK. **피난개시 시점·통과 타임스탬프·고유(중복제거) 통과수 모두 없음** |

> 결론: **카테고리 1·2·3·4의 "측정 기반"은 단일 카메라 기준으로 상당히 갖춰져 있으나,
> 피난 분석의 "의미 산출물"(정렬도·피난 개시 시점·비상구별 고유 통과 인원)이 빠져 있다.**
> 현재 WebUI는 *추적·속도·밀도 대시보드*에 가깝고, *피난 평가 엔진*까지는 갭이 있다.

수식 자체에 **틀린 곳은 발견되지 않음**(아래 §6). 문제는 "오류"가 아니라 "미구현 항목"이다.

## 1. 객체 인식 및 고유 ID 추적 — 🟢 대부분 충족

| 항목 | 상태 | 근거 |
|------|:----:|------|
| 대표점 픽셀 좌표 | 🟢 | 발끝(bbox 하단 중심) `speed.py:53 _foot`, `counter.py:47 _foot` |
| 시계열 고유 ID·궤적 | 🟢 | 트래커가 프레임 간 ID 부여, `speed.py:41 history` 궤적 보유. 파일 모드는 `server.py:217 replay_metrics`에 프레임별 (id, mx, my)가 누적되어 **전체 궤적 복원 가능** |
| Multi-Camera ID 병합 | ⚪ 보류 | 미구현 — 요구사항상 **최종 단계 항목**, 현재 단일 카메라 기준 동작이 정상 |

**참고/한계**
- 대표점은 4종(하단중심/접지점/마스크 무게중심/키포인트) 중 "하단 중심" 1종만. 요구사항은 "적어도 하나"이므로 **충족**.
- 라이브(RTSP) 모드는 `replay_metrics`를 쌓지 않으므로(`server.py:234 _worker_live`) 장기 궤적 영속화는 파일 모드 한정.

## 2. 평면도 좌표 기반 공간 위치 — 🟡 부분 충족

| 항목 | 상태 | 근거 |
|------|:----:|------|
| 픽셀→2D 미터 좌표 변환 | 🟢 | 수동 4점 호모그래피 `server.py:373-382`, 뎁스 기반 자동 호모그래피 `depth_ground.py:84 build_homography` |
| 실시간 변환 | 🟢 | 프레임마다 `speed.py:61 _world` 적용 |
| **실제 건물 도면 좌표 정합** | 🔴 | 변환 목적지가 **ROI에 anchor된 로컬 미터 평면**(0,0)-(rw,rh) 또는 뎁스 평면의 임의 축. *건물 평면도 이미지/좌표계와의 정합(등록)은 없음* |
| 캘리브레이션 파라미터(높이·각도·왜곡) | 🟡 | 호모그래피에 암묵 반영. 단 **렌즈 왜곡 보정(distortion) 단계 없음** → 광각/어안에서 좌표 오차 |

**갭**
- 요구사항의 "건물 평면도 상의 좌표"는 *도면 위 절대 위치*를 의미. 현재는 카메라별 로컬 평면이라, **다카메라 통합·도면 오버레이를 하려면 도면 정합(평면도 기준점 매핑)이 추가로 필요**.

## 3. 이동속도 및 방향 벡터 — 🟡 부분 충족 (정렬도 누락)

| 항목 | 상태 | 근거 |
|------|:----:|------|
| 개별 객체 속도 | 🟢 | `speed.py:67 _speed` (km/h or px/s) |
| 개별 이동 방향 벡터 | 🟢 | `speed.py:137 _obj_map`가 단위 방향벡터(dirx,diry) 산출, 맵에 화살표 표시 |
| 구역 평균 이동속도 | 🟢 | `speed.py:208 avg = sum(speeds)/n` (ROI 내 객체 한정) |
| **방향성 정렬도(코사인 유사도/사잇각)** | 🔴 **미구현** | 레포 전체에 권장 피난 경로 벡터·코사인 계산 없음(외부 ReID의 cosine은 외형 매칭용, 무관) |
| 구역 평균 정렬도 | 🔴 미구현 | 위와 동일 |

**갭(중요)**
- "권장 피난 경로 방향 벡터"라는 **참조 벡터 필드 자체가 없음** → 정렬도 산출 불가.
- 정렬도는 §5의 "피난 개시 시점" 판정의 입력이므로, 이게 없으면 5번도 막힌다(연쇄 의존).

## 4. 구역별 점유 및 밀도 — 🟡 부분 충족

| 항목 | 상태 | 근거 |
|------|:----:|------|
| 구역 내 재실자 수 | 🟢 | `speed.py:105 _in_roi`(pointPolygonTest)로 ROI 내 카운트 → `count` |
| 병목영역 밀도 = 인원/면적 | 🟢 | `speed.py:171 _density`, 면적은 호모그래피로 환산한 `world_area_m2`(`depth_ground.py:115 polygon_area_m2`, shoelace) |
| **다수 분석구역 동시 지원** | 🔴 | `job.roi` **단일 폴리곤만**. 문·계단·복도협소부를 *동시에* 여러 구역으로 정의 불가 |
| 경계 기하형상 판정 | 🟢(단일) | 임의 4각형 polygon test로 "실제 경계 내 포함" 판정은 됨 |

**갭**
- 요구사항은 "사전 정의된 *복수* 분석구역/병목 후보영역"을 전제. 현재는 한 번에 1개 구역만 측정 → **다구역 동시 점유/밀도 맵 미지원**.

## 5. 시간 기반 이벤트 및 통과 카운팅 — 🔴 미흡

| 항목 | 상태 | 근거 |
|------|:----:|------|
| 구역별 **피난 개시 시점**(임계 지속 최초 타임스탬프) | 🔴 **미구현** | 속도·정렬도·비율·지속시간 조건 판정 로직 전무 |
| 가상 통과선 통과 이벤트 감지 | 🟢 | `counter.py:50 update` 측 변경(side flip)으로 교차 감지 |
| 통과 **완료 시점(타임스탬프) 기록** | 🔴 | 교차 시 in/out 카운터만 증가, **객체별 통과 시각을 기록하지 않음** |
| 비상구별 **고유** 통과수(중복/재진입 제외, 최초 1회) | 🔴 | `counter.py:67-73`은 side flip마다 무조건 +1 → **왕복/재진입이 중복 집계됨**. 고유 ID 최초통과 dedup 없음 |
| **다수 비상구** 매핑 | 🔴 | 라인 1개만(`job.count_line`). 비상구별 분포 집계 불가 |

**갭(가장 큼)**
- 현재 `LineCounter`는 *재실 인원(occupancy = start+in−out)* 추정용으로는 타당하나,
  요구사항이 말하는 *"비상구별 고유 통과 인원 분포"*와는 **목적·집계 규칙이 다르다**:
  - 요구: ID별 **최초 통과 1회만** 유효 → 재진입/왕복 제외.
  - 현구현: 매 교차마다 카운트(왕복 시 in/out 양쪽 증가).
- "피난 개시 시점"은 §3 정렬도가 선행 입력이라 **3·5가 함께 묶여 미구현**.

## 6. 수식 정확성 검증 — ✅ 발견된 오류 없음

검토한 핵심 수식 전부 수학적으로 타당함:

| 수식 | 위치 | 판정 | 비고 |
|------|------|:----:|------|
| 속도(호모그래피): `‖ΔW‖/Δt × 3.6` (m/s→km/h) | `speed.py:79-83` | ✅ | 발끝을 월드로 변환 후 거리. 단위 정확 |
| 속도(ppm): `(px/ppm)/Δt × 3.6` | `speed.py:84-85` | ✅ | |
| 속도(보정無): `px/Δt` (px/s) | `speed.py:86` | ✅ | |
| 밀도: `n / world_area_m2` | `speed.py:173-174` | ✅ | 면적은 shoelace로 정확 |
| 면적(shoelace): `½|Σ(xᵢyᵢ₊₁−xᵢ₊₁yᵢ)|` | `depth_ground.py:118-120` | ✅ | |
| 초점거리: `f = h_px·Z / 1.7m` (median) | `depth_ground.py:20-39` | ✅ | 핀홀 투영 정합 |
| 역투영: `P=((u−cx)Z/f,(v−cy)Z/f,Z)` | `depth_ground.py:58` | ✅ | 표준 핀홀 |
| 광선-평면 교차: `P=(d/(n·ray))·ray` | `depth_ground.py:96-100` | ✅ | |
| 부호거리(라인): `cross(AB, P−A)/‖AB‖` | `counter.py:35-37` | ✅ | 수직 부호거리 정확 |

**경미한 주의(오류 아님, 설계 선택)**
- 속도는 **윈도 양 끝점 변위/Δt**(`speed.py:73-76`) → 경로가 휘면 *경로장 대비 과소추정* 가능. 일반적 윈도 추정 방식이라 허용 범위.
- 가속도 `|Δspeed|/Δt`(`speed.py:125`)는 절대값이라 가속/감속 부호 소실. 요구사항 항목 아님.
- 수동 호모그래피는 ROI 4점 클릭 **순서**(TL→TR→BR→BL)에 의존(`server.py:378`). 순서 틀리면 좌표 뒤틀림 — UI 가이드 필요.

## 7. 종합 갭 목록 (우선순위 제안)

**P1 — 피난 평가 엔진의 핵심 산출물 (요구 3·5, 현재 전무)**
1. **권장 피난 경로 방향 벡터 필드** 정의(구역/그리드별) → 정렬도 산출 전제.
2. **방향성 정렬도**: 객체 이동벡터 vs 경로벡터의 코사인 유사도/사잇각, 구역 평균.
3. **비상구별 고유 통과수**: ID 최초통과 1회만 집계(재진입 dedup) + 통과 타임스탬프 기록.
4. **피난 개시 시점**: (평균속도·평균정렬도·임계만족 비율)이 지속시간 이상 유지된 최초 타임스탬프.

**P2 — 다중성·정합 (요구 2·4·5)**
5. **다수 분석구역/다수 비상구 라인** 동시 정의·집계.
6. **실제 건물 평면도 정합**(도면 기준점↔월드 좌표 등록) — 다카메라 통합·도면 오버레이의 토대.

**P3 — 정밀도**
7. 렌즈 왜곡 보정(캘리브레이션) 옵션.
8. 라이브 모드 궤적/이벤트 영속화(현재 파일 모드 한정).

**보류(정상)** — Multi-Camera ID 병합: 요구사항상 최종 단계.

## 8. 결론

- **틀린 수식은 없다.** 측정 파이프라인(검출→ID→발끝→호모그래피→속도→밀도)은 단일 카메라 기준으로 견고하다.
- **빠진 것은 "피난 의미 산출"** 계층이다: 정렬도, 피난 개시 시점, 비상구별 고유 통과 인원, 다구역/다비상구.
- 다음 마일스톤은 **§7 P1**(경로 벡터 → 정렬도 → 고유 통과/타임스탬프 → 피난 개시 시점)을 한 묶음으로 구현하는 것을 권장한다. 이 4개가 북극성 요구사항의 "피난 분석" 본체다.
